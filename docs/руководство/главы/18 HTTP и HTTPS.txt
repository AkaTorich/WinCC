# HTTP и HTTPS
Большая часть того, что программа берёт из сети, приходит по HTTP: страницы, файлы, ответы сервисов погоды и курсов, обновления самой программы. Библиотека `net.h` сводит такой обмен к одному вызову: дать адрес — получить ответ целиком, с кодом, заголовками и содержимым. Под ней работает WinHTTP — та же служба Windows, через которую ходят в сеть многие программы самой системы, поэтому шифрование HTTPS, прокси, сжатие и переадресации достаются программе даром. Эта глава показывает, как спросить сервер, как отличить отказ сервера от отсутствия связи, как отправить данные, скачать файл с полосой хода и не ждать вечно того, кто не отвечает.

## Как устроен разговор с веб-сервером

HTTP — это договорённость о форме вопроса и ответа. Программа-клиент соединяется с сервером и посылает запрос: метод (что сделать — `GET` взять, `POST` отправить), путь (что именно — `/robots.txt`), строки-заголовки вида `Имя: значение` (кто спрашивает, в каком виде ждёт ответ) и, если нужно, тело — данные, которые клиент отдаёт серверу. Сервер возвращает ответ той же формы: код состояния (три цифры), заголовки и тело — саму страницу, картинку или текст сервиса.

HTTPS — тот же HTTP, только внутри шифрованного канала TLS. Слова запроса и ответа те же; разница в том, что посторонний на пути видит лишь, с каким сервером идёт разговор, но не что в нём сказано, и что программа убеждается по сертификату, что говорит с настоящим сервером, а не с подменой. Для программы на WinCC разница — одна буква в адресе: `http://` или `https://`. Всё остальное делает WinHTTP.

Код состояния говорит, чем кончилось дело. Первая цифра задаёт род ответа:

:= Коды | Что значат | Примеры
: 2xx | Получилось | 200 — вот ответ; 201 — создано; 204 — сделано, тела нет
: 3xx | Ищите в другом месте | 301, 302 — адрес переехал (библиотека идёт туда сама)
: 4xx | Ошибка в вопросе | 400 — непонятный запрос; 401, 403 — нельзя; 404 — нет такого
: 5xx | Ошибка у сервера | 500 — сбой внутри; 503 — сервер перегружен

## Первый запрос: net_get

Подключить библиотеку — одна строка `#include <net.h>`. Больше ничего делать не нужно: wcc видит в заголовке `#pragma comment(lib, "net")`, сам собирает с программой исходники библиотеки из папки `lib\net` и выбрасывает то, чего программа не зовёт. Готовая программа нужна только DLL самой Windows — `ws2_32.dll` и `winhttp.dll`, которые есть в каждой системе. Программа с сетью весит 80–120 КБ.

```
// robots: первый запрос — прочитать файл robots.txt сайта
#include <net.h>
#include <stdio.h>

int main(void)
{
    NetResponse *r = net_get("https://www.google.com/robots.txt");
    if (r->error) {
        printf("Не вышло: %s\n", r->error);
        net_free(r);
        return 1;
    }
    const char *type = net_header(r, "Content-Type");
    printf("Ответ %d, %zu байт, тип %s\n\n", r->status, r->size, type ? type : "не сказан");
    printf("%.150s...\n", r->body);
    net_free(r);
    return 0;
}
```

```
Allow: /search/howsearchworks

Disallow: /gr...
```

`net_get` ждёт, пока ответ придёт целиком, и возвращает структуру `NetResponse`. Поток программы всё это время стоит — для консольной программы это ровно то, что нужно; об окнах — в конце главы.

:= Поле | Что в нём
: `status` | Код ответа: 200, 404… Ноль — ответа не было вовсе
: `body` | Тело ответа. После последнего байта всегда стоит ноль, поэтому текст — готовая строка Си
: `size` | Сколько байт в теле. Для картинок и архивов верить только ему: внутри могут быть нули
: `headers` | Все заголовки ответа одной строкой, каждый — `Имя: значение` и перевод строки
: `error` | Ноль — сервер ответил. Иначе — почему ответа нет, словами Windows

Ответ живёт в памяти, пока его не отдадут `net_free`. Она освобождает всё сразу: тело, заголовки, текст ошибки и строки, которые выдавал `net_header`. Освобождать `body` отдельно через `free` нельзя.

Тексты в библиотеке — UTF-8, как и исходники WinCC: адреса с кириллицей, имена файлов, тексты ошибок. Тело ответа библиотека не перекодирует — отдаёт байты как пришли. Почти все сайты сегодня отвечают в UTF-8, и такой текст можно сразу печатать; какая кодировка на самом деле, говорит заголовок `Content-Type` (`charset=utf-8` или другая).

## Три исхода запроса

Новичка чаще всего путает вот что: 404 — это не ошибка запроса. Сервер нашёлся, понял вопрос и честно ответил, что такой страницы нет; `error` при этом ноль, `status` — 404, а в `body` лежит страница, которую сервер приготовил для этого случая. Ошибка в смысле `error` — это когда ответа нет совсем: имя сервера не нашлось, сервер не принимает соединений, связь оборвалась, вышло время, адрес записан неправильно. Отсюда три ветки, которые стоит различать в каждой сетевой программе.

```
// check: живы ли сайты. check адрес [адрес ...]
#include <net.h>
#include <stdio.h>

int main(int argc, char **argv)
{
    net_set_timeout(10000);                     // ждать каждого не больше 10 секунд
    for (int i = 1; i < argc; i++) {
        NetResponse *r = net_get(argv[i]);
        if (r->error)                           // сервер не ответил вовсе
            printf("нет ответа  %s\n", r->error);
        else if (r->status >= 400)              // ответил, но отказом
            printf("отказ %d   %s\n", r->status, argv[i]);
        else
            printf("ответ %d   %s, %zu байт\n", r->status, argv[i], r->size);
        net_free(r);
    }
    return 0;
}
```

```
> check https://github.com https://github.com/no-such-page-here https://нет-такого-сайта.example http://github.com github.com https://self-signed.badssl.com
ответ 200   https://github.com, 530385 байт
отказ 404   https://github.com/no-such-page-here
нет ответа  https://нет-такого-сайта.example: Не удается разрешить имя или адрес сервера (12007)
ответ 200   http://github.com, 530385 байт
нет ответа  Адрес не понят: github.com
нет ответа  https://self-signed.badssl.com: Произошла ошибка безопасности (12175)
```

Каждая строка — свой случай. GitHub ответил 200. Несуществующая страница — тоже ответ, но отказом 404. Выдуманное имя не нашлось вовсе. `http://github.com` сервер переадресовал на `https://`, библиотека сама прошла туда и вернула конечный ответ. Адрес без `https://` библиотека не поняла: в отличие от браузера, она не дописывает начало сама. Последний сервер нарочно предъявляет самодельный сертификат, и WinHTTP отказался с ним говорить.

Текст ошибки начинается с того, о чём речь (адрес или имя), дальше — слова Windows на языке системы и в скобках номер. По номеру удобно искать причину:

:= Номер | Что случилось
: 12007 | Имя сервера не найдено: опечатка в адресе или нет связи с сетью
: 12029 | Сервер не принимает соединений: выключен, не тот порт, мешает экран
: 12002 | Вышло время ожидания (`net_set_timeout`)
: 12030 | Соединение оборвалось посреди ответа
: 12175 | Ошибка безопасности: сертификат сервера просрочен, чужой или самодельный
: 12152 | Сервер ответил не по правилам HTTP
: — | «Адрес не понят: …» — в адресе нет `http://` или `https://`, или он записан неверно

Тот же текст ошибки доступен и через `net_error()` — она возвращает последнюю ошибку текущего потока, а удачный запрос стирает её до пустой строки. Для запросов удобнее поле `error`: оно принадлежит своему ответу и не затрётся следующим вызовом.

! `net_get` возвращает ноль только в одном случае — если в программе кончилась память. Во всех остальных ответ есть, и проверять надо `r->error`, а не сам указатель.

## Заголовки ответа: net_header

Заголовки ответа — это сведения о теле: тип (`Content-Type`), дата изменения, сколько хранить в кэше, куда идти дальше. `net_header(r, "Content-Type")` ищет заголовок по имени без учёта больших и малых букв и возвращает его значение без пробелов по краям — или ноль, если такого заголовка нет. Строка принадлежит ответу и освобождается вместе с ним в `net_free`; копировать её нужно, только если она понадобится после.

Все заголовки разом лежат в `r->headers`, каждый на своей строке. Первой строки ответа (`HTTP/1.1 200 OK`) там нет — код уже стоит в `status`.

! Когда сервер присылает сжатое тело, WinHTTP сам его распаковывает и убирает из ответа заголовки `Content-Encoding` и `Content-Length`: они говорили о сжатом виде, а программа получает распакованный. Поэтому длина тела — всегда `r->size`, а не заголовок.

## Отправить данные: net_post и net_post_text

Чтобы отдать серверу данные — заполненную форму, запись для сервиса, файл, — служит метод `POST`. `net_post(адрес, тип, данные, размер)` отправляет любые байты; тип — это строка для заголовка `Content-Type`, по которой сервер поймёт, что ему прислали. `net_post_text` — то же для строки: размер она считает сама, а если тип ноль, ставит `text/plain; charset=utf-8`.

Самый частый случай сегодня — сервисы, которые принимают и отдают JSON. Тестовый сервис `httpbin.org` возвращает в ответе всё, что получил, поэтому на нём хорошо видно, что именно ушло:

```
// post: отправить серверу JSON и показать, что он получил
#include <net.h>
#include <stdio.h>

int main(void)
{
    const char *json = "{\"город\": \"Хайфа\", \"дней\": 3}";
    NetResponse *r = net_post_text("https://httpbin.org/post", "application/json", json);
    if (r->error) {
        printf("Не вышло: %s\n", r->error);
        net_free(r);
        return 1;
    }
    printf("Ответ %d, тип %s\n%s\n", r->status, net_header(r, "Content-Type"), r->body);
    net_free(r);
    return 0;
}
```

Строка JSON ушла как есть, в UTF-8: 43 байта, хотя знаков в ней 29, — каждая русская буква занимает два байта. Сервер разобрал её и показал в поле `json`.

В заголовках, которые получил сервер, видно, что добавила сама библиотека: `Content-Length` (размер тела), `Host` (имя сервера), `User-Agent` (как программа себя называет — по умолчанию `WinCC net`) и `Accept-Encoding` — согласие принять сжатый ответ.

### Кириллица и знаки в адресе

В адресе и в теле формы у некоторых знаков особый смысл: `?` начинает параметры, `&` их разделяет, `=` отделяет имя от значения, пробел не допускается вовсе. Чтобы передать такой знак или кириллицу как обычный текст, его записывают через процент — каждый байт UTF-8 как `%` и две шестнадцатеричные цифры. `net_url_encode` делает это за программу: латиница, цифры и `- _ . ~` остаются как есть, пробел становится `+`, всё прочее — `%XX`. `net_url_decode` возвращает обратно. Обе отдают новую строку, которую освобождает `free`.

```
// form: кириллица и знаки в адресе и в форме — через net_url_encode
#include <net.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int main(void)
{
    char *q = net_url_encode("чай с мёдом & лимоном");
    char url[400];
    snprintf(url, sizeof url, "https://httpbin.org/get?q=%s", q);
    printf("Адрес: %s\n", url);
    free(q);

    NetResponse *r = net_get(url);
    const char *args = r->error ? 0 : strstr(r->body, "\"args\"");
    printf("%.*s\n", args ? (int)(strchr(args, '}') - args + 1) : 0, args ? args : "");
    net_free(r);

    char *name = net_url_encode("Анна"), *text = net_url_encode("2 + 2 = 4");
    char form[200];
    snprintf(form, sizeof form, "name=%s&text=%s", name, text);
    printf("Форма: %s\n", form);
    free(name);
    free(text);
    r = net_post_text("https://httpbin.org/post", "application/x-www-form-urlencoded", form);
    const char *got = r->error ? 0 : strstr(r->body, "\"form\"");
    printf("%.*s\n", got ? (int)(strchr(got, '}') - got + 1) : 0, got ? got : "");
    net_free(r);
    return 0;
}
```

Тип `application/x-www-form-urlencoded` — тот самый, в котором браузер отправляет обычную форму. Каждое значение кодируется отдельно, а `&` и `=` между ними пишутся как есть: закодируй программа всю строку целиком, сервер увидел бы одно длинное значение без полей.

! Кодировать нужно только значения, а не весь адрес. `net_url_encode("https://…")` превратит `:` и `/` в `%3A` и `%2F`, и адрес перестанет быть адресом.

## Любой метод и свои заголовки: net_request

`net_get`, `net_post` и `net_post_text` — короткие пути к одной общей функции `net_request(метод, адрес, заголовки, данные, размер)`. Через неё уходят методы, которых нет в коротких именах (`PUT` — заменить, `DELETE` — удалить, `PATCH`, `HEAD`), и свои заголовки — например ключ доступа к сервису. Заголовки пишутся строками `Имя: значение`, каждая оканчивается `\r\n`; ноль — своих заголовков нет.

```
const char *head = "Authorization: Bearer 12345\r\n"
                   "Accept: application/json\r\n";
NetResponse *r = net_request("DELETE", "https://example.com/api/notes/7", head, 0, 0);
if (!r->error && r->status == 204)
    printf("Заметка удалена\n");
net_free(r);
```

`Host`, `Content-Length` и `Accept-Encoding` библиотека ставит сама — писать их не нужно. Метод ноль означает `GET`.

Как программа называет себя серверу, меняет `net_set_agent("Погода/1.2")`: строка уходит заголовком `User-Agent` во всех следующих запросах. Некоторые сервисы требуют, чтобы программа представлялась, и отказывают безымянным. `net_set_agent(0)` или пустая строка возвращают имя по умолчанию.

! Значения заголовков пишите латиницей. Протокол HTTP пропускает в заголовках только знаки ASCII, и кириллица в `net_set_agent` или в своих заголовках дойдёт до сервера мусором. Если в заголовке нужен русский текст, его кодируют через `net_url_encode`, а сервер раскодирует.

## Скачать файл: net_download и ход загрузки

Картинку на сто килобайт можно взять через `net_get` и записать `r->body` в файл. Но файл на сотни мегабайт целиком в памяти держать незачем, и для него есть `net_download(адрес, файл)`: она пишет тело прямо на диск по мере прихода, кусками до 64 КБ, — сначала во временный файл с тем же именем и припиской `.part` (`npp.zip.part`), а когда тело пришло целиком, ставит его на место файла. Возвращает 1, если файл сохранён, и 0 — если нет; почему, скажет `net_error()`. Успехом считается только ответ с кодом 2xx: на 404 или 500 функция вернёт 0 с ошибкой «Сервер ответил 404: …», потому что страница-отказ — не тот файл, который просили.

Чтобы показать ход загрузки, функцию хода ставят через `net_on_progress(функция, данные)`. Библиотека зовёт её после каждого принятого куска с двумя числами: сколько байт пришло и сколько всего ожидается. Третий параметр — указатель `данные`, переданный при установке, — удобен, чтобы передать внутрь имя файла или окно.

```
// download: скачать файл с полосой хода. download адрес файл
#include <net.h>
#include <stdio.h>

static void bar(size_t done, size_t total, void *user)
{
    const char *name = user;
    if (total) {
        int filled = (int)(done * 30 / total);
        printf("\r%s [%.*s%*s] %3d%%", name, filled, "##############################", 30 - filled, "",
               (int)(done * 100 / total));
    } else                                      // размер заранее не сказан
        printf("\r%s: %zu КБ", name, done / 1024);
}

int main(int argc, char **argv)
{
    if (argc < 3) {
        printf("download адрес файл\n");
        return 1;
    }
    net_on_progress(bar, argv[2]);
    DWORD start = GetTickCount();
    if (!net_download(argv[1], argv[2])) {
        printf("\nНе скачан: %s\n", net_error());
        return 1;
    }
    printf("\nГотово за %.1f с\n", (GetTickCount() - start) / 1000.0);
    return 0;
}
```

```
> download https://github.com/notepad-plus-plus/notepad-plus-plus/releases/download/v8.6.9/npp.8.6.9.portable.x64.zip npp.zip
npp.zip [##############################] 100%
Готово за 1.0 с
```

Знак `\r` возвращает курсор к началу строки, и каждый следующий вызов печатает полосу поверх прежней — на экране она растёт на месте. Второе число, `total`, бывает нулём: сервер не сказал размер заранее. Так случается со страницами, которые сервер собирает на ходу, и со всем, что пришло сжатым, — тогда честно показать можно только, сколько уже пришло.

Ход загрузки работает не только для `net_download`, но и для `net_get` и всех прочих запросов. Установка действует на все следующие запросы того потока, который её сделал, пока её не снимут `net_on_progress(0, 0)`; другие потоки её не видят.

! Если загрузка не удалась, `net_download` стирает недокачанный `.part`, а прежний файл с тем же именем остаётся как был. Поэтому обновлять файл на месте безопасно: оборвись связь посреди загрузки, у программы останется старая целая копия, а не половина новой.

## Сколько ждать: net_set_timeout

Сервер может не отвечать: завис, перегружен, связь пропала на полпути. Без предела программа ждала бы его очень долго, поэтому у библиотеки есть тайм-аут — 30 секунд по умолчанию. `net_set_timeout(мс)` задаёт его для всех следующих запросов всех потоков. Предел действует на каждый шаг отдельно: найти имя, соединиться, отправить, дождаться ответа и дождаться каждого следующего куска тела. Поэтому медленная, но живая загрузка большого файла не обрывается: пока куски идут, каждый укладывается в свой предел. Ноль — ждать без конца.

```
// timeout: сервер думает шесть секунд, а мы готовы ждать две
#include <net.h>
#include <stdio.h>

int main(void)
{
    net_set_timeout(2000);
    DWORD start = GetTickCount();
    NetResponse *r = net_get("https://httpbin.org/delay/6");
    printf("%s\nпрошло %.1f с\n", r->error ? r->error : "ответ пришёл", (GetTickCount() - start) / 1000.0);
    net_free(r);
    return 0;
}
```

```
https://httpbin.org/delay/6: Время ожидания операции истекло (12002)
прошло 4.0 с
```

Просили две секунды, а прошло больше: ожидание ответа WinHTTP отсчитывает шагами по четыре секунды и округляет вверх. Предел в 1 с на деле даёт около 4 с, в 5 с — около 8, в 9 с — около 12. Предел на соединение отмеряется точнее. Если программе важно уложиться ровно в своё время, запрос делают в отдельном потоке, а главный ждёт его сколько нужно сам.

Тот же предел `net_set_timeout` действует и на соединения TCP из следующей главы.

## Что библиотека делает сама

Многое из того, что в других языках настраивают руками, у `net.h` включено с первого запроса:

- Прокси. Если в Windows настроен прокси-сервер (в параметрах сети или сценарием автонастройки), запросы идут через него, как у браузера.
- Сжатие. Сервер узнаёт, что программа принимает `gzip` и `deflate`, и ответ, сжатый на треть или вчетверо, распаковывается сам.
- Переадресации. На ответ 301, 302, 303, 307 и 308 библиотека идёт по новому адресу и возвращает уже конечный ответ: `http://github.com` приходит ответом 200 с `https://github.com`. Единственный переход, которого WinHTTP не делает, — с HTTPS обратно на HTTP: тогда программа получит сам ответ 302 с заголовком `Location`.
- Шифрование. HTTPS идёт по TLS 1.2 или 1.3; старые версии выключены. Сертификат сервера проверяется по хранилищу Windows; самодельный или просроченный сертификат даёт ошибку 12175, и отключить проверку через `net.h` нельзя. Если нужно говорить со своим сервером на самодельном сертификате, это делается через WinHTTP напрямую — об этом в главе 21.
- Одно соединение на всю программу. Все запросы идут через один сеанс WinHTTP, поэтому повторные запросы к тому же серверу не открывают соединение заново, а cookies, присланные сервером, возвращаются ему в следующих запросах этой программы.

## Сеть в оконной программе

`net_get` и `net_download` держат поток, пока не придёт ответ. В консольной программе это незаметно, а оконная на это время замирает: сообщения не обрабатываются, окно не перерисовывается, и Windows через несколько секунд пишет в заголовке «Не отвечает». Выход — делать запрос в отдельном потоке (`CreateThread`), а результат передавать окну сообщением через `PostMessageA`. Все функции HTTP можно звать из нескольких потоков сразу: у каждого потока своя `net_error()` и своя функция хода, а общий сеанс WinHTTP защищён внутри библиотеки.

Функция хода зовётся в том потоке, который качает, — значит, менять окно прямо из неё нельзя. Она передаёт числа окну через `PostMessageA`, а полосу двигает уже само окно. Как устроить сеть в окне совсем без второго потока, на сокетах, — в главе 21.

## Итог

Запрос по HTTP или HTTPS — один вызов: `net_get`, `net_post`, `net_post_text` или `net_request` для любого метода и своих заголовков. Ответ приходит целиком в `NetResponse`: код в `status`, тело в `body` и `size`, заголовки в `headers` и через `net_header`; освобождает всё `net_free`. Главное правило проверки: `error` — ответа не было вовсе, `status` от 400 — ответ был, но отказом. Кириллица и особые знаки в адресе и форме идут через `net_url_encode`. Большие файлы — `net_download` с ходом от `net_on_progress`, а предел ожидания задаёт `net_set_timeout`. Прокси, сжатие, переадресации и шифрование библиотека берёт на себя. Следующая глава спускается на уровень ниже — к прямым соединениям TCP и пакетам UDP, из которых сделан и сам HTTP.
