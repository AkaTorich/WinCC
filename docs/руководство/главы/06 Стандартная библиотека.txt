# Стандартная библиотека
За `printf`, `fopen`, `malloc` и `sin` в программе на WinCC стоит своя библиотека Си — не системная `msvcrt.dll` и не библиотека Visual Studio, а исходники, которые wcc собирает вместе с каждой программой. В готовый exe попадает только то, что программа зовёт, — функции и глобальные переменные библиотеки: программа, которая печатает строку через `printf`, весит 64 КБ. Эта глава проходит по библиотеке заголовок за заголовком: сначала стандартные, потом заголовки Microsoft и C11 — потоки, консоль, файлы по номерам, другие программы, команды процессора — и говорит, что в них есть, как оно ведёт себя в Windows и где поведение отличается от привычного.

## Двадцать пять заголовков

Стандартные заголовки встроены в сам компилятор: на диске их нет, и папка `include` для них не нужна. Программе для Windows доступны двадцать пять.

:= Заголовок | Что в нём
: `stdio.h` | ввод и вывод: `printf`, `scanf`, файлы `FILE`
: `stdlib.h` | память, числа из строк, `qsort`, `rand`, `exit`, `getenv`, `system`
: `string.h`, `strings.h` | строки и память: `strlen`, `strcpy`, `memcpy`, `strcasecmp`
: `ctype.h` | классы символов: `isdigit`, `toupper`
: `math.h` | математика двойной и одинарной точности
: `time.h` | время и дата, `clock`
: `setjmp.h`, `signal.h` | дальний переход, сигналы
: `errno.h`, `assert.h` | коды ошибок, проверки
: `locale.h` | `setlocale`, `localeconv`
: `wchar.h`, `wctype.h`, `uchar.h` | широкие строки и UTF-16 (глава 7)
: `stddef.h`, `stdarg.h`, `stdbool.h`, `stdint.h`, `inttypes.h`, `limits.h`, `float.h` | типы, пределы, переменные аргументы
: `stdalign.h`, `stdnoreturn.h`, `iso646.h` | слова `alignas`, `noreturn`, `and`, `or`

Ещё полтора десятка заголовков лежат в папке `include` рядом с wcc, как и `windows.h`, и находятся сами. Это те, к которым привыкли пишущие в Visual Studio, и новые заголовки стандарта C11:

:= Заголовок | Что в нём
: `threads.h`, `stdatomic.h` | потоки C11, замки, атомарные переменные
: `complex.h`, `fenv.h`, `tgmath.h` | комплексные числа, округление и флаги дробной арифметики, одно имя для `float` и `double`
: `conio.h` | клавиша без Enter, проверка, нажата ли клавиша
: `io.h`, `fcntl.h` | файлы по номерам, поиск файлов по маске
: `direct.h`, `sys/stat.h`, `sys/types.h` | папки, размер и время файла
: `process.h` | запуск других программ, потоки в стиле Microsoft
: `malloc.h` | память в стеке функции, память с выравниванием
: `intrin.h` | отдельные команды процессора как функции

Код из проектов Visual Studio с такими `#include` собирается без правок. Есть и `sal.h` с пометками `_In_`, `_Out_` и подобными: все они пустые, а `windows.h` включает его сам. О каждой группе заголовков — свой раздел ближе к концу главы.

## Вывод: printf

`printf`, `fprintf`, `sprintf`, `snprintf` и их варианты с `va_list` понимают все форматы стандарта: `%d %i %u %x %X %o %c %s %p %n %%`, дробные `%f %F %e %E %g %G %a %A`, флаги `- + # 0` и пробел, ширину и точность числом или звёздочкой, размеры `hh h l ll z j t`. Сверх стандарта есть `%b` — число в двоичной записи — и размеры Microsoft: `%I64d` и `%I64u` для 64-битных чисел, `%I32d` для 32-битных, `%Id` для `size_t`. Код, написанный для Visual Studio, печатает числа без правок.

Три отличия от библиотек Microsoft и GCC стоит знать. Первое — формат `%ld` берёт 4-байтный `long`, как и положено в Windows (глава 5); для `long long` нужен `%lld` или `%I64d`, для `size_t` — `%zu`. Второе — ширина поля считается в буквах, а не в байтах. В UTF-8 русская буква занимает два байта, и обычная библиотека, выравнивая `%-16s`, отсчитала бы шестнадцать байт — столбцы с кириллицей разъехались бы. Здесь таблица выравнивается правильно. Третье — `snprintf`, обрезая строку по размеру буфера, не режет букву UTF-8 пополам: `snprintf(buf, 8, "Привет")` даёт `"При"` — шесть байт, потому что четвёртая буква целиком не помещается (глава 7).

```
#include <stdio.h>

typedef struct { const char *city; long long people; double area; } City;

int main(void)
{
    City cities[] = {
        { "Москва", 13149803, 2561.5 },
        { "Тула", 463087, 145.8 },
        { "Санкт-Петербург", 5597763, 1439.0 },
    };
    printf("%-16s %10s %9s %8s\n", "Город", "Жители", "Площадь", "Плотн.");
    for (int i = 0; i < 3; i++) {
        City *c = &cities[i];
        printf("%-16s %10lld %9.1f %8.0f\n", c->city, c->people, c->area, c->people / c->area);
    }
    printf("%#x %#o %b %e %a\n", 255, 8, 5, 1234.5, 1.0);
    return 0;
}
```

```
Город                Жители   Площадь   Плотн.
Москва             13149803    2561.5     5134
Тула                 463087     145.8     3176
Санкт-Петербург     5597763    1439.0     3890
0xff 010 101 1.234500e+03 0x1p+0
```

Вывод в консоль идёт сразу, без задержки: `printf` отдаёт строку консоли целиком в конце вызова, а UTF-8 перекодирует в UTF-16 — поэтому кириллица видна при любой кодовой странице консоли. Если вывод перенаправлен в файл или в другую программу (`prog > out.txt`, `prog | more`), туда уходят байты UTF-8, а строки разделяет один `\n` без `\r`. Подробнее о тексте — в главе 7.

`printf` и всё, что пишет в `FILE` или читает из него, можно звать из нескольких потоков сразу. У ввода-вывода библиотеки один общий замок: пока один поток печатает, другой ждёт, и строка одного вызова не перемешивается с чужой.

## Ввод: scanf и fgets

`scanf`, `fscanf`, `sscanf` понимают `%d %i %u %o %x %p`, дробные `%f %e %g %a` (с `l` — в `double`, без — в `float`), `%s`, `%c`, наборы `%[a-z]` и `%[^,]`, `%n`, пропуск `%*d` и ширину, а также размеры Microsoft `%I64d`, `%I64u`, `%I32d` и `%Id`. Возвращают они, сколько значений удалось присвоить, а `EOF` — если ввод кончился раньше первого. На этом построен обычный цикл «читать, пока читается».

Ввод из консоли приходит по строке: пока не нажат Enter, программа ждёт. Конец ввода в консоли Windows — Ctrl+Z и Enter. Если же на вход подан файл или вывод другой программы (`prog < data.txt`, `echo 1 2 | prog`), строки читаются оттуда, а `\r` перед `\n` библиотека убирает сама. Когда нужна одна клавиша без Enter, есть `conio.h` — о нём ниже.

```
#include <stdio.h>

int main(void)
{
    double x, sum = 0, max = 0;
    int n = 0;
    while (scanf("%lf", &x) == 1) {
        sum += x;
        if (n == 0 || x > max) max = x;
        n++;
    }
    if (n == 0) {
        printf("чисел нет\n");
        return 1;
    }
    printf("чисел %d, сумма %g, среднее %.2f, наибольшее %g\n", n, sum, sum / n, max);

    int day, month, year;
    char name[32];
    if (sscanf("04.11.2026 Среда", "%d.%d.%d %31s", &day, &month, &year, name) == 4)
        printf("день %d, месяц %d, год %d, %s\n", day, month, year, name);
    return 0;
}
```

```
wcc stats.c
echo 3 14 15 9.5 -2 | stats
```

```
чисел 5, сумма 39.5, среднее 7.90, наибольшее 15
день 4, месяц 11, год 2026, Среда
```

`fgets` читает строку целиком вместе с `\n` и не переполняет буфер; для ввода текста от человека он надёжнее `scanf("%s")`, который останавливается на первом пробеле. `sscanf` разбирает уже прочитанную строку — так удобно разбирать даты, координаты, строки файлов настроек.

## Файлы

`fopen`, `fclose`, `fread`, `fwrite`, `fgets`, `fputs`, `fgetc`, `fputc`, `ungetc`, `fprintf`, `fscanf`, `fseek`, `ftell`, `rewind`, `fgetpos`, `fsetpos`, `feof`, `ferror`, `clearerr`, `fflush`, `freopen`, `setvbuf`, `tmpfile`, `tmpnam`, `remove`, `rename`, `perror` — всё на месте, а сверх стандарта — `_fseeki64`, `_ftelli64`, `fileno` и `fdopen`. Режимы — `r`, `w`, `a` с `+`, `b` и `x` («создать, только если файла нет»). Имена файлов — UTF-8: `fopen("дневник.txt", "a")` работает без всяких преобразований. Разделитель папок — `\` или `/`. Одновременно открытыми могут быть до 512 файлов.

Файл читается и пишется кусками. У каждого открытого `FILE` есть буфер в 4 КБ: `fgets` и `fread` берут данные из него, а когда буфер кончается, библиотека читает с диска следующий кусок через дескриптор файла Windows. Запись копится в том же буфере и уходит на диск, когда он наполнится, а также при `fflush`, `fclose` и в конце программы. Поэтому размер файла не важен: журнал в несколько гигабайт читается построчно и занимает в памяти всё те же 4 КБ. Исключение одно — `tmpfile`: временный файл без имени живёт целиком в памяти и на диск не попадает.

У буфера есть обратная сторона: то, что ещё лежит в нём, другие программы не видят, а при падении программы оно пропадёт. Журнал, который должен пережить сбой, сбрасывают `fflush` после каждой строки или открывают с записью по строкам — это делает `setvbuf`, о нём ниже.

### Текстовый и двоичный режим

Буква `b` в режиме открытия значит то же, что в библиотеке Microsoft. Без неё файл открыт в текстовом режиме, и библиотека переводит концы строк на принятый в Windows лад: при записи каждый `\n` становится парой `\r\n`, при чтении пара `\r\n` снова становится одним `\n`, а байт Ctrl+Z (код 0x1A) считается концом текста — дальше него чтение возвращает `EOF`. Программа работает со строками, которые кончаются одним `\n`, а файл на диске выходит таким, каким его ждут Блокнот и другие программы Windows. С буквой `b` файл двоичный: байты пишутся и читаются как есть, без замен.

Текстовый режим хорош для текста — журналов, настроек, таблиц CSV. Для всего остального — картинок, архивов, своих двоичных форматов — нужен `b`. В текстовом режиме байт 0x0A превратится при записи в два, байт 0x1A оборвёт чтение на середине, и число, которое вернёт `fread`, не совпадёт с размером файла на диске. `ftell` и `fseek` и в текстовом режиме считают байты на диске: после записи `"a\nb\n"` `ftell` вернёт 6, а не 4.

! До версии 1.2.0 WinCC писал `\n` без `\r` в любом режиме. Программе, которая сравнивает байты файла с ожидаемыми, считает их или пишет двоичные данные, теперь нужен режим с `b`: `"rb"`, `"wb"`, `"ab"`, `"r+b"`.

Программа ниже — маленький дневник: с текстом в командной строке она дописывает строку с датой, без текста — показывает записи.

```
#include <stdio.h>
#include <string.h>
#include <time.h>

int main(int argc, char **argv)
{
    const char *name = "дневник.txt";
    if (argc > 1) {                         // есть текст — дописать строку
        FILE *f = fopen(name, "a");
        if (!f) { perror(name); return 1; }
        char when[32];
        time_t now = time(NULL);
        strftime(when, sizeof when, "%d.%m.%Y %H:%M", localtime(&now));
        fprintf(f, "%s  ", when);
        for (int i = 1; i < argc; i++)
            fprintf(f, "%s%s", argv[i], i + 1 < argc ? " " : "\n");
        fclose(f);                          // fclose отдаёт буфер на диск
    }
    FILE *f = fopen(name, "r");
    if (!f) { perror(name); return 1; }
    char line[512];
    int n = 0;
    while (fgets(line, sizeof line, f))
        printf("%3d  %s", ++n, line);
    fseek(f, 0, SEEK_END);
    printf("записей %d, файл %ld байт\n", n, ftell(f));
    fclose(f);
    return 0;
}
```

diary Купить хлеба
diary Позвонить в мастерскую
```

```

  2  04.11.2026 02:09  Позвонить в мастерскую

Текста в двух строках — 103 байта вместе с двумя `\n`. На диске же файл занимает 105: дневник открыт без `b`, и каждая строка там кончается парой `\r\n`. `fgets` вернула строки с одним `\n`, как программа их и писала.

Когда `fopen` не может открыть файл, он возвращает `NULL` и пишет причину в `errno`: `ENOENT` — нет файла или папки, `EACCES` — нет доступа, `EISDIR` — это папка, `EEXIST` — файл уже есть (режим `x`). `perror` печатает имя и причину словами, `strerror` даёт эти слова строкой. Язык слов задаёт локаль: в стартовой локали `C` они такие же, как в стандартных библиотеках, — «No such file or directory», а в русской локали — русские (раздел «Локаль» ниже).

### Большие файлы, номера и буфер

`fseek` и `ftell` берут и возвращают `long`, а он в Windows занимает 4 байта, то есть не дальше 2 ГБ. Для мест дальше есть `_fseeki64` и `_ftelli64` с 64-битным местом в файле — те же имена, что у Microsoft. Вместе с чтением кусками это делает обычный `FILE` пригодным для файлов любого размера. Программа ниже показывает конец журнала, сколько бы он ни весил: прыгает к последнему килобайту и читает только его.

```
#include <stdio.h>

int main(int argc, char **argv)
{
    if (argc < 2) {
        printf("укажите файл\n");
        return 1;
    }
    FILE *f = fopen(argv[1], "rb");
    if (!f) { perror(argv[1]); return 1; }
    _fseeki64(f, 0, SEEK_END);
    long long size = _ftelli64(f);
    long long from = size > 1024 ? size - 1024 : 0;     // последний килобайт
    _fseeki64(f, from, SEEK_SET);
    char tail[1025];
    size_t n = fread(tail, 1, 1024, f);
    tail[n] = 0;
    printf("размер %lld байт, конец файла:\n%s\n", size, tail);
    fclose(f);
    return 0;
}
```

Файл здесь открыт с `b`: программа считает байты и прыгает по смещению, и ей нужны байты как есть.

`fileno` (или `_fileno`) даёт номер открытого `FILE` — дескриптор, с которым работают функции `io.h` (раздел ниже). `fdopen` (или `_fdopen`) делает обратное: оборачивает в `FILE` уже открытый номер, чтобы писать в него `fprintf` и читать `fgets`.

`setvbuf` выбирает, когда буфер уходит на диск: `_IOFBF` — когда наполнится (так по умолчанию), `_IOLBF` — после каждой строки, `_IONBF` — сразу при каждой записи, без буфера. Журнал, который должен пережить сбой программы, удобно открыть так:

```
FILE *log = fopen("журнал.txt", "a");
setvbuf(log, NULL, _IOLBF, 0);       // каждая строка уходит на диск сразу
fprintf(log, "запуск\n");
```

## stdlib: память, числа, сортировка

`malloc`, `calloc`, `realloc` и `free` берут память у Windows кусками по 16 МБ и больше и раздают её программе; звать их можно из любого потока. `aligned_alloc` выдаёт память с любым выравниванием — любой степенью двойки, — и освобождается она обычным `free`. Числа из строк — `atoi`, `atol`, `atof`, `strtol`, `strtoul`, `strtoll`, `strtoull`, `strtod`, `strtof`; функции `strto…` говорят через второй аргумент, где кончилось число, и потому годятся для проверки ввода. Есть `abs`, `labs`, `llabs`, `div`, `ldiv`, `lldiv`.

`qsort` сортирует массив чего угодно по функции сравнения, `bsearch` ищет в отсортированном массиве по той же функции. В примере — маленький справочник валют с условными курсами: код валюты берётся из командной строки, без него ищется `EUR`. Последняя строка показывает, как числа читаются из начала строки, а лишнее после них отбрасывается.

```
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

typedef struct { char code[4]; const char *name; double rate; } Currency;

static int by_code(const void *a, const void *b)
{
    return strcmp(((const Currency *)a)->code, ((const Currency *)b)->code);
}

int main(int argc, char **argv)
{
    Currency list[] = {
        { "USD", "доллар", 3.65 }, { "EUR", "евро", 3.95 }, { "GBP", "фунт", 4.70 },
        { "CHF", "франк", 4.20 }, { "JPY", "иена", 0.024 },
    };
    size_t n = sizeof list / sizeof list[0];
    qsort(list, n, sizeof list[0], by_code);
    for (size_t i = 0; i < n; i++)
        printf("%s ", list[i].code);
    printf("\n");

    Currency key = { 0 };
    strncpy(key.code, argc > 1 ? argv[1] : "EUR", 3);
    Currency *c = bsearch(&key, list, n, sizeof list[0], by_code);
    if (c) printf("%s — %s, %.3f шекеля\n", c->code, c->name, c->rate);
    else printf("%s — не знаю такой валюты\n", key.code);

    long v = strtol("ff", NULL, 16);
    double d = strtod("2.5e3 метра", NULL);
    printf("%ld %g %d\n", v, d, atoi("  -42 и дальше"));
    return 0;
}
```

```
CHF EUR GBP JPY USD
EUR — евро, 3.950 шекеля
255 2500 -42
```

`rand` — генератор из текста стандарта: `RAND_MAX` равен 32767, как у Microsoft, и без `srand` последовательность у каждого запуска одна и та же. Для игр этого хватает; для паролей и ключей нужен криптографический генератор Windows из её DLL — как звать функции любой DLL, рассказано в главе 11.

`exit` завершает программу из любого места: вызываются функции, зарегистрированные `atexit` (сколько угодно, в обратном порядке), открытые файлы записываются на диск. `_Exit` и `quick_exit` выходят без этого. `abort` печатает `abort()` и завершает программу с кодом 3, ничего не сохраняя.

## Строки и символы

В `string.h` — всё из стандарта (`strlen`, `strcpy`, `strncpy`, `strcat`, `strcmp`, `strncmp`, `strchr`, `strrchr`, `strstr`, `strspn`, `strcspn`, `strpbrk`, `strtok`, `strerror`, `strcoll`, `strxfrm`, `memcpy`, `memmove`, `memset`, `memcmp`, `memchr`) и полезное из POSIX: `strdup`, `strndup`, `strnlen`, `stpcpy`, `strtok_r`, `memccpy`, `strcasecmp`, `strncasecmp`. Есть и имена, под которыми те же функции знает библиотека Microsoft: `_strdup`, `_strndup`, `_stricmp`, `_strnicmp`, `_strcmpi`, `stricmp`, `strnicmp`, а в `stdio.h` — `_snprintf` и `_vsnprintf`. Код из проектов Visual Studio с ними собирается как есть. `strtok` помнит место в строке отдельно для каждого потока, так что два потока могут резать свои строки одновременно.

Функции `ctype.h` — `isalpha`, `isdigit`, `isspace`, `toupper` и остальные — смотрят на один байт, поэтому знают только латиницу и цифры: русская буква в UTF-8 для них — два байта, ни один из которых не буква. `strlen` считает байты, а не буквы, `strcmp` сравнивает байты. Порядок слов по алфавиту языка даёт `strcoll` с выбранной локалью (раздел «Локаль» ниже); как работать с кириллицей по буквам — в главе 7.

## Математика

`math.h` — полный набор C99 для `double`: корни и степени (`sqrt`, `cbrt`, `pow`, `hypot`), экспоненты и логарифмы (`exp`, `exp2`, `expm1`, `log`, `log2`, `log10`, `log1p`), тригонометрия прямая, обратная и гиперболическая, округления (`floor`, `ceil`, `round`, `trunc`, `rint`, `lround`), остатки (`fmod`, `remainder`, `remquo`, `modf`), `frexp`, `ldexp`, `fma`, `erf`, `tgamma`, `lgamma`, проверки `isnan`, `isinf`, `isfinite`, `signbit`, `fpclassify`. Для `float` есть варианты с буквой `f` — `sqrtf`, `sinf`, `powf` и ещё два десятка. Константы `M_PI`, `M_E`, `M_SQRT2` и другие определены сразу, без особых макросов. Функции с буквой `l` считают в `double`, потому что `long double` здесь — это `double`.

Ошибку математические функции отмечают в `errno`: `EDOM`, если аргумент вне области (корень из отрицательного), `ERANGE`, если ответ не помещается в `double`.

```
#include <stdio.h>
#include <math.h>
#include <errno.h>

int main(void)
{
    // из прямоугольных координат в полярные и обратно
    double x = 3, y = 4;
    double r = hypot(x, y), a = atan2(y, x);
    printf("r = %g, угол = %.4f рад = %.2f°\n", r, a, a * 180 / M_PI);
    printf("обратно: %.6f %.6f\n", r * cos(a), r * sin(a));
    printf("floor %g, ceil %g, round %g, trunc %g\n", floor(-2.5), ceil(-2.5), round(-2.5), trunc(-2.5));
    printf("cbrt(27) = %g, exp2(10) = %g, log10(1e6) = %g\n", cbrt(27), exp2(10), log10(1e6));

    errno = 0;
    double bad = sqrt(-1);
    printf("sqrt(-1) = %f, errno = %d (EDOM = %d)\n", bad, errno, EDOM);
    errno = 0;
    double big = exp(1000);
    printf("exp(1000) = %f, errno = %d (ERANGE = %d), isinf = %d\n", big, errno, ERANGE, isinf(big));
    return 0;
}
```

```
r = 5, угол = 0.9273 рад = 53.13°
обратно: 3.000000 4.000000
floor -3, ceil -2, round -3, trunc -2
cbrt(27) = 3, exp2(10) = 1024, log10(1e6) = 6
sqrt(-1) = nan, errno = 33 (EDOM = 33)
exp(1000) = inf, errno = 34 (ERANGE = 34), isinf = 1
```

## Комплексные числа, округление, tgmath

Три заголовка из папки `include` дополняют `math.h`.

`complex.h` устроен так, как в библиотеке Microsoft. Языкового типа `_Complex` в WinCC нет — макрос `__STDC_NO_COMPLEX__` равен 1, — и комплексное число здесь — структура из двух частей: `_Dcomplex` для `double`, `_Fcomplex` для `float`. Собирают её функцией `_Cbuild(вещественная, мнимая)`, части достают `creal` и `cimag`. Знаки `+` и `*` к структуре не применить, поэтому действия — тоже функции: `_Cmulcc` умножает два комплексных числа, `_Cmulcr` — комплексное на вещественное. Сложения, вычитания и деления у Microsoft нет; WinCC добавляет свои `_Caddcc`, `_Csubcc` и `_Cdivcc` — в коде, который должен собираться и в Visual Studio, их пишут сами в две строки. Функции стандарта все на месте: `cabs`, `carg`, `conj`, `cproj`, `cexp`, `clog`, `clog10`, `csqrt`, `cpow`, `csin`, `ccos`, `ctan` и обратные и гиперболические до `catanh`.

```
#include <stdio.h>
#include <complex.h>

int main(void)
{
    // корни уравнения x² + 2x + 5 = 0: дискриминант отрицательный
    double a = 1, b = 2, c = 5;
    _Dcomplex d = csqrt(_Cbuild(b * b - 4 * a * c, 0));       // корень из −16 — это 4i
    _Dcomplex x1 = _Cmulcr(_Caddcc(_Cbuild(-b, 0), d), 1 / (2 * a));
    _Dcomplex x2 = _Cmulcr(_Csubcc(_Cbuild(-b, 0), d), 1 / (2 * a));
    printf("x1 = %g%+gi, x2 = %g%+gi\n", creal(x1), cimag(x1), creal(x2), cimag(x2));

    _Dcomplex z = _Cbuild(3, 4);
    printf("|3+4i| = %g, угол %.4f рад\n", cabs(z), carg(z));
    return 0;
}
```

```
x1 = -1+2i, x2 = -1-2i
|3+4i| = 5, угол 0.9273 рад
```

`fenv.h` управляет самой дробной арифметикой. `fesetround` выбирает, куда округлять результат, который не представим точно: к ближайшему (`FE_TONEAREST`, так по умолчанию), вниз (`FE_DOWNWARD`), вверх (`FE_UPWARD`) или к нулю (`FE_TOWARDZERO`); `fegetround` говорит, какое округление действует. Округление вниз и вверх нужно, например, чтобы получить вилку, внутри которой точно лежит настоящий ответ. Флаги исключений — `FE_DIVBYZERO`, `FE_OVERFLOW`, `FE_UNDERFLOW`, `FE_INVALID`, `FE_INEXACT` — запоминают, что случилось при счёте: деление на ноль не останавливает программу, а только поднимает флаг, и `fetestexcept` его увидит. `feclearexcept` флаги сбрасывает, `feraiseexcept` поднимает, `fegetenv`, `fesetenv`, `feholdexcept` и `feupdateenv` сохраняют и возвращают всё состояние сразу. Настройки меняются у обоих вычислителей процессора вместе — у SSE, которым считаются `double` и `float`, и у x87 из вставок на ассемблере (глава 8).

```
#include <stdio.h>
#include <fenv.h>

int main(void)
{
    volatile double one = 1, three = 3, zero = 0;    // volatile: считать при выполнении
    fesetround(FE_DOWNWARD);
    double down = one / three;
    fesetround(FE_UPWARD);
    double up = one / three;
    fesetround(FE_TONEAREST);
    printf("1/3 вверх больше, чем вниз: %s\n", up > down ? "да" : "нет");

    feclearexcept(FE_ALL_EXCEPT);
    double r = one / zero;
    printf("деление на ноль %s, результат %g\n", fetestexcept(FE_DIVBYZERO) ? "замечено" : "не замечено", r);
    return 0;
}
```

```
1/3 вверх больше, чем вниз: да
деление на ноль замечено, результат inf
```

`tgmath.h` даёт одно имя на две функции: `sqrt` от `float` зовёт `sqrtf`, от `double` или целого — `sqrt`. Так же устроены `sin`, `pow`, `exp`, `log`, `fabs`, `floor`, `round`, `hypot`, `atan2` и остальные обычные функции. Выбор делается при сборке через `_Generic`, ничего не стоит при выполнении и избавляет от ошибки, когда `float` молча считается в `double`. Работает он только с вещественными числами: комплексные здесь — структуры, и их функции зовут по своим именам.

```
#include <tgmath.h>

float half_diagonal(float w, float h)
{
    return sqrt(w * w + h * h) / 2;      // float: вызывается sqrtf
}
```

## Время

`time` возвращает число секунд с 1 января 1970 года по Гринвичу — то самое «время Unix», которое понимают базы данных, серверы и другие программы. `localtime` раскладывает его на год, месяц, день и часы по местному времени, с часовым поясом и летним временем, как они заданы в Windows; `gmtime` — по Гринвичу. `mktime` собирает разложенное местное время обратно в число, `strftime` печатает по шаблону, `difftime` вычитает. `clock` считает время работы программы в миллисекундах (`CLOCKS_PER_SEC` равен 1000); он берёт время у счётчика производительности Windows, и шаг у него — одна миллисекунда.

```
#include <stdio.h>
#include <time.h>

int main(void)
{
    time_t now = time(NULL);
    struct tm *t = localtime(&now);
    char text[64];
    strftime(text, sizeof text, "%d.%m.%Y, %H:%M:%S, день года %j", t);
    printf("%s\n", text);
    printf("год %d, месяц %d, день недели %d\n", t->tm_year + 1900, t->tm_mon + 1, t->tm_wday);

    struct tm newyear = { 0 };
    newyear.tm_year = t->tm_year + 1;
    newyear.tm_mon = 0;
    newyear.tm_mday = 1;
    double left = difftime(mktime(&newyear), now);
    printf("до Нового года %.0f дней\n", left / 86400);

    clock_t start = clock();
    volatile double s = 0;
    for (int i = 0; i < 20000000; i++)
        s += i * 0.5;
    printf("цикл занял %ld мс\n", (long)((clock() - start) * 1000 / CLOCKS_PER_SEC));
    return 0;
}
```

```
04.11.2026, 02:09:42, день года 308
год 2026, месяц 11, день недели 3
до Нового года 58 дней
цикл занял 78 мс
```

Местное время и время по Гринвичу различаются на часовой пояс, и `strftime` с `%z` показывает этот пояс числом. `mktime` считает переданную ему `struct tm` местным временем, поэтому `mktime(localtime(&t))` возвращает то же `t`.

```
#include <stdio.h>
#include <time.h>

int main(void)
{
    time_t now = time(NULL);
    char utc[32], here[32];
    strftime(utc, sizeof utc, "%H:%M", gmtime(&now));
    strftime(here, sizeof here, "%H:%M, пояс %z", localtime(&now));
    printf("по Гринвичу %s, здесь %s\n", utc, here);
    printf("mktime вернул то же число: %s\n", mktime(localtime(&now)) == now ? "да" : "нет");
    return 0;
}
```

```
по Гринвичу 00:32, здесь 03:32, пояс +0300
mktime вернул то же число: да
```

Число из `time` можно отдавать наружу — в базу, на сервер, в файл, который прочтёт другая программа: это настоящее время по Гринвичу. А для показа человеку его раскладывает `localtime`.

Названия месяцев и дней недели (`%a`, `%A`, `%b`, `%B`, `%c`) `strftime` пишет на языке локали: в стартовой локали `C` — такие, как велит стандарт (`January`, `Wednesday`), а после `setlocale(LC_ALL, "Russian")` — по-русски (раздел «Локаль» ниже). `%Z` даёт имя часового пояса — так, как его называет Windows. `ctime` печатает местное время. `timespec_get` с `TIME_UTC` даёт секунды и миллисекунды. Для замеров точнее миллисекунды есть `QueryPerformanceCounter` и счётчик тактов процессора `__rdtsc` из `intrin.h`.

## setjmp, longjmp и сигналы

`setjmp` запоминает место в программе, `longjmp` возвращается туда из любой глубины вызовов — это способ выйти из ошибки, не проверяя код возврата на каждом уровне. `jmp_buf` в WinCC занимает 4 КБ: кроме регистров, он хранит кусок стека вокруг вызова `setjmp`.

`signal` ставит обработчик сигнала, `raise` его вызывает. Сигналы `SIGINT`, `SIGTERM`, `SIGABRT` бывают только от `raise` и `abort`. А три сигнала посылает сам процессор: `SIGSEGV` — обращение к чужой памяти, `SIGFPE` — целочисленное деление на ноль, `SIGILL` — неверная инструкция. Программа, которая не ставила обработчика ни одного из них, на таком сбое ведёт себя как любая программа Windows: молча кончается, а что случилось, говорит код выхода (`C0000005` — чужая память, `C0000094` — деление на ноль). Перехват сбоев попадает в программу вместе с первым `signal` для одного из трёх сигналов. С ним сбой без обработчика (или после того, как обработчик снялся) печатает, что случилось:

```
программа остановлена: обращение к чужой памяти
```

С обработчиком и `longjmp` программа может пережить сбой и продолжить.

```
#include <stdio.h>
#include <setjmp.h>
#include <signal.h>

static jmp_buf retry;

static void on_fault(int sig)
{
    longjmp(retry, sig);
}

static int divide(int a, int b)
{
    return a / b;
}

int main(void)
{
    int divisors[] = { 5, 0, 4 };
    for (int i = 0; i < 3; i++) {
        signal(SIGFPE, on_fault);       // после срабатывания обработчик снимается
        int sig = setjmp(retry);
        if (sig == 0)
            printf("100 / %d = %d\n", divisors[i], divide(100, divisors[i]));
        else
            printf("100 / %d: сигнал %d, деление пропущено\n", divisors[i], sig);
    }
    return 0;
}
```

```
100 / 5 = 20
100 / 0: сигнал 8, деление пропущено
100 / 4 = 25
```

Обработчик после срабатывания снимается — так велит стандарт, — и его ставят заново перед следующей попыткой. Если обработчик вернётся, а не уйдёт через `longjmp`, программа всё равно будет остановлена: продолжить команду, которая упала, нельзя. Деление дробных чисел на ноль сигнала не даёт — получается бесконечность. Сбой становится сигналом, только если его не поймал блок `__try` (глава 5): библиотека слушает сбои последней.

Переполнение стека — бесконечная рекурсия, огромный локальный массив — сигналом не ловится. Программа завершается с кодом выхода `C00000FD`; если в ней есть перехват сбоев (стоит `signal` для `SIGSEGV`, `SIGFPE` или `SIGILL`), перед этим она печатает, что случилось и как быть:

```
программа остановлена: переполнение стека (слишком глубокая рекурсия или слишком большой массив внутри функции; больше стека даёт ключ wcc --stack МБ)
```

! Стек по умолчанию — 8 МБ. Большой массив внутри функции лучше взять у `malloc`, а если программе на самом деле нужна глубокая рекурсия, стек увеличивают ключом `--stack` (глава 4).

## Окружение и другие программы

`getenv` возвращает значение переменной окружения в UTF-8 или `NULL`, если её нет. У каждого имени своя строка: следующий `getenv` с другим именем прежнюю не затирает, и держать можно сколько угодно значений сразу. `system` передаёт команду `cmd.exe` и ждёт её конца; возвращает код выхода команды, а `system(NULL)` — 1, то есть командный процессор есть. Окно консоли у команды то же, что у программы.

Команда работает в кодировке UTF-8: на время её выполнения библиотека переключает консоль на кодовую страницу 65001, а потом возвращает прежнюю. Поэтому русские буквы в тексте команды доходят до `cmd.exe` правильно, а то, что команда пишет в файл (`dir > список.txt`), выходит в UTF-8 — в той же кодировке, что и всё остальное в программе.

```
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    const char *user = getenv("USERNAME");
    const char *windir = getenv("WINDIR");          // строка user от этого не меняется
    printf("пользователь %s, Windows в %s\n", user ? user : "?", windir ? windir : "?");
    if (!getenv("WINCC_DEMO"))
        printf("WINCC_DEMO не задана\n");

    int rc = system("ver > nul && echo команда выполнена && exit /b 3");
    printf("код выхода команды: %d\n", rc);
    return 0;
}
```

```
пользователь Admin, Windows в C:\Windows
WINCC_DEMO не задана
команда выполнена
код выхода команды: 3
```

`system` удобна, когда нужна именно команда `cmd.exe` — с перенаправлением, `&&`, встроенными командами вроде `dir`. Чтобы запустить программу напрямую, без `cmd.exe`, и не обязательно ждать её конца, есть `process.h` — о нём ниже.

## Локаль

Локаль — набор правил языка и страны: какой знак отделяет дробную часть числа, как называются месяцы, в каком порядке идут буквы алфавита, на каком языке сообщения об ошибках. Программа начинает в локали `C`, как требует стандарт: точка в числах, названия из стандарта, порядок строк по байтам. `setlocale` меняет локаль, и за каждой локалью WinCC стоит настоящая локаль Windows с её правилами.

Имена `setlocale` понимает в нескольких записях: `"ru_RU.UTF-8"`, `"ru-RU"`, `"ru"`, `"Russian"`, `"Russian_Russia.1251"`, `"English_United States"`, а также `"C"`, `"POSIX"`, `"C.UTF-8"` и `".UTF-8"`. Пустая строка `""` значит локаль пользователя — ту, что выбрана в настройках Windows. Незнакомое имя даёт `NULL`, и локаль остаётся прежней. Какое бы имя ни было выбрано, многобайтный текст остаётся UTF-8: `"Russian_Russia.1251"` даёт русские правила, но не кодировку 1251.

Локаль делится на категории, и каждую можно выбрать отдельно — например, русские названия месяцев, но точку в числах.

:= Категория | Что она меняет
: `LC_NUMERIC` | десятичный знак в `printf`, `scanf`, `strtod`, `localeconv`; в русской локали — запятая
: `LC_TIME` | названия месяцев и дней в `strftime`
: `LC_COLLATE` | порядок строк в `strcoll`, `strxfrm`, `wcscoll` — по правилам Windows
: `LC_CTYPE` | язык сообщений `strerror` и `perror`
: `LC_ALL` | все категории сразу

```
#include <stdio.h>
#include <stdlib.h>
#include <string.h>
#include <locale.h>
#include <time.h>
#include <errno.h>

static int by_alphabet(const void *a, const void *b)
{
    return strcoll(*(const char *const *)a, *(const char *const *)b);
}

int main(void)
{
    if (!setlocale(LC_ALL, "Russian")) {
        printf("русской локали нет\n");
        return 1;
    }
    printf("локаль %s, число %.1f, strtod(\"3,25\") = %g\n", setlocale(LC_ALL, NULL), 2.5, strtod("3,25", NULL));

    struct tm day = { 0 };
    day.tm_year = 126;                      // 2026
    day.tm_mday = 1;                        // 1 января
    char month[32];
    strftime(month, sizeof month, "%B", &day);
    printf("первый месяц года: %s\n", month);

    const char *words[] = { "яблоко", "ёж", "жук", "арбуз", "дом" };
    qsort(words, 5, sizeof words[0], by_alphabet);
    for (int i = 0; i < 5; i++)
        printf("%s ", words[i]);
    printf("\n%s\n", strerror(ENOENT));
    return 0;
}
```

Программа выбирает русскую локаль целиком. Число 2,5 печатается с запятой, и `strtod` читает `"3,25"` как три с четвертью. Название января приходит от Windows по-русски. Слова встают по алфавиту — `ёж` между `дом` и `жук`, а не в конце, куда его поставил бы `strcmp` (глава 7). Последняя строка — сообщение об отсутствии файла, тоже по-русски.

! `setlocale(LC_ALL, "")` на русской Windows включает и русский `LC_NUMERIC`: `printf("%.1f", 2.5)` напечатает `2,5`, а `strtod` будет ждать запятую. Для файлов, которые прочтёт другая программа (CSV, JSON, настройки), числа нужны с точкой: после `setlocale(LC_ALL, "")` числовую категорию возвращают — `setlocale(LC_NUMERIC, "C")`.

## Потоки: threads.h и stdatomic.h

Поток — вторая (третья, десятая) линия выполнения внутри одной программы: все потоки видят одни и те же глобальные переменные и память, но идут одновременно, каждый на своём ядре процессора. Это нужно, когда работу можно поделить — посчитать четыре куска данных на четырёх ядрах, — или когда долгое дело не должно останавливать остальное: скачивание, разбор большого файла.

`threads.h` — потоки из стандарта C11 поверх потоков Windows. `thrd_create` запускает функцию вида `int f(void *arg)` в новом потоке, `thrd_join` ждёт её конца и забирает число, которое она вернула; `thrd_detach` отпускает поток, если ждать его не нужно. `thrd_sleep`, `thrd_yield`, `thrd_current`, `thrd_equal` и `thrd_exit` — ожидание, уступка очереди, свой поток и выход из него.

Главная трудность потоков — общие данные. Строка `total += sum` — это три шага: прочитать, сложить, записать. Если два потока сделают их одновременно, оба прочтут старое значение, и одно прибавление пропадёт. Против этого есть два средства. Замок `mtx_t` пропускает к данным по одному потоку: `mtx_lock` ждёт, пока замок свободен, и занимает его, `mtx_unlock` освобождает. Замки бывают простые (`mtx_plain`), с ожиданием до срока (`mtx_timed`, `mtx_timedlock`) и повторные (`mtx_recursive`), которые один поток может занять несколько раз. А для одиночного счётчика замок не нужен: `stdatomic.h` даёт атомарные переменные, у которых каждое изменение — один неделимый шаг процессора.

```
#include <stdio.h>
#include <stdint.h>
#include <threads.h>
#include <stdatomic.h>

#define PARTS 4
#define LIMIT 1000000

static mtx_t sum_lock;
static long long total;              // общая сумма: меняется только под замком
static atomic_int sevens;            // счётчик: каждое прибавление — один неделимый шаг

static int work(void *arg)
{
    int part = (int)(intptr_t)arg;
    int from = part * (LIMIT / PARTS) + 1, to = from + LIMIT / PARTS;
    long long sum = 0;
    for (int i = from; i < to; i++) {
        sum += i;
        if (i % 7 == 0)
            atomic_fetch_add(&sevens, 1);
    }
    mtx_lock(&sum_lock);
    total += sum;
    mtx_unlock(&sum_lock);
    return 0;
}

int main(void)
{
    thrd_t t[PARTS];
    mtx_init(&sum_lock, mtx_plain);
    for (int i = 0; i < PARTS; i++)
        if (thrd_create(&t[i], work, (void *)(intptr_t)i) != thrd_success)
            return 1;
    for (int i = 0; i < PARTS; i++)
        thrd_join(t[i], NULL);
    mtx_destroy(&sum_lock);
    printf("сумма %lld, кратных семи %d\n", total, atomic_load(&sevens));
    return 0;
}
```

```
сумма 500000500000, кратных семи 142857
```

Четыре потока делят числа от одного до миллиона на четыре куска. Каждый складывает свой кусок в локальную `sum` — она у каждого потока своя, и защищать её не надо, — а в общую `total` добавляет один раз, под замком. Счётчик кратных семи прибавляется часто, и для него взята атомарная переменная: `atomic_fetch_add` не пропустит ни одного прибавления, сколько бы потоков ни работали сразу.

Остальное из `threads.h`: условная переменная `cnd_t` (`cnd_wait`, `cnd_signal`, `cnd_broadcast`, `cnd_timedwait`) — способ уснуть под замком, пока другой поток не скажет «данные готовы»; `tss_create`, `tss_set`, `tss_get` — значение, у каждого потока своё, с функцией-уборщиком, которая вызывается при конце потока; `call_once` — вызвать функцию подготовки ровно один раз, сколько бы потоков к ней ни пришли. Слово `thread_local` (оно же `_Thread_local`) делает глобальную переменную своей у каждого потока. `errno` у каждого потока и так своя.

В `stdatomic.h` — типы `atomic_int`, `atomic_long`, `atomic_bool`, `atomic_size_t` и другие, функции `atomic_load`, `atomic_store`, `atomic_exchange`, `atomic_compare_exchange_strong` и `atomic_compare_exchange_weak` («записать новое, только если там всё ещё старое»), `atomic_fetch_add`, `atomic_fetch_sub`, `atomic_fetch_or`, `atomic_fetch_and`, `atomic_fetch_xor`, их варианты с `_explicit`, флаг `atomic_flag` и `atomic_thread_fence`. Обычные знаки тоже работают: у переменной `_Atomic int n` запись `n += 5` или `n++` — один неделимый шаг.

## Консоль без Enter: conio.h

`scanf` и `fgets` получают строку только после Enter. Меню, игре, программе «нажмите любую клавишу» нужна одна клавиша сразу — это даёт `conio.h`. `_getch` ждёт клавишу и возвращает её, не показывая на экране и не дожидаясь Enter; `_getche` то же, но с показом. `_kbhit` не ждёт, а только говорит, нажата ли клавиша, — так программа может заниматься своим делом и проверять клавиатуру между делами. `_ungetch` возвращает клавишу обратно, `_putch`, `_cputs` и `_cprintf` пишут прямо в консоль. Работают и старые имена без подчёркивания: `getch`, `kbhit`.

Клавиши без буквы — стрелки, F1…F12, Home, Delete — приходят за два вызова: сначала 0 или 0xE0, потом скан-код клавиши (вверх — 72, вниз — 80, влево — 75, вправо — 77, F1 — 59). Русская буква приходит от `_getch` по байтам UTF-8, двумя вызовами; целиком её даёт `_getwch` — как один `wchar_t`.

```
#include <stdio.h>
#include <conio.h>
#include <windows.h>

int main(void)
{
    printf("Стрелки влево и вправо двигают звезду, Esc — выход\n");
    int x = 20, steps = 0;
    for (;;) {
        printf("\r%*s*%*s шагов %d ", x, "", 40 - x, "", steps);
        while (!_kbhit())
            Sleep(20);                       // здесь могла бы идти своя работа
        int c = _getch();
        if (c == 27)                         // Esc
            break;
        if (c == 0 || c == 0xE0) {           // особая клавиша: следом её скан-код
            int code = _getch();
            if (code == 75 && x > 0) x--;
            if (code == 77 && x < 40) x++;
            steps++;
        }
    }
    printf("\nготово\n");
    return 0;
}
```

Звезда перерисовывается в той же строке: `\r` возвращает курсор в её начало. Цикл с `_kbhit` и `Sleep` показывает главное: программа не стоит в ожидании клавиши, а сама решает, когда её спросить.

## Файлы по номерам и папки: io.h, direct.h, sys/stat.h

`FILE` из `stdio.h` — удобная обёртка с буфером. Под ней лежит уровень проще: открытый файл — это номер, дескриптор, а читают и пишут его функции `_open`, `_read`, `_write`, `_lseek` и `_close` из `io.h`, как в библиотеке Microsoft. Номера 0, 1 и 2 — стандартные ввод, вывод и ошибки. Этот уровень встречается в старом коде и в переносимых программах, а пригождается, когда нужен дескриптор Windows (`_get_osfhandle`) или когда файл открывает одна функция, а `FILE` нужен другой (`fdopen`).

Как открыть файл, говорят флаги из `fcntl.h`: `_O_RDONLY`, `_O_WRONLY` или `_O_RDWR`, а к ним `_O_CREAT` (создать), `_O_TRUNC` (обрезать), `_O_APPEND`, `_O_EXCL` и режим — `_O_BINARY` (байты как есть) или `_O_TEXT` (`\n` в файле становится `\r\n`, как в текстовом режиме `FILE`). `_setmode` меняет режим уже открытого номера. Имена файлов — UTF-8. Есть и имена POSIX без подчёркивания: `open`, `read`, `write`, `close`.

```
int fd = _open("данные.bin", _O_RDONLY | _O_BINARY);
if (fd >= 0) {
    char head[4];
    int n = _read(fd, head, sizeof head);        // сколько байт прочитано
    long size = _filelength(fd);
    _close(fd);
}
```

Ещё в `io.h`: `_access` проверяет, есть ли файл (`_access(имя, 0) == 0`), `_unlink` удаляет файл, `_dup` и `_dup2` копируют номер, `_isatty` говорит, консоль ли это, `_chsize` меняет длину файла, `_commit` дописывает его на диск. И главное для работы с папками — поиск файлов по маске: `_findfirst` находит первый файл, `_findnext` — следующие, `_findclose` заканчивает поиск. В структуре `_finddata_t` — имя, размер, время записи и признаки (`_A_SUBDIR` — это папка).

`direct.h` — сами папки: `_mkdir` создаёт, `_rmdir` удаляет пустую, `_chdir` делает текущей, `_getcwd` возвращает текущую (с пустым буфером — новую строку от `malloc`, которую потом отдают `free`), `_getdrive` и `_chdrive` — текущий диск. `sys/stat.h` — сведения о файле: `stat` и `fstat` заполняют `struct stat` с 64-битным размером `st_size` и временами `st_mtime`, `st_atime`, `st_ctime`, а `S_ISDIR` и `S_ISREG` говорят, папка это или файл.

```
#include <stdio.h>
#include <stdlib.h>
#include <time.h>
#include <io.h>
#include <direct.h>

int main(int argc, char **argv)
{
    const char *mask = argc > 1 ? argv[1] : "*.c";
    char *here = _getcwd(NULL, 0);
    printf("папка %s, маска %s\n", here, mask);
    free(here);

    struct _finddata_t fd;
    intptr_t h = _findfirst(mask, &fd);
    if (h == -1) {
        printf("ничего не найдено\n");
        return 0;
    }
    long long sum = 0;
    int n = 0;
    do {
        if (fd.attrib & _A_SUBDIR)
            continue;                        // папки пропускаем
        char when[32];
        time_t t = fd.time_write;
        strftime(when, sizeof when, "%d.%m.%Y %H:%M", localtime(&t));
        printf("%-24s %10lu  %s\n", fd.name, fd.size, when);
        sum += fd.size;
        n++;
    } while (_findnext(h, &fd) == 0);
    _findclose(h);
    printf("файлов %d, всего %lld байт\n", n, sum);
    return 0;
}
```

Программа печатает файлы текущей папки по маске из командной строки (`list *.txt`), с размером и временем последней записи. Имена с кириллицей приходят в UTF-8, и `%-24s` выравнивает их по буквам. Узнать размер одного файла проще через `stat`:

```
struct stat st;
if (stat("отчёт.txt", &st) == 0 && S_ISREG(st.st_mode))
    printf("%lld байт, изменён %s", st.st_size, ctime(&st.st_mtime));
```

## Другие программы: process.h

`system` запускает команду через `cmd.exe` и всегда ждёт её конца. `process.h` запускает программу напрямую и даёт выбор, ждать или нет. Функции `_spawn…` различаются буквами: `l` — аргументы перечислены через запятую и кончаются `NULL`, `v` — переданы массивом; `p` — программа ищется в папках `PATH`, как в командной строке. Первый аргумент — режим:

:= Режим | Что делает
: `_P_WAIT` | ждать конца; ответ — код выхода программы
: `_P_NOWAIT` | идти дальше; ответ — описатель процесса, дождаться можно `_cwait`
: `_P_OVERLAY` | эта программа кончается, и её код выхода — код новой программы
: `_P_DETACH` | запустить отдельно, без консоли

Функции `_exec…` — то же, что `_spawn…` с `_P_OVERLAY`. `_getpid` даёт номер своего процесса.

```
#include <stdio.h>
#include <process.h>

int main(void)
{
    // запустить и дождаться: ответ — код выхода
    intptr_t code = _spawnlp(_P_WAIT, "cmd", "cmd", "/c", "exit 7", NULL);
    printf("первая команда вернула %d\n", (int)code);

    // запустить и идти дальше, а дождаться потом
    intptr_t h = _spawnlp(_P_NOWAIT, "cmd", "cmd", "/c", "exit 5", NULL);
    printf("вторая команда запущена, эта программа — процесс %d\n", _getpid());
    int status = 0;
    _cwait(&status, h, _WAIT_CHILD);
    printf("вторая команда вернула %d\n", status);
    return 0;
}
```

Чаще второй режим нужен, чтобы открыть что-то для человека и не ждать: `_spawnlp(_P_NOWAIT, "notepad", "notepad", "заметки.txt", NULL)` открывает Блокнот, а программа продолжает работу.

Там же — потоки в стиле Microsoft. `_beginthreadex` запускает функцию вида `unsigned __stdcall f(void *arg)` и возвращает описатель потока Windows: его ждут `WaitForSingleObject`, код выхода берут `GetExitCodeThread`, а потом закрывают `CloseHandle`. Это тот же поток, что и у `thrd_create`; удобнее та запись, что принята в остальном коде программы.

## Память: malloc.h

`_alloca(n)` берёт `n` байт в стеке самой функции. Такая память освобождается сама при выходе из функции, `free` для неё не нужен, а взять её быстрее, чем у `malloc`, — это сдвиг указателя стека. Подходит она для временного буфера, размер которого известен только при выполнении. Большие куски она проходит постранично, как того требует Windows, но стек не безграничен — 8 МБ по умолчанию, — и на мегабайты лучше брать `malloc`. `alloca` — то же без подчёркивания, `_malloca` здесь всегда берёт в стеке, `_freea` ничего не делает.

`_aligned_malloc(размер, выравнивание)` выдаёт память, адрес которой делится на выравнивание — любую степень двойки, хоть 64 байта под строку кэша процессора, хоть 4096 под страницу; освобождает её `_aligned_free`. `_msize` говорит, сколько байт в блоке от `malloc`, `_expand` пробует изменить размер блока, не перенося его.

```
#include <malloc.h>
#include <string.h>

void fill_line(int width)
{
    char *line = _alloca(width + 1);         // освободится при выходе из функции
    memset(line, '-', width);
    line[width] = 0;
    // ...
    void *table = _aligned_malloc(1 << 20, 64);    // адрес кратен 64
    // ...
    _aligned_free(table);
}
```

## Команды процессора: intrin.h

`intrin.h` — то же, что у Microsoft: отдельные команды процессора, записанные как функции. Каждая — макрос из нескольких строк ассемблера, поэтому вызова функции не происходит: в программе остаётся сама команда.

:= Что | Функции
: процессор | `__cpuid`, `__cpuidex`, `__rdtsc`, `__rdtscp`, `_xgetbv`, `__debugbreak`, `_mm_pause`
: биты | `__popcnt`, `__lzcnt`, `_tzcnt_u32`, `_BitScanForward`, `_BitScanReverse`, `_bittest`, `_bittestandset`
: порядок байт и сдвиги | `_byteswap_ushort`, `_byteswap_ulong`, `_byteswap_uint64`, `_rotl`, `_rotr`, `_rotl64`
: 128-битная арифметика | `_umul128`, `_mul128`, `__umulh`, `_addcarry_u64`, `_subborrow_u64`, `__shiftleft128`
: память и барьеры | `__stosb`, `__movsb`, `_mm_mfence`, `_ReadWriteBarrier`, `__readgsqword`, `NtCurrentTeb`
: атомарные действия | `_InterlockedIncrement`, `_InterlockedExchange`, `_InterlockedCompareExchange`, `_InterlockedOr` и другие

У многих функций есть варианты для 16 и 64 бит: `__popcnt16`, `__popcnt64`, `_BitScanForward64`. Функций SSE с типом `__m128` в WinCC нет — такие места пишут вставкой на ассемблере (глава 8).

```
#include <stdio.h>
#include <string.h>
#include <intrin.h>

int main(void)
{
    int info[4];
    char vendor[13];
    __cpuid(info, 0);                        // лист 0: имя производителя в ebx, edx, ecx
    memcpy(vendor, &info[1], 4);
    memcpy(vendor + 4, &info[3], 4);
    memcpy(vendor + 8, &info[2], 4);
    vendor[12] = 0;
    printf("процессор %s\n", vendor);

    __cpuid(info, 1);                        // лист 1: что процессор умеет
    printf("popcnt %s, sse4.2 %s\n", (info[2] >> 23) & 1 ? "есть" : "нет",
           (info[2] >> 20) & 1 ? "есть" : "нет");

    unsigned mask = 0xF0F0;
    unsigned long low;
    _BitScanForward(&low, mask);
    printf("в %#x единиц %u, младшая на месте %lu\n", mask, __popcnt(mask), low);
    printf("%#x задом наперёд: %#lx\n", 0x11223344, _byteswap_ulong(0x11223344));
    return 0;
}
```

`__cpuid` спрашивает процессор, кто он и что умеет, — так программа решает, можно ли ей пользоваться новыми командами. `__popcnt` считает единичные биты, `_BitScanForward` находит младший из них, `_byteswap_ulong` переворачивает порядок байт — это нужно при разборе сетевых и файловых форматов, где числа записаны старшим байтом вперёд.

## Итог

Библиотека Си собирается вместе с программой из исходников, и в exe попадает только нужное. Двадцать пять стандартных заголовков встроены в компилятор, ещё полтора десятка заголовков Microsoft и C11 лежат в папке `include`. `printf` знает все форматы стандарта, `%b` и `%I64d`, считает ширину в буквах, `%ld` берёт 4 байта; `snprintf` не режет букву UTF-8; ввод-вывод можно звать из нескольких потоков. Файл читается и пишется кусками по 4 КБ, его размер не важен; без `b` файл текстовый, как у Microsoft, — `\n` на диске становится `\r\n`, — а для байтов как есть нужен `b`. Места дальше 2 ГБ дают `_fseeki64` и `_ftelli64`, буфер настраивает `setvbuf`.

`clock` идёт шагом в 1 мс, `atexit` принимает сколько угодно функций, `getenv` держит своё значение для каждого имени, команды `system` работают в UTF-8. `setlocale` выбирает настоящие локали Windows по категориям: запятую в числах, русские месяцы, алфавитный порядок `strcoll`, русские сообщения `strerror`. Потоки дают `threads.h` и `process.h`, неделимые счётчики — `stdatomic.h`; комплексные числа в стиле Microsoft — `complex.h`, округление — `fenv.h`; клавиши без Enter — `conio.h`; файлы по номерам и папки — `io.h`, `direct.h`, `sys/stat.h`; память в стеке и с выравниванием — `malloc.h`; отдельные команды процессора — `intrin.h`. Сбои процессора становятся сигналами `SIGSEGV`, `SIGFPE`, `SIGILL` и ловятся через `signal` и `longjmp`; переполнение стека программа называет сама и выходит.
