# Отладчик
Отладчик останавливает программу на нужной строке и показывает, что у неё внутри: значения переменных, кто кого вызвал, куда она пойдёт дальше. Вместо того чтобы гадать по выводу и вставлять `printf` в каждую строку, программу проходят по шагам и видят, где она свернула не туда. В WinCC отладчик встроен в окно редактора: точка останова ставится щелчком, программа запускается клавишей F5. Эта глава показывает, как найти ошибку отладчиком, что видно в его вкладках, как он ведёт себя при падении программы и чем различаются режимы сборки «Отладка» и «Выпуск».

## Что нужно отладчику

Готовая программа — это машинный код: в `.exe` нет ни имён переменных, ни номеров строк. Чтобы показать строку исходника и значение переменной `sum`, отладчику нужно знать, какие адреса кода принадлежат какой строке, где в памяти лежит каждая переменная и какого она типа. Эти сведения компилятор записывает в отдельный файл рядом с программой — `программа.wdbg` — когда его просят ключом `-g`.

Второе условие — переменные должны лежать в памяти. Обычный режим WinCC держит самые нужные переменные в регистрах процессора: так программа быстрее и меньше (глава 1). Отладчик умеет читать и регистры, но удобнее, когда каждая переменная живёт на своём месте в памяти всё время работы функции. Это даёт ключ `-O0`.

:= Режим сборки | Ключи wcc | Что получается
: Отладка | `-g -O0` | файл `.wdbg` рядом с программой, все переменные в памяти; программа чуть больше и медленнее
: Выпуск | без ключей | оптимизированный код, сведений для отладчика нет; старый `.wdbg` удаляется

Режим выбирается списком на панели кнопок окна WinCC, слева от вида программы. У проекта режим свой и хранится в самом проекте строкой `config=Debug` или `config=Release`. Пока программу пишут и проверяют, держат «Отладку»; программу, которую отдают людям, собирают в «Выпуске».

! F5 запускает отладку в любом режиме. В «Выпуске» он сам добавляет `-g`: отладчик работает и с оптимизированной программой, просто часть переменных он читает из регистров.

## Точки останова и первая остановка

Возьмём программу с ошибкой. Она считает средние оценки двух учеников, и считает неправильно.

```
#include <stdio.h>

typedef struct {
    const char *name;
    int marks[4];
} Student;

static double average(const int *m, int n)
{
    int sum = 0;
    for (int i = 0; i <= n; i++)
        sum += m[i];
    return (double)sum / n;
}

int main(void)
{
    Student group[2] = {
        { "Анна", { 5, 4, 5, 5 } },
        { "Борис", { 3, 4, 4, 3 } },
    };
    for (int k = 0; k < 2; k++)
        printf("%s: %.2f\n", group[k].name, average(group[k].marks, 4));
    return 0;
}
```

```
> оценки
Анна: 205841415.00
Борис: -450888020.50
```

Средние в сотни миллионов — значит, в сумму попало что-то чужое. Откройте файл в окне WinCC и поставьте точку останова на строке 12, `sum += m[i];`: щёлкните слева от её номера или встаньте на неё и нажмите F9. Слева появится красный кружок, сама строка подсветится красным. Точка останова — отметка «остановись здесь»: программа будет работать как обычно, пока не дойдёт до этой строки.

Нажмите F5. Окно соберёт программу в выбранном режиме, запустит её под отладчиком, и через мгновение программа замрёт: строка 12 станет жёлтой, слева от номера встанет жёлтая стрелка — сюда программа сейчас придёт, эта строка ещё не выполнена. Внизу откроется вкладка «Переменные».

@ 22-отладка.png | Программа стоит на строке 12: жёлтая стрелка, вкладка «Переменные» с параметрами функции average

Во вкладке видно:

:= Имя | Значение | Тип
: m | адрес вида 0x2A055FFBB8 → 5 | int *
:   [0] | 5 | int
:   [1] | 4 | int
: n | 4 | int
: i | 0 | int
: sum | 0 | int

`m` — указатель на оценки Анны: после адреса стоит то, на что он смотрит, — первая оценка, 5. Под ним, по раскрытию, оценки идут по номерам, как в массиве: `[0]`, `[1]`, `[2]`… Сколько их, указатель не знает, поэтому отладчик показывает по десять, а следующие десять — в строке `[10…19]`; за концом массива начнутся чужие числа. Пока программа стоит, текст в редакторе нельзя править: строки кода должны совпадать с тем, что выполняется.

## Шаги

Дальше программу ведут по шагам. Шагов три вида, и у каждого своя клавиша.

:= Клавиша | Шаг | Что делает
: F10 | с обходом | выполнить текущую строку и встать на следующую; вызовы функций выполняются целиком
: F11 | с заходом | то же, но если в строке вызывается функция программы — войти в неё и встать на её первую строку
: Shift+F11 | наружу | дойти до конца текущей функции и вернуться в ту строку, которая её вызвала
: F5 | продолжить | работать дальше до следующей точки останова или до конца
: Shift+F5 | стоп | закончить программу и отладку

Нажимайте F10 и смотрите на `i` и `sum`. Программа ходит между строками 11 и 12: строка 11 — проверка условия цикла и `i++`, строка 12 — сложение. После каждого сложения `sum` растёт: 5, 9, 14, 19. Значение, которое изменилось с прошлой остановки, отладчик выделяет красным — глаз сразу видит, что поменял последний шаг.

После четвёртой оценки `sum` равна 19, а `i` становится 4. Условие `i <= n` при `i = 4` и `n = 4` всё ещё истинно, и программа снова встаёт на строку 12. Ещё одно F10 — и `sum` превращается в 823365660. Ошибка найдена: массив `marks` из четырёх элементов, у последнего номер 3, а цикл берёт и `m[4]` — то, что лежит в памяти за массивом. Там начинается следующий ученик, и сумма получает кусок адреса его имени. Условие должно быть `i < n`.

Числа в чужой памяти от запуска к запуску разные: адреса в Windows меняются при каждом старте программы. Поэтому и неверные средние каждый раз другие — ещё одна примета того, что программа читает не свою память.

! Строка `for` даёт несколько остановок: начало цикла, проверку условия и шаг `i++` компилятор помечает той же строкой. Отладчик не стоит на ней дважды подряд: F10 переходит туда, где начинается другая строка.

## Шаг с заходом и стек вызовов

Чтобы увидеть, как `main` зовёт `average`, поставьте точку на строке 23 — той, где `printf` выводит среднее, — и запустите программу заново (Shift+F5, потом F5). F10 выполнил бы строку целиком, вместе с вызовом. F11 входит внутрь: программа встанет на первую строку `average`, `int sum = 0;`.

Чем F11 отличается от F10 в строке с несколькими вызовами? В строке 23 их два: `average` и `printf`. F11 заходит только в функции самой программы. `printf` — функция библиотеки Си, вшитой в программу, и `strlen`, и функции Windows отладчик проходит целиком: исходник у них есть, но ошибку ищут не в них.

Вкладка «Стек вызовов» показывает цепочку вызовов от текущей функции вниз до `main`:

:= Функция | Место
: average | оценки.c, строка 11
: main | оценки.c, строка 23

Щелчок по строке стека переносит взгляд в ту функцию: редактор показывает строку, на которой она стоит, вкладка «Переменные» — её переменные. Так видно, с какими значениями `main` позвала `average`: `k`, `group`, раскрытые поля учеников. Сама программа при этом остаётся на месте; F10 продолжит с той строки, где стоит жёлтая стрелка.

Shift+F11 выводит из функции: программа досчитает `average` до конца и встанет в `main`, в строке 23, сразу после вызова. Это удобно, когда зашли в функцию и уже видно, что она здесь ни при чём.

## Что показывает вкладка «Переменные»

Вкладка показывает параметры остановленной функции, затем её локальные переменные, уже объявленные к текущей строке, а последней строкой — «Глобальные»: переменные программы вне функций. Переменные, объявленные ниже текущей строки, не показываются: память под них есть, но в ней ещё мусор, и он только сбивал бы с толку.

:= Тип | Как показан | Раскрытие
: числа | 42, -7, 3.14 | нет
: char | 65 'A' | нет
: bool | true или false | нет
: char * | адрес и строка в кавычках, кириллица видна | символ по адресу
: указатель на числа | адрес и первое значение: 0x1BCBCDE01C0 → 5, или NULL | значения по номерам [0], [1]…, по десять
: указатель на структуру | адрес или NULL | поля структуры
: массив | первые элементы в фигурных скобках | все элементы с номерами
: структура | поля в фигурных скобках | все поля, с битовыми полями
: указатель на функцию | адрес и имя функции | нет

Указатель на структуру раскрывается сразу в её поля, её поле-указатель — дальше, так что по списку из узлов можно пройти, раскрывая `next` за `next`. Если указатель смотрит в чужую или освобождённую память, вместо значения будет «не прочитать».

## Когда программа падает

Вторая программа должна печатать длину имени файла, переданного ей в командной строке:

```
#include <stdio.h>
#include <string.h>

static size_t name_length(const char *name)
{
    return strlen(name);
}

int main(int argc, char **argv)
{
    const char *name = argv[1];
    printf("Имя файла: %zu букв\n", name_length(name));
    return 0;
}
```

Запущенная без имени, она молча кончается:

```
> длина
> echo %errorlevel%
-1073741819
```

Код `-1073741819` — это `C0000005`, «обращение к чужой памяти»: процессор поймал обращение к памяти, которой у программы нет, и Windows остановила её. Где именно — код не говорит.

Под отладчиком (F5, без всяких точек останова) программа останавливается в момент сбоя. Во «Выводе» отладчик пишет причину: «Обращение к памяти: чтение по адресу 0x0». Чтение по адресу ноль — почти всегда разыменование указателя `NULL`. Сбой случился внутри `strlen`, у которой нет исходника в программе, поэтому отладчик показывает ближайшую строку самой программы: жёлтая стрелка стоит в `name_length` на `return strlen(name);`, а «Стек вызовов» объясняет путь:

:= Функция | Место
: адрес внутри strlen | без исходника
: name_length | длина.c, строка 6
: main | длина.c, строка 12

Во «Переменных» — `name = NULL`. Дальше дело простое: щелчок по `main` в стеке показывает `argc = 1`, то есть кроме имени самой программы аргументов нет, и `argv[1]` — это `NULL`. Исправление — проверить `argc` до того, как брать `argv[1]`.

После такой остановки программе продолжать нельзя: F5 или Shift+F5 её завершают. Так же отладчик ловит деление на ноль, переполнение стека и недопустимую команду. Исключения, которые программа ловит сама в `__try` (глава 5), отладчик не трогает: он останавливается только там, где программа упала бы.

! Если программа зовёт `__debugbreak()`, отладчик останавливается на этом месте, как на точке останова. Строки, которые программа отдаёт через `OutputDebugStringA`, он печатает во «Вывод».

## Точки останова живут с текстом

Точки останова запоминаются: закройте окно WinCC и откройте снова — кружки останутся на своих строках. Если выше точки вставить или удалить строки, точка переедет вместе со своей строкой, как закладка в тексте.

Если поставить точку на строку, где нет кода — пустую, с комментарием, с одной скобкой, — программа остановится на ближайшей следующей строке, где код есть. Точки можно ставить и снимать, пока программа работает: щелчок по номеру строки действует сразу.

## Отладка оконной программы и проекта

Оконная программа отлаживается так же. Пока программа стоит, её окно не отвечает и не перерисовывается — так и должно быть: остановлен весь её код, в том числе обработка сообщений. Перерисуется, как только программу отпустят.

Консольная программа под отладчиком получает своё окно консоли. Когда она кончается, окно консоли закрывается вместе с ней, а во «Вывод» отладчик пишет код выхода: «Программа завершилась, код 0». Если вывод программы нужно посмотреть, поставьте точку на последней строке `main` или запустите её без отладчика — Ctrl+F5: тогда окно консоли ждёт клавишу.

Проект (глава 3) отлаживается целиком: F5 собирает все его файлы, точки останова можно ставить в любом из них, а F11 заходит из одного файла в функции другого. Отладчик заходит и в функции своих библиотек `.lib` — это тема следующей главы.

## Отладка в «Выпуске»

В «Выпуске» компилятор сам решает, какие переменные держать в регистрах. Отладчик знает и это: файл `.wdbg` говорит, в каком регистре какая переменная, и вкладка показывает её значение. Разница видна в двух местах. Адреса у такой переменной нет, поэтому раскрыть указатель на неё нельзя. И изменение значения может появиться на строку позже или раньше, чем ждёшь: оптимизированный код не обязан выполнять строки по одной. Когда что-то кажется странным, переключите режим в «Отладку» и повторите — там каждая строка честно отдельная.

## Без окна: ключи wcc

Отладчик работает в окне WinCC, но сведения для него делает компилятор, и их можно получить и из командной строки:

```
> wcc оценки.c -g -O0
Готово: оценки.exe — консольная программа, 37376 байт, 156 мс
```

Рядом с `оценки.exe` появится `оценки.wdbg` — текстовый файл со строками, функциями и переменными. Окно WinCC берёт его, когда отлаживает программу. Если пересобрать программу без `-g`, wcc удалит старый `.wdbg`: сведения о другом коде отладчика только запутали бы.

## Итог

Отладка в WinCC — это F9 и F5: точка останова на подозрительной строке, запуск, жёлтая стрелка там, где программа стоит. F10 идёт по строкам, F11 заходит в функции программы, Shift+F11 выходит из них. «Переменные» показывают значения, красным — то, что изменил последний шаг; «Стек вызовов» — кто кого позвал и с чем. Упавшая под отладчиком программа останавливается на своей строке, а не просто исчезает.

Сведения для отладчика компилятор пишет ключом `-g` в файл `.wdbg`, а `-O0` держит переменные в памяти; вместе они составляют режим «Отладка». «Выпуск» отдаёт маленькую быструю программу, и F5 отлаживает и её.
