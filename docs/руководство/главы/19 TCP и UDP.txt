# TCP и UDP
HTTP из прошлой главы — разговор по готовым правилам: вопрос, ответ, соединение закрыто. Но бывает, что две свои программы должны говорить на своём языке: чат, игра по сети, датчик, который шлёт показания, программа, управляющая другой на соседнем компьютере. Для этого есть уровень ниже HTTP — соединения TCP и пакеты UDP. На них построен и сам HTTP, и почти всё прочее в сети. Эта глава показывает оба способа на `net.h`: клиент и сервер TCP, строки и байты, ожидание без зависания, комнату для разговора на много собеседников и поиск соседей в локальной сети рассылкой UDP.

## Звонок и открытки

TCP похож на телефонный звонок. Сначала соединение: одна программа звонит, другая снимает трубку. Дальше обе говорят, и всё сказанное доходит целиком, без пропусков и в том же порядке; если связь рвётся, обе стороны об этом узнают. UDP похож на открытки: каждая уходит сама по себе, соединения нет, одна может потеряться, две — прийти не в том порядке, и отправитель об этом не узнает. Зато открытку можно бросить сразу всем в сети, а звонок всегда один на один.

:= | TCP | UDP
: Соединение | Есть: `net_connect` и `net_accept` | Нет: пакет просто отправляется
: Доставка | Всё и по порядку, или ошибка | Пакет дойдёт или нет, порядок не обещан
: Границы | Поток байт без границ | Каждый пакет приходит целым
: Кому | Одному собеседнику | Одному или всем в сети сразу
: Для чего | Чат, файлы, команды, HTTP | Поиск в сети, датчики, голос, игры

Чтобы найти собеседника, нужны две вещи: адрес компьютера (`192.168.1.7`, `::1` или имя `github.com`, которое превращается в адрес) и порт — число от 1 до 65535, которое отличает одну программу на компьютере от другой. Веб-сервер обычно слушает порт 80 (HTTP) или 443 (HTTPS); свои программы берут номера повыше, например 9000. Имя `localhost` (адрес `127.0.0.1` или `::1`) — это сам компьютер: так удобно проверять клиент и сервер на одной машине, запустив их в двух окнах консоли.

## Клиент: net_connect

`net_connect(адрес, порт)` соединяется с сервером и возвращает `NetSocket *` — указатель на соединение, через который потом идёт весь разговор. Если не вышло, возвращает ноль, а почему — говорит `net_error()`. У имени бывает несколько адресов, IPv4 и IPv6; функция пробует их по очереди, пока какой-нибудь не ответит. На каждую попытку она ждёт не дольше предела `net_set_timeout` (по умолчанию 30 секунд).

Чтобы увидеть, что HTTP — это обычные строки поверх TCP, можно спросить веб-сервер руками:

```
// head: спросить сайт напрямую по TCP — тот же HTTP, только руками
#include <net.h>
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    NetSocket *s = net_connect("github.com", 80);
    if (!s) {
        printf("%s\n", net_error());
        return 1;
    }
    printf("Соединились с %s\n", net_peer(s));
    net_printf(s, "HEAD / HTTP/1.1\r\nHost: %s\r\nConnection: close\r\n\r\n", "github.com");
    char *line;
    while ((line = net_recv_line(s)) != 0 && line[0]) {   // до пустой строки — конца заголовков
        printf("%s\n", line);
        free(line);
    }
    free(line);
    net_close(s);
    return 0;
}
```

```
Соединились с 20.217.135.5:80
HTTP/1.1 301 Moved Permanently
Content-Length: 0
Location: https://github.com/
connection: close
```

`net_printf` отправляет текст, собранный как в `printf`; `net_send_text` — готовую строку; `net_send(s, данные, размер)` — любые байты. Все три отправляют всё до последнего байта или возвращают -1 при ошибке. `net_peer` говорит, кто на том конце, строкой «адрес:порт» (адрес IPv6 — в квадратных скобках). `net_close` закрывает соединение и освобождает `NetSocket`; после неё указатель трогать нельзя.

## Строки и байты

TCP передаёт поток байт, а не сообщения. Если одна программа отправила «привет» и сразу «как дела», другая может получить «приветкак д» одним куском и «ела» вторым — сеть режет поток как ей удобно. Поэтому договор о том, где кончается одно сообщение и начинается другое, — забота самих программ. Самый простой и самый частый договор — строки: каждое сообщение оканчивается переводом строки.

`net_recv_line(s)` читает ровно одну строку, сколько бы кусков для этого ни понадобилось, и возвращает её без `\n` и без `\r` перед ним — значит, понимает и `\n`, и `\r\n`. Строку отдаёт новой, через `malloc`: освобождает её программа. Ноль — собеседник закрыл соединение (или ошибка — тогда `net_error()` не пуста). Если соединение закрылось посреди строки, последний её кусок всё равно придёт.

Для данных, у которых нет строк, — картинок, чисел, файлов — есть два других чтения. `net_recv(s, буфер, размер)` берёт то, что уже пришло, но не больше `размер` байт, и возвращает, сколько взяла; 0 — соединение закрыто, -1 — ошибка. `net_recv_all(s, буфер, размер)` ждёт, пока придёт ровно `размер` байт, и возвращает 1, или 0 — если соединение закрылось раньше. Обычный договор для двоичных данных — сначала длина, потом сами байты:

```
// отправить: длина (4 байта, старший вперёд), потом байты
u_long n = htonl((u_long)size);
net_send(s, &n, 4);
net_send(s, data, size);

// принять: сначала длина, потом ровно столько байт
u_long len;
if (!net_recv_all(s, &len, 4))
    return 0;                       // собеседник ушёл
int size = (int)ntohl(len);
char *data = malloc(size);
if (!net_recv_all(s, data, size)) { free(data); return 0; }
```

`htonl` и `ntohl` переставляют байты числа в «сетевой» порядок и обратно: так число прочтётся одинаково, на каком бы процессоре ни работал собеседник. Чтения разных видов можно мешать в одном соединении: то, что `net_recv_line` прочитала из сети сверх строки, она держит у себя и отдаёт следующему чтению.

## Сервер: net_listen и net_accept

Сервер — это программа, которая ждёт звонков. `net_listen(порт)` открывает порт и возвращает слушающий `NetSocket`; если порт уже занят другой программой, вернёт ноль с ошибкой «Порт 9000 занят». Порт 0 означает «любой свободный» — какой достался, скажет `net_local_port`. Один слушающий сокет принимает и IPv4, и IPv6.

`net_accept(сервер)` спит, пока кто-нибудь не соединится, и возвращает новый `NetSocket` — для разговора именно с этим гостем. Слушающий сокет остаётся слушать дальше. Самый простой сервер возвращает каждую строку обратно:

```
// echo: сервер на порту 9000 — возвращает каждую строку обратно
#include <net.h>
#include <stdio.h>
#include <stdlib.h>

int main(void)
{
    NetSocket *server = net_listen(9000);
    if (!server) {
        printf("%s\n", net_error());
        return 1;
    }
    printf("Жду на порту %d\n", net_local_port(server));
    for (;;) {
        NetSocket *c = net_accept(server);          // спит, пока кто-нибудь не придёт
        if (!c)
            continue;
        printf("Пришёл %s\n", net_peer(c));
        char *line;
        while ((line = net_recv_line(c)) != 0) {    // ноль — гость закрыл соединение
            printf("  %s\n", line);
            net_printf(c, "эхо: %s\n", line);
            free(line);
        }
        printf("Ушёл %s\n", net_peer(c));
        net_close(c);
    }
}
```

Если запустить сервер в одном окне консоли, а в другом — собеседника из раздела о чате ниже (`chat localhost Анна`) и написать пару строк, в окне сервера будет:

```
Жду на порту 9000
Пришёл [::1]:51700
  Анна
  Привет, сервер
  Как слышно?
Ушёл [::1]:51700
```

Первая строка от гостя — его имя: так устроен собеседник для комнаты, и эхо честно вернуло и её.

Этот сервер обслуживает гостей по одному: пока Анна не уйдёт, следующий гость будет ждать в очереди (Windows держит пришедших, пока программа не позовёт `net_accept`). Для эха этого хватает. Чтобы говорить со многими сразу, нужно ждать сразу всех — это следующий раздел, а пока — о том, кому сервер виден.

`net_listen` слушает на всех сетях компьютера, поэтому к серверу могут прийти не только с этого компьютера, но и с соседних. Брандмауэр Windows при первом таком запуске программы спрашивает, разрешить ли ей принимать соединения из сети. Если разрешить, соседи по сети смогут соединиться; если отказать, сервер будет работать для программ на этом же компьютере (`localhost`), а снаружи до него не достучаться.

Если сервер нужен только своему компьютеру — помощник для другой своей программы, служба, которой незачем быть видной соседям, — его открывают через `net_listen_local(порт)`. Она делает всё то же, что `net_listen`, но слушает один адрес `127.0.0.1`, куда можно прийти лишь с этого же компьютера. Из сети такого сервера нет вовсе, и брандмауэр о нём не спрашивает. Слушает он только IPv4, поэтому клиенту проще звать его по адресу `127.0.0.1`; имя `localhost` тоже годится — `net_connect` пробует `::1`, получает отказ и переходит к `127.0.0.1`.

## Ожидание: net_ready и net_socket_timeout

`net_recv_line` и `net_accept` ждут столько, сколько нужно. Иногда так нельзя: программа должна заниматься и другим делом, а в сеть заглядывать между делом. Для этого есть два средства.

`net_ready(s, мс)` ждёт не дольше `мс` миллисекунд и говорит, есть ли что читать: 1 — пришли данные (или собеседник закрыл соединение — тогда чтение вернёт 0), 0 — время вышло впустую. С нулём она не ждёт вовсе, а только смотрит. Учитывает она и то, что `net_recv_line` держит у себя в запасе.

```
for (;;) {
    if (net_ready(s, 100)) {        // заглянуть в сеть на десятую долю секунды
        char *line = net_recv_line(s);
        if (!line)
            break;                  // собеседник ушёл
        printf("%s\n", line);
        free(line);
    }
    do_other_work();                // своё дело между заглядываниями
}
```

`net_socket_timeout(s, мс)` ставит предел самим чтению и отправке: если за это время ничего не пришло, `net_recv` вернёт -1, а `net_recv_line` — ноль, и `net_error()` скажет, что время ожидания истекло. Ноль — снова ждать без конца. Предел удобен против собеседника, который соединился и замолчал, но после него соединение лучше закрыть: Windows не обещает, что сокет, на котором истекло время, годится для дальнейшей работы. Для «подождать и заняться другим» служит `net_ready`.

## Комната для разговора

Чат — хороший пример, потому что в нём сразу видны все трудности сети: гостей много, говорят они когда захотят, а уходят — не прощаясь. Сделаем две программы: комнату (сервер), которая принимает всех и раздаёт каждую строку остальным, и собеседника (клиент), который в одно и то же время читает клавиатуру и показывает, что говорят другие.

Комнате нужно ждать сразу всех: новых гостей на слушающем сокете и строк от каждого из пришедших. Для этого в Windows есть функция `select` из `winsock2.h`: ей дают набор сокетов, и она спит, пока хотя бы в одном не появится, что читать. Сам сокет Windows из `NetSocket` достаёт `net_handle` — так функции библиотеки и функции `winsock2.h` работают вместе.

```
// room: комната для разговора — принимает всех, кто пришёл на порт 9000,
// и каждую строку одного раздаёт всем остальным
#include <net.h>
#include <stdio.h>
#include <stdlib.h>

#define PLACES 32

static NetSocket *guest[PLACES];
static char *name[PLACES];

static void tell_all(int except, const char *text)
{
    for (int i = 0; i < PLACES; i++)
        if (guest[i] && i != except)
            net_send_text(guest[i], text);
}

static void come_in(NetSocket *room)
{
    NetSocket *c = net_accept(room);
    if (!c)
        return;
    int i = 0;
    while (i < PLACES && guest[i])
        i++;
    char *who = i < PLACES ? net_recv_line(c) : 0;     // первая строка гостя — его имя
    if (!who) {
        net_close(c);
        return;
    }
    guest[i] = c;
    name[i] = who;
    printf("Вход: %s, %s\n", who, net_peer(c));
    char text[300];
    snprintf(text, sizeof text, "* %s входит в комнату\n", who);
    tell_all(i, text);
}

static void hear(int i)
{
    do {
        char *line = net_recv_line(guest[i]);
        char text[1200];
        if (!line) {                                    // гость закрыл соединение
            printf("Выход: %s\n", name[i]);
            snprintf(text, sizeof text, "* %s уходит\n", name[i]);
            net_close(guest[i]);
            free(name[i]);
            guest[i] = 0;
            tell_all(-1, text);
            return;
        }
        snprintf(text, sizeof text, "%s: %s\n", name[i], line);
        free(line);
        tell_all(i, text);
    } while (net_ready(guest[i], 0));                   // в запасе ещё строка — тоже раздать
}

int main(void)
{
    NetSocket *room = net_listen(9000);
    if (!room) {
        printf("%s\n", net_error());
        return 1;
    }
    printf("Комната открыта: порт %d\n", net_local_port(room));
    for (;;) {
        fd_set wait;
        FD_ZERO(&wait);
        FD_SET(net_handle(room), &wait);
        for (int i = 0; i < PLACES; i++)
            if (guest[i])
                FD_SET(net_handle(guest[i]), &wait);
        if (select(0, &wait, 0, 0, 0) <= 0)            // спать, пока кто-нибудь не заговорит
            break;
        if (FD_ISSET(net_handle(room), &wait))
            come_in(room);
        for (int i = 0; i < PLACES; i++)
            if (guest[i] && FD_ISSET(net_handle(guest[i]), &wait))
                hear(i);
    }
    return 0;
}
```

Цикл в `main` устроен так: собрать в набор `wait` слушающий сокет и сокеты всех гостей, уснуть в `select` (последний ноль — ждать без предела), а проснувшись, проверить через `FD_ISSET`, кто именно разбудил. Слушающий — значит, пришёл новый гость: `come_in` принимает его и читает первую строку — имя. Сокет гостя — значит, гость что-то сказал или ушёл: `hear` читает строку и раздаёт её остальным, а пустой ответ `net_recv_line` означает, что гость закрыл соединение, и его место освобождается.

Цикл `do … while (net_ready(guest[i], 0))` в `hear` нужен из-за запаса `net_recv_line`. Если гость прислал две строки разом, первая уйдёт сразу, а вторая останется в запасе библиотеки — в самом сокете читать уже нечего, и `select` о ней не напомнит. `net_ready` с нулём видит и запас, поэтому все пришедшие строки разойдутся сразу.

! Набор `fd_set` вмещает 64 сокета — столько задаёт `FD_SETSIZE` в `winsock2.h`. Для комнаты на 32 места этого хватает. Если гостей нужно больше, число задают своим `#define FD_SETSIZE 256` до `#include <net.h>` (или до `winsock2.h`). Другой путь — `WSAPoll` вместо `select`: ей дают массив любой длины (о ней — в главе 21).

Собеседнику нужно делать два дела сразу: ждать строку с клавиатуры и ждать строку из сети. И то и другое — ожидание, которое держит поток, поэтому у собеседника два потока. Главный читает сеть и печатает, второй читает клавиатуру и отправляет:

```
// chat: собеседник для комнаты. chat [адрес] [имя]
#include <net.h>
#include <stdio.h>
#include <stdlib.h>

// второй поток: строки с клавиатуры — в комнату
static DWORD WINAPI keyboard(LPVOID arg)
{
    NetSocket *s = arg;
    HANDLE in = GetStdHandle(STD_INPUT_HANDLE);
    DWORD mode, n;
    int console = GetConsoleMode(in, &mode);
    for (;;) {
        char text[2048];
        int size;
        if (console) {                                  // консоль: строка в UTF-16
            wchar_t w[600];
            if (!ReadConsoleW(in, w, 600, &n, 0) || n == 0)
                break;
            size = WideCharToMultiByte(CP_UTF8, 0, w, (int)n, text, sizeof text, 0, 0);
        } else {                                        // файл или труба: байты как есть
            if (!ReadFile(in, text, sizeof text, &n, 0) || n == 0)
                break;
            size = (int)n;
        }
        if (net_send(s, text, size) < 0)
            break;
    }
    shutdown(net_handle(s), SD_SEND);                   // «я всё сказал» — комната нас отпустит
    return 0;
}

int main(int argc, char **argv)
{
    const char *host = argc > 1 ? argv[1] : "localhost";
    const char *me = argc > 2 ? argv[2] : "Гость";
    NetSocket *s = net_connect(host, 9000);
    if (!s) {
        printf("%s\n", net_error());
        return 1;
    }
    printf("Вы в комнате %s. Пишите и нажимайте Enter.\n", net_peer(s));
    net_printf(s, "%s\n", me);
    CreateThread(0, 0, keyboard, s, 0, 0);
    char *line;
    while ((line = net_recv_line(s)) != 0) {            // всё, что говорят другие
        printf("%s\n", line);
        free(line);
    }
    printf("Соединение закрыто.\n");
    net_close(s);
    return 0;
}
```

Второй поток читает клавиатуру не через `fgets`, а через `ReadConsoleW` самой Windows. Причина — правило библиотеки Си WinCC: её ввод и вывод (`printf`, `fgets`, `FILE`) рассчитаны на один поток, а печатает здесь главный. Функции Windows такого ограничения не имеют. `ReadConsoleW` отдаёт строку в UTF-16 вместе с `\r\n`; `WideCharToMultiByte` превращает её в UTF-8 для сети. Если ввод перенаправлен из файла (`chat localhost Бот < реплики.txt`), консоли нет, и строки читаются `ReadFile` как есть.

Отправлять из одного потока и читать из другого через одно соединение можно: это два независимых направления. Когда ввод кончается (Ctrl+Z и Enter в консоли или конец файла), поток говорит `shutdown(…, SD_SEND)` — «я больше ничего не скажу». Комната видит закрытие, отпускает гостя и закрывает соединение со своей стороны; тогда `net_recv_line` в главном потоке возвращает ноль, и собеседник завершается.

Комната запускается в одном окне консоли, собеседники — в других (`chat localhost Борис`, `chat localhost Анна`). Борис пришёл первым, следом Анна; она поздоровалась, Борис ответил, Анна попрощалась и закрыла ввод. Строки, которые человек набирает сам, консоль показывает по мере набора, а программа их не повторяет, поэтому от программы в окне Анны — только чужие слова:

```
Вы в комнате [::1]:9000. Пишите и нажимайте Enter.
Борис: Борис здесь. Привет, Анна!
Соединение закрыто.
```

В окне Бориса:

```
Вы в комнате [::1]:9000. Пишите и нажимайте Enter.
* Анна входит в комнату
Анна: Привет! Кто здесь?
Анна: Я пошла, пока.
* Анна уходит
Соединение закрыто.
```

А в окне комнаты — кто когда входил и выходил:

```
Комната открыта: порт 9000
Вход: Борис, [::1]:51705
Вход: Анна, [::1]:51706
Выход: Анна
Выход: Борис
```

Оба собеседника соединились по IPv6 (`[::1]` — тот же компьютер), потому что `localhost` в Windows сначала означает `::1`. Чтобы говорить с другого компьютера, вместо `localhost` указывают его адрес или имя в сети, а брандмауэр на компьютере комнаты должен разрешить ей принимать соединения.

## UDP: отдельные пакеты

Для UDP нет ни слушающего сокета, ни `net_accept`: каждый сокет и отправляет, и принимает. `net_udp(порт)` открывает сокет на порту (0 — любой свободный; такой годится, чтобы спрашивать и ждать ответов). `net_udp_send(s, адрес, порт, данные, размер)` отправляет один пакет и возвращает, сколько байт ушло, или -1. `net_udp_recv(s, буфер, размер, от, размер_от)` ждёт один пакет, кладёт его в буфер и возвращает его длину; в строку `от` пишет, кто прислал, — «адрес:порт», по которому можно сразу ответить.

UDP в библиотеке — только IPv4. Пакет приходит целым или не приходит вовсе, и несколько правил стоит помнить сразу:

- Держите пакеты небольшими — до 1400 байт. Больший пакет сеть порежет на части, и потеря любой части губит весь пакет.
- Буфер для приёма должен вмещать самый большой пакет. Если пакет не влез, `net_udp_recv` вернёт -1 с ошибкой 10040, а сам пакет пропадёт.
- Пакет может потеряться: важное повторяют или ждут подтверждения.
- Пакет на порт, где никто не слушает, просто пропадает: отправитель об этом не узнаёт, и следующий `net_udp_recv` того же сокета работает как обычно.
- Чтобы не ждать вечно, у сокета ставят `net_socket_timeout` или спрашивают `net_ready`: тогда `net_udp_recv` после предела вернёт -1 с ошибкой «Ничего не пришло».

## Рассылка: кто ещё в сети

Главное, что умеет UDP и не умеет TCP, — отправить пакет всем сразу. Адрес `255.255.255.255` значит «каждому компьютеру этой сети», и `net_udp` сразу разрешает сокету такую рассылку. Так находят соседей, не зная их адресов: принтеры, медиаплееры, свои программы на других компьютерах. Одна программа кричит «кто здесь?» на всю сеть, остальные отвечают ей лично — на адрес, с которого пришёл крик.

```
// neighbors: кто ещё в сети.
//   neighbors Имя   — отзываться на поиск под этим именем
//   neighbors       — искать: крикнуть всем и собрать ответы
#include <net.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

#define PORT 9001
static const char ASK[] = "КТО ЗДЕСЬ?";

static int answer(const char *me)
{
    NetSocket *u = net_udp(PORT);
    if (!u) {
        printf("%s\n", net_error());
        return 1;
    }
    printf("Отзываюсь на порту %d как «%s»\n", PORT, me);
    for (;;) {
        char packet[100], from[80];
        int n = net_udp_recv(u, packet, sizeof packet - 1, from, sizeof from);
        if (n < 0)
            continue;                       // чужой длинный пакет не влез в буфер — мимо
        packet[n] = 0;
        if (strcmp(packet, ASK) != 0)
            continue;                       // чужой пакет — мимо
        printf("Спрашивает %s\n", from);
        char *colon = strrchr(from, ':');   // "192.168.1.7:50123" — адрес и порт отдельно
        *colon = 0;
        net_udp_send(u, from, atoi(colon + 1), me, (int)strlen(me));
    }
}

static int search(void)
{
    NetSocket *u = net_udp(0);
    if (!u || net_udp_send(u, "255.255.255.255", PORT, ASK, (int)strlen(ASK)) < 0) {
        printf("%s\n", net_error());
        return 1;
    }
    int found = 0;
    while (net_ready(u, 1500)) {            // ждать, пока полторы секунды никто не ответит
        char name[100], from[80];
        int n = net_udp_recv(u, name, sizeof name - 1, from, sizeof from);
        if (n < 0)
            continue;
        name[n] = 0;
        printf("%s — %s\n", name, from);
        found++;
    }
    printf("Найдено: %d\n", found);
    net_close(u);
    return 0;
}

int main(int argc, char **argv)
{
    return argc > 1 ? answer(argv[1]) : search();
}
```

На одном компьютере запущена программа с именем — `neighbors Кухня`. На том же или на соседнем запуск без параметров находит её:

```
Кухня — 192.168.56.1:9001
Найдено: 1
```

А отвечающая программа видит каждый вопрос (поиск запускали дважды):

```
Отзываюсь на порту 9001 как «Кухня»
Спрашивает 192.168.56.1:56503
Спрашивает 192.168.56.1:56504
```

Ожидание ответов устроено через `net_ready(u, 1500)`: пока ответы приходят, цикл крутится, а как только полторы секунды подряд никто ничего не сказал, поиск окончен. Так программа не зависит от того, сколько соседей и как быстро они отвечают.

Отвечающая программа шлёт ответ по адресу, с которого пришёл вопрос, и не знает, ждёт ли там ещё кто-нибудь: ищущий мог закрыться раньше, чем ответ дошёл. Такой ответ просто пропадает — `net_udp` заранее выключает у сокета привычку Windows сообщать о таком пакете ошибкой 10054 при следующем приёме, поэтому цикл спокойно ждёт следующий вопрос. Ошибка приёма здесь — почти всегда чужой пакет длиннее буфера (10040): он не наш, и цикл пропускает его, не бросая работу.

! Общая рассылка `255.255.255.255` уходит только через одну сеть компьютера. Если у него несколько сетевых адаптеров (VirtualBox, VPN, проводная и беспроводная сеть), это может оказаться не та сеть: в выводе выше и вопрос, и ответ пошли через адаптер VirtualBox `192.168.56.1`. Чтобы крикнуть в нужную сеть, используют её собственный адрес рассылки — последнее число адреса 255 при маске 255.255.255.0: для сети `192.168.1.x` это `192.168.1.255`.

Рассылка не выходит за пределы своей сети: маршрутизатор её дальше не пускает. Найти так можно только соседей в той же домашней или офисной сети. И, как и для сервера TCP, брандмауэр должен разрешить отвечающей программе принимать пакеты из сети.

## Итог

TCP — соединение двух программ: клиент зовёт `net_connect`, сервер — `net_listen` (или `net_listen_local`, если его не должно быть видно из сети) и `net_accept`, дальше обе стороны отправляют (`net_send`, `net_send_text`, `net_printf`) и читают (`net_recv_line` для строк, `net_recv` и `net_recv_all` для байт), а `net_close` всё освобождает. Поток TCP не знает границ сообщений, поэтому программы договариваются о них сами — строками или длиной впереди. Ждать без зависания помогают `net_ready` и `net_socket_timeout`, а ждать многих сразу — `select` с сокетами из `net_handle`. UDP — отдельные пакеты без соединения и без обещаний: `net_udp`, `net_udp_send`, `net_udp_recv`, и рассылка всем по `255.255.255.255`, которая находит соседей в сети. Следующая глава строит поверх TCP уже готовую вещь — свой веб-сервер.
