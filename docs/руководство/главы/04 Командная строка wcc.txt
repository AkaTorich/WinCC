# Командная строка wcc
Окно WinCC собирает один файл; всё остальное делает команда `wcc`. Программа из нескольких файлов `.c`, файл на ассемблере, свои макросы и папки заголовков, DLL и программы, которые её зовут, увеличенный стек, сборка в пакетном файле — всё это ключи одной команды. Глава проходит их по порядку, каждый с примером и с тем, что получится на выходе. В конце — коды выхода `wcc`: по ним пакетный файл или другая программа узнают, удалась ли сборка.

## Как устроена команда

Общий вид:

```
wcc файл.c [ещё.c файл.asm ...] [параметры]
```

Всё, что начинается с `-`, — ключ; всё остальное — имя исходного файла. Порядок свободный: ключи можно писать до файлов, после них и вперемешку. Имена с пробелами берут в кавычки, кириллица в именах файлов и папок допустима.

Исходники бывают двух видов. Файл `.c` — текст на Си (так же читается и файл с любым другим расширением, кроме `.asm` и `.s`). Файл `.asm` или `.s` — текст на ассемблере x86-64. Сколько бы файлов ни было названо, получается одна программа.

Ключи `wcc` читает буквально: незнакомый ключ — ошибка, и сборка не начинается.

```
wcc привет.c --fast
wcc: неизвестный параметр --fast (wcc --help)
```

Справку дают `wcc` без параметров, а также `wcc --help`, `wcc -h` и `wcc /?`; номер версии — `wcc --version` или `wcc -v`.

## Самое короткое

```
wcc привет.c
Готово: привет.exe — консольная программа, 65536 байт, 110 мс
```

Строка «Готово» — единственное, что `wcc` печатает при удачной сборке, если в программе нет поводов для предупреждений (о них — в конце главы). В ней имя готового файла, его вид (консольная программа, оконная программа или библиотека DLL), размер в байтах и время сборки. Вид здесь важно читать: если в строке написано «оконная программа», а ожидалась консольная, значит, сработало одно из правил выбора вида, о которых ниже.

Готовый файл ложится туда, где лежит первый исходник, и называется так же, с расширением `.exe` (или `.dll` при ключе `--dll`). Команда `wcc src\main.c` положит `main.exe` в папку `src`, а не в текущую.

## Имя готового файла: -o

Ключ `-o` задаёт имя и, если нужно, папку готового файла:

```
wcc main.c util.c -o "Учёт расходов.exe"
wcc main.c util.c -o сборка\uchet.exe
```

Папка должна существовать: `wcc` её не создаёт. Расширение пишется явно — `-o prog` сделает файл `prog` без расширения, и Windows не станет его запускать двойным щелчком.

## Вид программы: --console, --gui, --dll

Вид программы `wcc` выбирает по правилам, которые проверяются в таком порядке.

1. Ключ `--dll` — получается DLL, что бы ни было в программе.
2. Ключ `--gui` — оконная программа; `--console` — консольная.
3. Если ключа нет, а в программе или в её заголовках есть строка `#pragma comment(linker, "/SUBSYSTEM:WINDOWS")`, — оконная. Эту строку содержит `wui.h`, поэтому программа на WUI становится оконной сама, даже с `main`.
4. Иначе — по функции входа: если есть `WinMain` (или `wWinMain`), но нет `main` (и `wmain`), программа оконная, во всех остальных случаях — консольная.

Разница между видами — в одном поле заголовка exe: оно говорит Windows, нужно ли программе окно консоли. Консольной программе Windows его даёт (или отдаёт ей консоль, из которой её запустили); оконной — нет, и всё, что она печатает через `printf`, никуда не попадает. Функции входа при этом могут быть любые: консольная программа с `WinMain` и оконная с `main` собираются одинаково хорошо. Если в программе есть и `main`, и `WinMain`, консольная начнётся с `main`, оконная — с `WinMain`.

Если функции входа нет совсем, сборка останавливается:

```
wcc stats.c
нет функции main (для окон — WinMain)
```

У DLL функции входа нет; если в ней определена `DllMain`, Windows позовёт её при загрузке и выгрузке библиотеки (глава 10).

## Несколько исходников

Программу больше пары сотен строк удобно делить на файлы: каждый отвечает за своё, а общий заголовок `.h` говорит остальным, что в нём есть. Ниже — маленький журнал оценок из трёх частей: `stats.c` считает среднюю и лучшую оценку, `twice.asm` удваивает число (пример ассемблера), `main.c` всё это зовёт.

Заголовок объявляет функции `stats.c`. Строки `#ifndef` — `#define` — `#endif` защищают его от двойного включения: если заголовок подключат дважды, второй раз он окажется пустым.

```
// файл: stats.h
// Что умеет stats.c: подключают и main.c, и сам stats.c
#ifndef STATS_H
#define STATS_H

double average(const int *v, int n);
int maximum(const int *v, int n);

#endif
```

Сами функции:

```
// файл: stats.c
#include "stats.h"

double average(const int *v, int n)
{
    long long sum = 0;
    for (int i = 0; i < n; i++)
        sum += v[i];
    return n ? (double)sum / n : 0.0;
}

int maximum(const int *v, int n)
{
    int m = v[0];
    for (int i = 1; i < n; i++)
        if (v[i] > m)
            m = v[i];
    return m;
}
```

Функция на ассемблере. По правилам вызова 64-битной Windows первый целый аргумент приходит в регистре `rcx`, второй — в `rdx`, третий и четвёртый — в `r8` и `r9`, а ответ функция оставляет в `rax`. Метка `twice:` — имя функции, его видит Си. Комментарии в файле `.asm` начинаются с `;` или `//`.

```
// файл: twice.asm
; long long twice(long long x): x приходит в rcx, ответ уходит в rax
twice:
    lea rax, [rcx+rcx]
    ret
```

И главная часть. Функцию из `twice.asm` Си знать неоткуда, поэтому её объявление написано прямо здесь:

```
// файл: main.c
// сборка: wcc main.c stats.c twice.asm -o journal.exe
#include <stdio.h>
#include "stats.h"

long long twice(long long x);       // из twice.asm

int main(void)
{
    int marks[] = { 4, 5, 3, 5, 4, 5 };
    int n = sizeof marks / sizeof marks[0];
    printf("Оценок: %d\n", n);
    printf("Средняя: %.2f\n", average(marks, n));
    printf("Лучшая: %d\n", maximum(marks, n));
    printf("Вдвое: %lld\n", twice(maximum(marks, n)));
    return 0;
}
```

Сборка и запуск:

```
wcc main.c stats.c twice.asm -o journal.exe
Готово: journal.exe — консольная программа, 67584 байт, 125 мс

journal
Оценок: 6
Средняя: 4.33
Лучшая: 5
Вдвое: 10
```

Несколько правил, которые видны на этом примере.

Заголовки `.h` в командную строку не пишут: их подставляет `#include`. В команде — только `.c` и `.asm`.

Каждый файл `.c` проходит препроцессор отдельно, начиная с чистого листа: макрос, определённый в `main.c`, в `stats.c` не виден, а `stats.h` подключается в каждый файл заново. Поэтому общее — типы, объявления, макросы — держат в заголовках.

Если какой-то файл забыт, `wcc` не найдёт его функций и перечислит их все сразу:

```
wcc main.c -o journal.exe
функции объявлены, но не написаны — average, maximum, twice: их нет ни в программе, ни в библиотеках Windows (своя DLL — ключ -l имя или #pragma comment(lib, "имя"))
```

Подсказка про `-l` в скобках относится к функциям из DLL; здесь же функции свои, и лекарство — добавить в команду `stats.c` и `twice.asm`.

Имена функций и глобальных переменных общие для всей программы: две функции `maximum` в разных файлах — ошибка. Функция, которая нужна только внутри своего файла, объявляется со словом `static` — тогда в другом файле можно завести свою с тем же именем.

Ассемблер подробно разобран в главе 8: там же — вставки `asm("…")` прямо в функцию на Си и команды x87.

## Где искать заголовки: -I

Строка `#include "stats.h"` ищет файл сначала рядом с тем файлом, в котором она написана; поэтому в примере выше `wcc` нашёл `stats.h` без подсказок. Если заголовки лежат в своей папке — например, общие для нескольких программ, — её называют ключом `-I`:

```
wcc main.c stats.c twice.asm -I общие -o journal.exe
```

Без `-I` сборка остановилась бы на первом `#include`:

```
main.c:4: нет файла stats.h
```

Ключей `-I` может быть несколько (до тридцати); папку можно писать и слитно — `-Iобщие`. Полный порядок поиска такой.

:= Как написано | Где ищется, по порядку
: `#include "имя.h"` | рядом с файлом, который подключает; среди стандартных заголовков Си, встроенных в `wcc`; в текущей папке; в папках `-I` в порядке их записи; в папке `include\` WinCC
: `#include <имя.h>` | среди стандартных заголовков Си, встроенных в `wcc`; в папках `-I` в порядке их записи; в папке `include\` WinCC; в текущей папке — последней

Текущая папка для `<имя.h>` стоит в конце нарочно: свой файл `windows.h`, случайно оказавшийся в папке, откуда запущена сборка, не подменит системный заголовок.

Стандартные заголовки (`stdio.h`, `stdlib.h`, `string.h`, `math.h` и другие из стандарта Си) встроены в сам `wcc`, а заголовки Windows и библиотек (`windows.h`, `wui.h`, `net.h`) лежат в папке `include\`. Переменную окружения `INCLUDE`, которую читают компиляторы Microsoft, `wcc` не смотрит.

## Макросы снаружи: -D

Ключ `-D` определяет макрос так, будто в начале каждого файла `.c` стоит `#define`. Так одну и ту же программу собирают в разных вариантах, не трогая текст:

```
// файл: defs.c
// сборка: wcc defs.c -D DEBUG=2 -D VERSION=3 -o defs.exe
#include <stdio.h>

#ifndef VERSION
#define VERSION 1
#endif

int main(void)
{
#ifdef DEBUG
    printf("Отладка, уровень %d\n", DEBUG);
#endif
    printf("Версия %d\n", VERSION);
    return 0;
}
```

Три сборки — три разные программы:

```
wcc defs.c -o defs.exe
defs
Версия 1

wcc defs.c -D DEBUG=2 -D VERSION=3 -o defs.exe
defs
Отладка, уровень 2
Версия 3

wcc defs.c -DDEBUG -o defs.exe
defs
Отладка, уровень 1
Версия 1
```

Запись `-D ИМЯ` без значения определяет макрос, равный 1. Ключ можно писать слитно (`-DDEBUG`) и раздельно (`-D DEBUG`). Значение со строкой в кавычках командная строка Windows разбирает по своим правилам, поэтому строковые значения надёжнее держать в самой программе, а снаружи передавать числа и имена. Всего можно задать до шестидесяти четырёх макросов.

Без всяких `-D` всегда определены `_WIN32`, `_WIN64`, `__WINCC__`, `__x86_64__` и `__STDC__` (все равны 1), `_M_X64` и `_M_AMD64` (равны 100) и `__STDC_VERSION__` (`199901L`).

## DLL: --dll и -l

Ключ `--dll` делает из исходников библиотеку DLL. Наружу она отдаёт функции, помеченные `__declspec(dllexport)`, а если таких нет — все свои функции, которые не `static`. Программа, которая зовёт функции своей DLL, собирается с ключом `-l` и именем этой DLL:

```
wcc --dll mathlib.c
Готово: mathlib.dll — библиотека DLL, 56832 байт, 156 мс

wcc usemath.c -l mathlib
Готово: usemath.exe — консольная программа, 66560 байт, 109 мс
```

Ключ `-l` говорит: «функции, которых нет в программе, ищи и в этой DLL». Имя пишется без расширения (`mathlib`), с ним (`mathlib.dll`) или даже как имя библиотеки Microsoft (`mathlib.lib`) — `wcc` в любом случае возьмёт `mathlib.dll`. Своя DLL ищется в папке первого исходника и в папке готового файла, системная — в `System32`. Ключей `-l` может быть сколько угодно.

Для DLL самой Windows `-l` нужен редко: десять самых ходовых (`kernel32`, `user32`, `gdi32` и другие, список в главе 1) просматриваются всегда, а заголовки WinCC для остальных сами содержат `#pragma comment(lib, "…")`. Если названная DLL не нашлась, `wcc` скажет об этом только при неудачной сборке, строкой «wcc: не найдены библиотеки: …». Свои DLL подробно — в главе 10, функции любых DLL Windows — в главе 11.

## Ассемблерный текст: -S

Ключ `-S` сохраняет рядом с готовым файлом текст на ассемблере, из которого он собран, — `journal.s` для `journal.exe`:

```
wcc main.c stats.c twice.asm -S -o journal.exe
```

В этом файле вся программа так, как её увидел ассемблер: функции программы, файлы `.asm`, а следом — та часть библиотеки Си, которая в программу попала. Даже у маленькой программы он большой — у журнала оценок около двадцати тысяч строк, почти все из библиотеки. Свою функцию в нём находят поиском по имени с двоеточием, например `maximum:`. Перед командами стоят строки `.loc 0 14` — номер строки исходника, из которой получены команды ниже.

`-S` нужен в двух случаях. Первый — понять, во что компилятор превратил строку Си: это хороший способ учить ассемблер. Второй — найти ошибку ассемблера в файле `.asm` или во вставке вне функций. Такая ошибка приходит без файла исходника — `ассемблер, строка 8709 текста (wcc -S сохранит его в .s): …` — и номер в ней указывает строку именно этого текста; файл `.s` пишется и при неудачной сборке, и по номеру строки в нём сразу видно, что виновато (приложение Б). Ошибка во вставке `asm("…")` внутри функции на Си в `-S` не нуждается: она приходит обычной строкой `файл:строка: ассемблер: …` с номером строки исходника.

## Размер стека: --stack

Стек — память, в которой лежат локальные переменные и адреса возврата вызванных функций. У главного потока программы WinCC он по умолчанию 8 мегабайт; это много для обычной программы, но мало для глубокой рекурсии или для большого локального массива. Когда стек кончается, программа останавливается с сообщением о переполнении стека. Пример — рекурсия, где каждый вызов держит в стеке килобайт:

```
#include <stdio.h>
#include <string.h>

// Глубина рекурсии: каждый вызов держит в стеке 1 КБ
static int depth(int n)
{
    char frame[1024];
    memset(frame, n & 0xFF, sizeof frame);
    if (n == 0)
        return frame[0];
    return depth(n - 1) + (frame[10] & 1);
}

int main(void)
{
    int n = 20000;                      // около 20 МБ стека
    printf("Рекурсия глубиной %d...\n", n);
    printf("Готово: %d\n", depth(n));
    return 0;
}
```

С обычным стеком программа печатает первую строку, а следом — сообщение библиотеки WinCC:

```
deep
Рекурсия глубиной 20000...

программа остановлена: переполнение стека (слишком глубокая рекурсия или слишком большой массив внутри функции; больше стека даёт ключ wcc --stack МБ)
```

Код её выхода — `-1073741571`, он же `C00000FD`, «переполнение стека». С ключом `--stack 32` (размер в мегабайтах) она доходит до конца:

```
wcc deep.c --stack 32
Готово: deep.exe — консольная программа, 66560 байт, 109 мс

deep
Рекурсия глубиной 20000...
Готово: 10000
```

Размер записывается в заголовок exe; память под стек Windows отводит постепенно, по мере надобности, так что большой стек не делает программу тяжелее. Но лучшее лекарство от переполнения обычно другое: большие массивы заводить через `malloc`, а не локальными переменными. Ключ касается только главного потока; размер стека других потоков задаётся при их создании.

## Собрать и запустить: --run

Ключ `--run` после удачной сборки сразу запускает программу в той же консоли и ждёт её окончания. Программа запускается по полному пути к готовому файлу, поэтому её находят при любых настройках поиска программ в Windows:

```
wcc deep.c --stack 32 --run
Готово: deep.exe — консольная программа, 66560 байт, 109 мс
Рекурсия глубиной 20000...
Готово: 10000
```

Код выхода `wcc` в этом случае — код выхода самой программы. Аргументы программе передать нельзя: всё, что написано в строке, относится к `wcc`. DLL при `--run` только собирается. Оконная программа запускается, и `wcc` ждёт, пока её закроют.

## Код выхода

Как и любая программа, `wcc` сообщает итог числом — кодом выхода. Его видят пакетные файлы (`%errorlevel%`), PowerShell (`$LASTEXITCODE`) и программы, которые зовут `wcc`.

:= Код | Что значит
: 0 | сборка удалась, даже если были предупреждения (или напечатана справка, версия)
: 1 | ошибка в программе: сообщение компилятора, нет функции, нельзя записать готовый файл, не запустилась программа при `--run`
: 2 | ошибка в команде: нет исходников, нет такого файла, неизвестный ключ, не найдена библиотека `runtime\`
: 3 | компилятору не хватило памяти
: любой | при `--run` — код выхода самой программы

Все сообщения `wcc` пишет в поток ошибок, а строку «Готово» — в обычный вывод; так её легко отделить. Ошибка всегда одна: `wcc` останавливается на первой. Предупреждений (`файл:строка: предупреждение: текст`) может быть несколько; они идут в тот же поток ошибок, сборку не останавливают и кода выхода не меняют.

## Сборка пакетным файлом

Когда команда сборки длинная или программ несколько, её записывают в пакетный файл рядом с исходниками — `build.cmd`. Двойной щелчок по нему собирает всё заново, а строка `|| goto fail` прекращает сборку на первой ошибке:

```
@echo off
rem Сборка журнала оценок и библиотеки к нему
cd /d "%~dp0"
wcc --dll mathlib.c || goto fail
wcc main.c stats.c twice.asm -l mathlib -o journal.exe || goto fail
echo Всё собрано.
pause
exit /b 0
:fail
echo Сборка остановлена.
pause
exit /b 1
```

Строка `cd /d "%~dp0"` переходит в папку, где лежит сам пакетный файл, — иначе при запуске двойным щелчком текущей была бы другая папка, и `wcc` не нашёл бы исходников. Если в пакетном файле есть русские буквы, его стоит сохранять в UTF-8 без BOM и первой командой после `@echo off` поставить `chcp 65001 >nul`, иначе `cmd` прочтёт кириллицу в своей кодировке.

## Итог

Команда `wcc` принимает любое число файлов `.c` и `.asm` и собирает из них одну программу; заголовки в команду не пишут. Вид программы задают `--console`, `--gui` и `--dll`, а без ключа его выбирает `#pragma comment(linker, …)` или функция входа. `-o` задаёт имя готового файла, `-I` — папки заголовков, `-D` — макросы, `-l` — DLL, из которых брать функции, `--stack` — стек главного потока, `-S` сохраняет ассемблерный текст, `--run` запускает собранное. Удачная сборка печатает строку «Готово» (и перед ней — предупреждения, если они есть), неудачная — одно сообщение об ошибке; код выхода 0, 1 или 2 позволяет пакетному файлу остановиться на ошибке. Полная таблица ключей — в приложении А.
