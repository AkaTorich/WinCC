# Приложение А. Ключи wcc и переменные окружения
Справочник по командной строке трёх программ WinCC — компилятора `wcc.exe`, окна `WinCC.exe` и установщика `WinCCSetup.exe` — и по переменным окружения, которые читают программы на WUI. Объяснения и примеры — в главах 2, 3 и 4.

## wcc.exe: вызов

```
wcc файл.c [ещё.c файл.asm ...] [параметры]
```

Ключи и имена файлов идут в любом порядке. Всё, что начинается с `-`, считается ключом; остальное — именами исходников. Незнакомый ключ останавливает работу с кодом выхода 2.

## wcc.exe: ключи

:= Ключ | Что делает | Замечания
: `-o имя` | имя готового файла, можно с папкой | без ключа — имя первого исходника с `.exe` или `.dll`, в его папке; папка должна существовать; расширение не добавляется само
: `--console` | консольная программа | так по умолчанию; отменяет `#pragma comment(linker, "/SUBSYSTEM:WINDOWS")`
: `--gui` | оконная программа, без консоли | без ключа так же выходит, если есть `WinMain` или `wWinMain` и нет `main` и `wmain`
: `--dll` | библиотека DLL | экспорт — функции с `__declspec(dllexport)`, а если их нет — все определённые функции; `--run` при нём не запускает
: `--lib` | своя библиотека `.lib` (глава 23) | все исходники команды после препроцессора в одном файле; без `-o` — имя первого исходника с `.lib`
: `-l имя`, `-lимя` | брать функции и из этой DLL | имя с `.dll`, с `.lib` или без расширения; ищется в папке первого исходника, в папке готового файла, затем в `System32`; с путём (`-l ..\mylib\mylib`) берётся этот файл, а в программу пишется только имя; ключ можно повторять до 128 раз
: `-I папка`, `-Iпапка` | ещё одна папка для `#include` | до 30 папок; просматриваются в порядке записи, до `include\` WinCC; для `"имя"` — после текущей папки, для `<имя>` — до неё
: `-D ИМЯ`, `-D ИМЯ=знач` | определить макрос во всех файлах `.c` | без значения макрос равен 1; можно слитно (`-DИМЯ`); до 64 макросов
: `-S` | сохранить ассемблерный текст | файл `.s` рядом с готовым файлом, с его именем; пишется и при неудачной сборке
: `-g` | сведения для отладчика WinCC | файл `.wdbg` рядом с готовым файлом, с его именем; без ключа старый `.wdbg` удаляется (глава 22)
: `-O0` | без раскладки переменных по регистрам | все переменные в памяти, отладчик видит каждую; `-O`, `-O1`, `-O2` возвращают обычную сборку
: `--manifest` | вложить в `.exe` манифест WinCC | кодовая страница программы — UTF-8 (A-функции Windows понимают кириллицу), Common Controls 6, права «как у запустившего», Windows 10 и 11; без ключа и без `#pragma comment(linker, "/MANIFEST")` манифеста нет; свой манифест из `.rc` заменяет этот (глава 7)
: `--stack МБ` | размер стека главного потока, в мегабайтах | по умолчанию 8; целое число
: `--run` | после удачной сборки запустить программу и дождаться её | программа запускается по полному пути; код выхода `wcc` — код выхода программы; аргументы программе не передаются
: `-h`, `--help`, `/?` | краткая справка | код выхода 0; без параметров — та же справка с кодом 2
: `-v`, `--version` | номер версии | печатает `WinCC 1.5.0`

## wcc.exe: исходные файлы

:= Расширение | Как читается
: `.asm`, `.s` | текст на ассемблере x86-64, синтаксис Intel; комментарии `;` и `//`
: `.lib` | своя библиотека WinCC (`wcc --lib`); из неё в программу идёт только то, что программа зовёт
: `.rc`, `.res` | ресурсы: значок, меню, диалоги, строки; `.rc` — текст, `.res` — уже собранный файл
: любое другое (обычно `.c`) | текст на Си; каждый файл проходит препроцессор отдельно

Файлы читаются как UTF-8; метка BOM в начале допустима и пропускается. Файл в UTF-16 с меткой BOM и файл в Windows-1251 (не UTF-8) `wcc` узнаёт сам и перед разбором переводит в UTF-8. Всего — до 500 файлов в одной команде. Заголовки `.h` в команду не пишут.

## wcc.exe: вид программы

Проверяется по порядку, первое совпадение решает.

:= Условие | Вид
: ключ `--dll` | DLL
: ключ `--gui` или `--console` | оконная или консольная
: `#pragma comment(linker, "/SUBSYSTEM:WINDOWS")` (или `"/SUBSYSTEM:CONSOLE"`) в программе или её заголовках; `wui.h` содержит первую | оконная или консольная
: есть `WinMain` или `wWinMain`, нет `main` и `wmain` | оконная
: всё остальное | консольная

Функция входа консольной программы ищется в порядке `main`, `wmain`, `WinMain`, `wWinMain`; оконной — `WinMain`, `wWinMain`, `main`, `wmain`. В DLL входа нет; необязательная `DllMain` вызывается при загрузке и выгрузке.

## wcc.exe: поиск заголовков

:= Запись | Порядок поиска
: `#include "имя"` | рядом с подключающим файлом; встроенные стандартные заголовки; текущая папка; папки `-I`; `include\` WinCC
: `#include <имя>` | встроенные стандартные заголовки; папки `-I`; `include\` WinCC; текущая папка

Встроены в `wcc.exe` 25 стандартных заголовков: `assert.h`, `ctype.h`, `errno.h`, `float.h`, `inttypes.h`, `iso646.h`, `limits.h`, `locale.h`, `math.h`, `setjmp.h`, `signal.h`, `stdalign.h`, `stdarg.h`, `stdbool.h`, `stddef.h`, `stdint.h`, `stdio.h`, `stdlib.h`, `stdnoreturn.h`, `string.h`, `strings.h`, `time.h`, `uchar.h`, `wchar.h`, `wctype.h`. Глубина вложенных `#include` — до 32.

## wcc.exe: поиск DLL

Для каждого имени, которое программа зовёт, но не определяет, `wcc` ищет DLL, в таблице экспорта которой это имя есть. DLL просматриваются в таком порядке: названные ключами `-l`; названные строками `#pragma comment(lib, "имя")`, если рядом с `wcc.exe` нет папки `lib\имя`; затем всегда `kernel32`, `user32`, `gdi32`, `comdlg32`, `shell32`, `advapi32`, `comctl32`, `ole32`, `winmm`, `ws2_32`. Побеждает первая DLL, у которой имя нашлось. Сам файл DLL ищется в папке первого исходника, в папке готового файла и в `System32`.

Строка `#pragma comment(lib, "имя")` при наличии папки `lib\имя` рядом с `wcc.exe` подключает не DLL, а исходники: все файлы `.c` этой папки собираются вместе с программой, лишнее выбрасывается. Так подключаются `lib\wui` (из `wui.h`), `lib\net` (из `net.h`) и `lib\elements` (из `elements.h`). Ключ `-l` такие папки не подключает.

## wcc.exe: предопределённые макросы

:= Макрос | Значение
: `_WIN32`, `_WIN64` | 1
: `__WINCC__` | 1
: `_M_X64`, `_M_AMD64` | 100
: `__x86_64__` | 1
: `__STDC__` | 1
: `__STDC_VERSION__` | `201112L` (C11)
: `__STDC_NO_COMPLEX__` | 1 — языкового `_Complex` нет; `complex.h` в стиле Microsoft
: `__FILE__`, `__LINE__` | имя файла и номер строки; раскрываются и внутри аргумента макроса; `#line N "файл"` меняет счёт
: `__DATE__`, `__TIME__` | дата и время сборки строкой: `"Nov  4 2026"`, `"03:23:41"`
: `__COUNTER__` | 0, 1, 2… — при каждом раскрытии на единицу больше
: `NULL` | `((void*)0)`
: `bool`, `true`, `false` | `_Bool`, 1, 0 — без `stdbool.h`

Внутри функции имена `__func__` и `__FUNCTION__` дают её имя строкой; это не макросы, а имена, которые знает сам язык.

Слова Microsoft `__stdcall`, `__cdecl`, `__fastcall`, `__thiscall`, `__vectorcall`, `__w64`, `__ptr64`, `__ptr32`, `__unaligned`, `__restrict` определены пустыми (в 64-битной Windows соглашение о вызовах одно). `__inline` и `__forceinline` означают `inline`; `__int8`, `__int16`, `__int32`, `__int64` — `char`, `short`, `int`, `long long`.

## wcc.exe: вывод и коды выхода

Удачная сборка печатает в обычный вывод одну строку:

```
Готово: имя — вид, N байт, M мс
```

где вид — «консольная программа», «оконная программа», «библиотека DLL» или «библиотека WinCC» (у неё перед размером ещё число файлов: `файлов 1, 4797 байт`). Сообщения об ошибках идут в поток ошибок, по одному за запуск. Предупреждения (`файл:строка: предупреждение: текст`) идут туда же, их может быть несколько; сборку они не останавливают и кода выхода не меняют.

:= Код | Когда
: 0 | сборка удалась, в том числе с предупреждениями; напечатана справка (`--help`) или версия
: 1 | ошибка компиляции, сборки или импорта; нельзя записать готовый файл; при `--run` программа не запустилась
: 2 | нет исходников; нет такого файла; неизвестный ключ; больше 500 файлов; не найдена папка `runtime\` или файл библиотеки в ней
: 3 | не хватило памяти
: код программы | при `--run` после удачной сборки

## WinCC.exe

```
WinCC.exe [файл ...] [проект.wccproj]
WinCC.exe --window снимок.png [ШxВ] [lang:en|ru] [empty] [project:файл.wccproj] [debug:файл.c:строка]
```

:= Вызов | Что делает
: без параметров | открывает окно, проект и файлы прошлого раза; если их нет — новый файл с заготовкой
: `WinCC.exe файл.c ...` | то же, и открывает названные файлы каждый во вкладке; файл `.wccproj` открывается как проект
: `--window снимок.png` | снимок окна в файл PNG без показа на экране; в окне — образец кода, вывода и ошибок; ничего не запоминает; программа выходит
: `ШxВ` (при `--window`) | размер окна в точках, через латинскую `x`, например `1100x700`; по умолчанию `1280x820`
: `lang:en`, `lang:ru` (при `--window`) | язык окна; без него — язык Windows
: `empty` (при `--window`) | окно без открытых файлов
: `project:файл` (при `--window`) | окно с открытым проектом
: `debug:файл.c:строка` (при `--window`) | собрать файл под отладчиком, остановиться на строке и снять окно с переменными

Ключ `--window` должен стоять первым. Настройки окна — в файле `%APPDATA%\WinCC\settings.txt`: язык, вид программы и режим сборки, открытые файлы и передняя вкладка, проект и недавние проекты, размеры панелей, точки останова.

## WinCCSetup.exe

:= Вызов | Что делает
: без параметров | окно установки; если WinCC уже стоит — обновление
: `/silent` | установка без окна, в папку по умолчанию, с переключателями по умолчанию: ярлыки, `PATH`, «Открыть с помощью»; WinCC после установки не запускается
: `/silent /dir="папка"` | то же в указанную папку
: `/uninstall` | окно установщика сразу спрашивает, удалить ли WinCC
: `/uninstall /silent` | удаление без вопросов; уходят только файлы из поставки WinCC и собранные `.exe` примеров, свои файлы в папке остаются
: `/drytest` | распаковывает содержимое во временную папку, печатает, что внутри и сколько файлов, и стирает её; в системе ничего не меняет
: `--снимок=файл.png` | снимок окна установщика в PNG; ничего не ставит
: `--страница=ход` или `--страница=готово` (при `--снимок`) | снимок страницы хода установки или её конца

Ключи `/silent` и `/uninstall` можно писать и через дефис (`-silent`, `-uninstall`), регистр букв не важен. Папка по умолчанию — `%LOCALAPPDATA%\Programs\WinCC`. При ошибке тихой установки или удаления установщик пишет в консоль строку «Ошибка: …» и выходит с кодом 1. Установщик и удаление работают с частью реестра текущего пользователя: `HKCU\Environment` (переменная `Path`), `HKCU\Software\Classes` (пункт «Открыть с помощью» для `.c` и `.h`), `HKCU\Software\Microsoft\Windows\CurrentVersion\Uninstall\WinCC` (запись программы).

## Переменные окружения: компилятор

Компилятор `wcc` не читает переменных окружения: ни `INCLUDE`, ни `LIB`, ни своих. Всё, что ему нужно, он находит относительно своего файла — папки `runtime\`, `include\` и `lib\` рядом с `wcc.exe`. Ключ `--run` запускает готовую программу по полному пути, поэтому переменные Windows, которые меняют поиск программ (например, `NoDefaultCurrentDirectoryInExePath`), на него не влияют.

## Переменные окружения: программы на WUI

Библиотека WUI читает пять переменных. Они нужны для проверки вида окон без экрана и мыши — для снимков в документацию и для автоматических проверок; обычной работе программы они не мешают, пока не заданы.

:= Переменная | Значение | Что делает
: `WUI_SNAPSHOT` | путь к файлу `.png` | первое окно программы не показывается на экране, а после первой отрисовки сохраняется в этот файл, после чего `wui_run` возвращает 0 и программа завершается
: `WUI_SNAPSHOT_WAIT` | любое непустое значение | вместе с `WUI_SNAPSHOT`: окно показывается и работает как обычно, а снимок `файл-N.png` делается по сообщению окну `WM_APP+3` с номером N в `wParam`
: `WUI_THEME` | Id темы, например `Emerald` | тема первого окна вместо запомненной; регистр не важен; незнакомый Id не замечается
: `WUI_SIZE` | `ширина,высота` | размер содержимого первого окна в точках (без тени), оба числа больше нуля; окно не бывает больше рабочей области экрана
: `WUI_SCALE` | число больше 0,5, например `2` или `2.25` | масштаб экрана для первого окна: при 2 снимок вдвое чётче

`WUI_THEME`, `WUI_SIZE` и `WUI_SCALE` действуют только на первое созданное окно. Размер окна в пикселях — `WUI_SIZE`, умноженный на `WUI_SCALE`, плюс поля тени; если это больше рабочей области монитора, окно обрезается до неё, поэтому при масштабе 2 на экране 1920 на 1080 точек размер не стоит задавать больше примерно 940 на 500.

Пример — снимок окна программы в теме «Изумруд и золото» для печати:

```
set WUI_SNAPSHOT=рисунки\окно.png
set WUI_THEME=Emerald
set WUI_SIZE=900,500
set WUI_SCALE=2
программа.exe
```

В PowerShell те же переменные задаются так: `$env:WUI_SNAPSHOT = "рисунки\окно.png"`. Чтобы следующий запуск программы был обычным, переменные снимают: `set WUI_SNAPSHOT=` в `cmd` или `Remove-Item Env:\WUI_SNAPSHOT` в PowerShell.

Выбор темы пользователем программа на WUI хранит в `%APPDATA%\ThemeLibrary\<ключ>.theme`, где ключ — четвёртый параметр `wui_window`; если ключ пустой, тема не запоминается (глава 13).
