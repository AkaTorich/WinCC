# Свои библиотеки .lib
Когда одни и те же функции нужны в нескольких программах, их выносят в библиотеку. В главе 10 такой библиотекой была DLL — отдельный файл, который программа загружает при запуске. У WinCC есть и второй путь: своя библиотека `.lib`, функции которой вшиваются внутрь каждой программы, как библиотека Си. Эта глава показывает, как сделать такую библиотеку командой и в окне WinCC, как программа её подключает, что лежит внутри файла `.lib` и чем этот путь отличается от DLL.

## DLL или .lib

Обе библиотеки пишутся на Си, как обычная программа, только без `main`. Разница в том, где окажется их код.

:= | DLL | Своя библиотека .lib
: Где код | в отдельном файле `.dll`, программа загружает его при запуске | внутри каждой программы, которая её берёт
: Что нужно при запуске | `.dll` рядом с `.exe` | ничего, программа самостоятельна
: Что попадает в программу | ничего, только имена функций | только те функции, которые программа вызывает
: Обновить библиотеку | заменить `.dll`, программы пересобирать не нужно | пересобрать библиотеку и программы
: Сборка | `wcc --dll` | `wcc --lib`
: Подключение | `-l имя` или `-l путь\имя` | файл `.lib` в команде сборки

DLL выбирают, когда библиотеку меняют отдельно от программ или когда её зовёт программа на другом языке. Своя `.lib` удобнее, когда функции просто общие для нескольких своих программ: программа остаётся одним файлом, а из библиотеки в неё попадает только то, что она зовёт, — так же, как из библиотеки Си попадает только `printf`, если программа больше ничего не просит.

! `.lib` WinCC — свой формат, не тот, что у Visual Studio. Библиотеки `.lib`, собранные Visual Studio, WinCC не читает, а его `.lib` не поймёт Visual Studio.

## Библиотека из командной строки

Библиотека `geom` считает расстояния, периметры и площади многоугольников. У неё два файла: заголовок с объявлениями, который подключат программы, и сам код.

```
// файл: geom.h
// Библиотека geom: фигуры на плоскости. Этот заголовок подключает и сама библиотека, и программа.
#pragma once

typedef struct { double x, y; } Point;

double geom_distance(Point a, Point b);
double geom_polygon_area(const Point *p, int n);
double geom_perimeter(const Point *p, int n);
int geom_calls(void);
```

```
// файл: geom.c
// сборка: wcc --lib geom.c -o geom.lib
#include <math.h>
#include "geom.h"

static int g_calls;                 // своя переменная библиотеки, снаружи не видна

static double cross(Point a, Point b)
{
    return a.x * b.y - a.y * b.x;
}

double geom_distance(Point a, Point b)
{
    g_calls++;
    return sqrt((b.x - a.x) * (b.x - a.x) + (b.y - a.y) * (b.y - a.y));
}

double geom_polygon_area(const Point *p, int n)
{
    double s = 0;
    g_calls++;
    for (int i = 0; i < n; i++)
        s += cross(p[i], p[(i + 1) % n]);
    return fabs(s) / 2;
}

double geom_perimeter(const Point *p, int n)
{
    double s = 0;
    for (int i = 0; i < n; i++)
        s += geom_distance(p[i], p[(i + 1) % n]);
    return s;
}

int geom_calls(void)
{
    return g_calls;
}
```

Ключ `--lib` говорит wcc, что нужна библиотека. Файлов может быть сколько угодно — все `.c` и `.asm` библиотеки перечисляются в одной команде. Имя по умолчанию — имя первого исходника с расширением `.lib`.

```
> wcc --lib geom.c -o geom.lib
Готово: geom.lib — библиотека WinCC, файлов 1, 4797 байт, 0 мс
```

Снаружи видны все функции библиотеки, кроме `static`: `cross` и `g_calls` — внутреннее дело `geom`, программа не может ни позвать `cross`, ни испортить счётчик. Помечать функции `__declspec(dllexport)` не нужно: это слово для DLL.

При сборке библиотека компилируется целиком, как программа: синтаксическая ошибка, неизвестная функция, неверный тип — всё всплывёт здесь, а не в программах, которые её потом возьмут.

## Программа с библиотекой

Программе нужен заголовок библиотеки — ради объявлений — и сам файл `.lib` в команде сборки:

```
// файл: участок.c
// сборка: wcc участок.c geom.lib
#include <stdio.h>
#include "geom.h"

int main(void)
{
    Point plot[] = { { 0, 0 }, { 40, 0 }, { 40, 25 }, { 10, 30 } };
    int n = sizeof(plot) / sizeof(plot[0]);
    printf("Площадь участка: %.1f кв. м\n", geom_polygon_area(plot, n));
    printf("Забор: %.1f м\n", geom_perimeter(plot, n));
    printf("Вызовов библиотеки: %d\n", geom_calls());
    return 0;
}
```

```
> wcc участок.c geom.lib
Готово: участок.exe — консольная программа, 36352 байт, 157 мс
> участок
Площадь участка: 975.0 кв. м
Забор: 127.0 м
Вызовов библиотеки: 5
```

Пять вызовов: одна площадь и четыре расстояния, из которых сложился периметр. Если заголовок лежит в другой папке, её называют ключом `-I`, как в главе 4: `wcc участок.c ..\geom\geom.lib -I ..\geom`. Библиотек в одной команде может быть несколько, и путь к каждой пишется полностью или от папки, где идёт сборка.

Какие библиотеки берёт программа, решает тот, кто её собирает: wcc сам `.lib` нигде не ищет. Если файл забыт, сообщение называет недостающие функции:

```
> wcc участок.c
функции объявлены, но не написаны — geom_polygon_area, geom_perimeter, geom_calls: их нет ни в программе, ни в библиотеках Windows (своя DLL — ключ -l имя или #pragma comment(lib, "имя"); своя библиотека — её файл .lib в команде)
```

## Что попадает в программу

Программа `участок` зовёт три функции из четырёх: `geom_distance` она не зовёт сама, но её зовёт `geom_perimeter`, поэтому она тоже нужна. Всё, до чего программа не дотягивается ни прямо, ни через другие функции, в `.exe` не попадает. Так работает и библиотека Си: хоть в ней сотни функций, `hello.exe` весит около 35 КБ.

Поэтому в библиотеку можно складывать всё полезное, не думая о весе программ. Сотня функций в `.lib` не утяжелит программу, которая берёт из неё одну.

## Что внутри файла .lib

`.lib` WinCC — текстовый файл. Первая строка — `WCCLIB 1`, дальше идут исходники библиотеки, уже пропущенные через препроцессор:

```
WCCLIB 1
source 4656 C:\Работа\geom\geom.c

#line 30 "math.h"
extern int signgam ;
typedef double double_t ;
```

Это начало `geom.lib`: строка `source` — какой исходник идёт дальше и сколько в нём байт, а за ней — текст `geom.c`, начиная с объявлений из `math.h`, который он подключил.

«Уже пропущенные через препроцессор» значит: все `#include` библиотеки уже вставлены, все её макросы раскрыты, все `#if` решены. Поэтому программе при сборке не нужны ни внутренние заголовки библиотеки, ни её макросы — только её открытый заголовок с объявлениями. Строки `#line` хранят, из какого файла и какой строки пришёл каждый кусок: ошибки и отладчик показывают настоящие места в исходниках библиотеки.

Отсюда два следствия.

- Макросы, от которых зависит библиотека, решаются при её сборке, а не при сборке программы. Если в библиотеке есть `#ifdef DEBUG`, то `-D DEBUG` нужно давать команде `wcc --lib`, а не программе.
- Изменили исходник библиотеки — пересоберите `.lib`, а потом программы. Сама программа о новых строках библиотеки не узнает.

Если исходники библиотеки подключают `#pragma comment(lib, "имя")` — например, библиотеку WUI или DLL `dwmapi` — `.lib` запоминает эти имена строкой `uses`, и программа получит их сама.

## Отладка внутри библиотеки

Функции своей библиотеки отладчик проходит так же, как функции программы (глава 22). Точку останова можно поставить прямо в `geom.c`, F11 из `участок.c` зайдёт в `geom_polygon_area`, «Переменные» покажут `p`, `n`, `s`, а глобальная `g_calls` появится среди глобальных. Для этого отладчику нужны исходники библиотеки там же, где они лежали при сборке `.lib`: путь к каждому файлу записан в самой библиотеке. Если исходников нет, программа всё равно отлаживается, а функции библиотеки проходятся целиком, как функции библиотеки Си.

## Новый проект: выбор вида

В окне WinCC библиотеку начинают с проекта. «Новый проект…» на панели проекта сначала спрашивает, что делать:

:= Вид | Что кладётся в новую папку
: Консоль | `main.c` с `main()` — программа в окне консоли
: Окно | `main.c` с `WinMain()` — программа со своими окнами
: DLL | `имя.h` с объявлениями и `имя.c` с функцией `__declspec(dllexport)` и `DllMain`
: Библиотека | `имя.h` и `имя.c` с функцией, без `main`

Потом — где сохранить проект и как его назвать. Имя проекта становится именем файлов: проект `geom` получит `geom.h` и `geom.c` с заготовкой функции `geom_add`, которую остаётся заменить своими. Если в выбранной папке уже есть файлы Си, окно предложит взять их в проект вместо заготовки.

У проекта вида «Библиотека» F7 собирает `geom.lib`. Запустить её нельзя, и кнопка «Запустить» скажет об этом: библиотека работает только внутри программы. Новые файлы Си, добавленные в такой проект кнопкой «Новый файл в проекте», начинаются со строки `#include "geom.h"`.

Кнопка «Новый» на панели кнопок (Ctrl+N) тоже смотрит на выбранный вид программы: в виде «Окно» она даёт заготовку с `WinMain`, в виде «Библиотека» — функцию без `main`.

## Программа с библиотекой в окне WinCC

В проекте программы библиотека — такой же файл проекта, как исходник:

1. На панели проекта «Добавить файлы…» и выбрать `geom.lib` (в окне выбора есть строка «Библиотеки WinCC (*.lib)»). Файл появится в группе «Библиотеки».
2. В «Свойствах проекта» в поле «Папки #include» вписать папку, где лежит `geom.h`, например `..\geom`.
3. F7 или F5 — проект собирается вместе с библиотекой.

В файле проекта это две строки: `file=..\geom\geom.lib` и `include=..\geom`. Путь хранится от папки проекта, так что пару «библиотека и программа» можно переносить вместе, сохраняя их взаимное расположение.

## Своя DLL по пути

Для DLL из главы 10 ключ `-l` тоже принимает путь: `wcc main.c -l ..\mathlib\mathlib`. По пути wcc находит файл, чтобы прочитать его таблицу экспорта, а в программу записывает только имя `mathlib.dll`. При запуске Windows ищет DLL рядом с `.exe`, поэтому перед запуском её копируют туда. В проекте путь вписывается в поле «DLL (-l)».

## Итог

Своя библиотека `.lib` — это функции, которые вшиваются в каждую программу, которая их берёт, и только те, что ей нужны. Собирается она ключом `wcc --lib`, подключается файлом `.lib` в команде сборки или в проекте, объявления берутся из её заголовка. Внутри `.lib` — исходники после препроцессора: программе не нужны внутренние заголовки библиотеки, ошибки и отладчик указывают в её исходники, а макросы решаются при сборке самой библиотеки.

В окне WinCC библиотеку начинают проектом вида «Библиотека»: заготовка без `main`, F7 даёт `.lib`. Для DLL — вид «DLL» с заготовкой экспорта и `DllMain`. Выбор между ними простой: отдельный обновляемый файл — DLL, общие функции своих программ — `.lib`.
