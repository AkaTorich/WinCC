# Свой веб-сервер
Браузер есть на каждом компьютере и в каждом телефоне. Если программа умеет отвечать на HTTP, любой браузер становится её окном: можно посмотреть отчёт, поменять настройку, нажать кнопку — с этого же компьютера или с телефона в той же сети. Тот же сервер отдаёт данные другим программам, которые спрашивают его через `net_get` из главы 18. В `net.h` веб-сервер умещается в одну функцию-обработчик: библиотека принимает соединения, разбирает запрос, а программа решает только, что ответить. Эта глава строит сайт от самого маленького до записной книжки с формой, JSON и файлами, объясняет, как остановить сервер и как держать его в отдельном потоке, и где у него пределы.

## Самый маленький сайт

Сервер в `net.h` — это функция-обработчик, которую библиотека зовёт на каждый пришедший запрос. Обработчик смотрит, что спросили, и отвечает одной из функций `net_http_reply…`. Всё остальное — слушать порт, принимать соединения, читать запрос, отправлять ответ и закрывать соединение — делает библиотека.

```
// hello: самый маленький сайт — http://localhost:8080
#include <net.h>
#include <stdio.h>
#include <string.h>

static void site(NetHttpRequest *r, void *user)
{
    (void)user;
    printf("%s %s %s\n", r->peer, r->method, r->path);
    if (strcmp(r->path, "/") == 0) {
        const char *name = net_http_param(r, "name");
        char html[300];
        snprintf(html, sizeof html, "<!doctype html><meta charset=utf-8><h1>Привет, %s!</h1>",
                 name ? name : "мир");
        net_http_reply_html(r, 200, html);
    } else if (strcmp(r->path, "/stop") == 0) {
        net_http_reply_text(r, 200, "До свидания.");
        net_http_stop(net_http_server(r));
    }
}

int main(void)
{
    printf("Откройте http://localhost:8080\n");
    if (net_http_run(8080, site, 0) < 0) {
        printf("%s\n", net_error());
        return 1;
    }
    printf("Сервер остановлен.\n");
    return 0;
}
```

`net_http_run(порт, обработчик, данные)` открывает порт и занимает поток, который её позвал, — до тех пор, пока сервер не остановят. Каждое пришедшее соединение библиотека читает в отдельном потоке, а обработчик зовёт строго по одному, под замком, — так что писать его можно как обычную функцию, не думая о потоках (подробнее — в разделе о пределах сервера). Если порт занят, она сразу возвращает -1, и `net_error()` говорит «Порт 8080 занят»; после остановки — 0. Третий параметр, указатель `данные`, библиотека передаёт в каждый вызов обработчика вторым параметром — через него удобно дать обработчику доступ к своим данным без глобальных переменных.

Программа запущена, и по очереди открыты адреса `http://localhost:8080/`, `http://localhost:8080/?name=Анна`, `/favicon.ico` и `/stop`. В окне сервера:

```
Откройте http://localhost:8080
[::1]:51727 GET /
[::1]:51728 GET /
[::1]:51729 GET /favicon.ico
[::1]:51730 GET /stop
Сервер остановлен.
```

Первые два адреса ответили «Привет, мир!» и «Привет, Анна!», последний — «До свидания.», после чего `net_http_run` вернулась и программа допечатала свою строку. На `/favicon.ico` пришёл ответ 404 «Не найдено», хотя такой строки в программе нет: обработчик ничего не ответил, и библиотека ответила сама. Этот адрес — значок сайта, браузер спрашивает его без просьбы, так что такие строки в журнале — обычное дело.

Имя из адреса здесь вставлено в страницу как есть — для первого знакомства так проще. В настоящем сайте так нельзя, и почему — объясняет раздел о записной книжке ниже.

## Что приходит в обработчик

Обработчик получает указатель на `NetHttpRequest`:

:= Поле | Что в нём | Пример
: `method` | Метод запроса | `GET`, `POST`, `HEAD`
: `path` | Путь без параметров, `%XX` уже раскрыты | `/notes/день 1`
: `query` | Всё после `?` как есть, или пустая строка | `name=%D0%90&x=1`
: `headers` | Все заголовки запроса, строками `Имя: значение` | `Host: localhost:8080…`
: `body`, `size` | Тело запроса и его длина; после тела всегда ноль | `text=…`
: `peer` | Кто спросил, «адрес:порт» | `127.0.0.1:51493`

Все эти строки принадлежат библиотеке и живут, пока обработчик не вернулся. Что нужно сохранить надолго (текст заметки, имя), копируют через `strdup` или `malloc`.

В пути `%XX` уже превращены в байты, а `+` остаётся плюсом — так велит правило адресов: пробел в пути пишется только `%20`. Параметры в `query`, наоборот, оставлены как пришли, потому что `&` и `=` внутри значения иначе нельзя было бы отличить от разделителей. Значения из них достаёт `net_http_param`.

## Параметры и формы: net_http_param

`net_http_param(r, "name")` ищет параметр сначала в адресе (`?name=…`), а если там нет — в теле запроса, когда это обычная форма браузера (тип `application/x-www-form-urlencoded`). Возвращает значение уже раскодированным — `%D0%90%D0%BD%D0%BD%D0%B0` становится «Анна», `+` — пробелом — или ноль, если параметра нет. Параметр без значения (`?debug`) даёт пустую строку. Возвращённая строка живёт до конца обработчика.

Формы с файлами (`enctype="multipart/form-data"`) `net_http_param` не разбирает: такое тело приходит в `body` как есть, и разбирать его программа должна сама. Тело JSON тоже лежит в `body` — его программа читает сама или своей библиотекой. Если клиент прислал тело частями, не сказав длину заранее (`Transfer-Encoding: chunked`), библиотека сама собирает куски, и в `body` и `size` оно приходит целым, как любое другое.

`net_http_header(r, "User-Agent")` возвращает значение заголовка запроса без учёта больших и малых букв, или ноль.

## Ответ

:= Функция | Что отправляет
: `net_http_reply(r, код, тип, данные, размер)` | Любые байты с любым типом; тип ноль — `application/octet-stream`
: `net_http_reply_text(r, код, текст)` | Строку как `text/plain; charset=utf-8`
: `net_http_reply_html(r, код, html)` | Строку как `text/html; charset=utf-8`
: `net_http_reply_file(r, путь)` | Файл с диска; тип — по расширению
: `net_http_add_header(r, имя, значение)` | Добавляет свой заголовок к ответу — до вызова `reply`

На каждый запрос уходит один ответ: второй вызов `reply` в том же обработчике ничего не отправит. Если обработчик вернулся, ничего не ответив, библиотека отвечает 404 «Не найдено». Сама она ставит заголовки `Content-Type`, `Content-Length` и `Connection: close`; на запрос `HEAD` отправляются только заголовки, без тела. Код ответа может быть любым — для частых кодов (200, 201, 204, 301–307, 400–405, 413, 500, 503 и другие) библиотека сама пишет и их название.

`net_http_add_header` нужен, когда ответ должен сказать больше, чем тип и длину: `Location` для переадресации, `Cache-Control: no-store`, чтобы браузер не хранил старую страницу, `Access-Control-Allow-Origin: *`, чтобы данные сервера могли брать страницы с других сайтов.

## Сайт-записная книжка

Пример побольше — записная книжка: страница со списком и формой, приём новой заметки, те же заметки в JSON для программ и раздача файлов из папки.

```
// notes: сайт-записная книжка на http://localhost:8080
//   /            — список заметок и форма
//   /add         — форма присылает сюда новую заметку
//   /notes.json  — те же заметки для программ
//   /files/имя   — файлы из папки public рядом с программой
//   /stop        — остановить сервер
#include <net.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

#define MAX_NOTES 100
static char *notes[MAX_NOTES];
static int count;

static size_t room_for_notes(void)             // сколько байт хватит на все заметки
{
    size_t n = 400;
    for (int i = 0; i < count; i++)
        n += strlen(notes[i]) * 6 + 16;         // любой знак может стать "&quot;"
    return n;
}

// текст пользователя в HTML: < > & " — словами, чтобы чужая заметка не стала частью страницы
static void add_escaped(char *out, const char *text)
{
    out += strlen(out);
    for (; *text; text++) {
        const char *s = *text == '<' ? "&lt;" : *text == '>' ? "&gt;" : *text == '&' ? "&amp;"
                      : *text == '"' ? "&quot;" : 0;
        if (s)
            out += strlen(strcpy(out, s));
        else
            *out++ = *text;
    }
    *out = 0;
}

static void page(NetHttpRequest *r)
{
    char *html = malloc(room_for_notes());
    strcpy(html, "<!doctype html><meta charset=utf-8><title>Заметки</title>"
                 "<h1>Заметки</h1><form method=post action=/add>"
                 "<input name=text size=40 autofocus> <button>Записать</button></form><ul>");
    for (int i = 0; i < count; i++) {
        strcat(html, "<li>");
        add_escaped(html, notes[i]);
    }
    strcat(html, "</ul>");
    net_http_reply_html(r, 200, html);
    free(html);
}

static void json(NetHttpRequest *r)
{
    char *text = malloc(room_for_notes()), *o = text;
    *o++ = '[';
    for (int i = 0; i < count; i++) {
        if (i)
            *o++ = ',';
        *o++ = '"';
        for (const char *p = notes[i]; *p; p++) {
            if (*p == '"' || *p == '\\')        // в JSON их пишут с косой чертой впереди
                *o++ = '\\';
            *o++ = *p;
        }
        *o++ = '"';
    }
    *o++ = ']';
    net_http_reply(r, 200, "application/json", text, (size_t)(o - text));
    free(text);
}

static void site(NetHttpRequest *r, void *user)
{
    (void)user;
    printf("%s %s %s\n", r->peer, r->method, r->path);
    if (strcmp(r->path, "/") == 0)
        page(r);
    else if (strcmp(r->path, "/add") == 0 && strcmp(r->method, "POST") == 0) {
        const char *text = net_http_param(r, "text");
        if (text && text[0] && count < MAX_NOTES)
            notes[count++] = strdup(text);
        net_http_add_header(r, "Location", "/");        // «теперь иди на главную»
        net_http_reply_text(r, 303, "");
    } else if (strcmp(r->path, "/notes.json") == 0)
        json(r);
    else if (strncmp(r->path, "/files/", 7) == 0) {
        const char *name = r->path + 7;
        char path[600];
        if (strstr(name, "..") || strchr(name, '\\') || strchr(name, ':'))
            net_http_reply_text(r, 403, "Сюда нельзя");  // только внутри папки public
        else {
            snprintf(path, sizeof path, "public/%s", name);
            if (!net_http_reply_file(r, path))
                net_http_reply_text(r, 404, "Нет такого файла");
        }
    } else if (strcmp(r->path, "/stop") == 0) {
        net_http_reply_text(r, 200, "Сервер остановлен.");
        net_http_stop(net_http_server(r));
    }
    // всё прочее: обработчик молчит — сервер ответит 404 сам
}

int main(void)
{
    printf("Заметки: http://localhost:8080\n");
    if (net_http_run(8080, site, 0) < 0) {
        printf("%s\n", net_error());
        return 1;
    }
    printf("Остановлен, заметок было %d.\n", count);
    return 0;
}
```

Здесь четыре приёма, которые встречаются почти в каждом сайте.

Экранирование. Заметку написал пользователь, и в ней может оказаться `<script>`. Если вставить её в страницу как есть, браузер выполнит чужой код. `add_escaped` заменяет `<`, `>`, `&` и `"` на их имена (`&lt;` и другие), и браузер покажет текст, а не исполнит его. Правило простое: всё, что пришло от пользователя, в HTML вставляется только экранированным.

Переадресация после формы. Приняв заметку, сервер отвечает не страницей, а кодом 303 и заголовком `Location: /` — «теперь иди на главную». Браузер сам откроет список. Если бы `/add` сразу вернул страницу, обновление страницы в браузере отправило бы форму ещё раз, и заметка записалась бы дважды.

JSON для программ. Путь `/notes.json` отдаёт тот же список с типом `application/json` — его может взять любая программа, хоть `net_get` из главы 18. Кавычки и обратная косая черта внутри текста экранируются, иначе JSON сломается.

Файлы — с проверкой пути. Об этом ниже, в разделе о файлах.

Сервер запущен, рядом с ним папка `public` с картинкой `logo.png`. Открыта главная страница, через форму записаны две заметки — «Купить хлеб» и `<b>жирный</b> & "кавычки"`, — затем спрошены снова главная, JSON, картинка, файл за пределами `public` и файл, которого нет. Журнал сервера:

```
Заметки: http://localhost:8080
127.0.0.1:51801 GET /
127.0.0.1:51802 POST /add
127.0.0.1:51803 POST /add
127.0.0.1:51804 GET /
127.0.0.1:51805 GET /notes.json
127.0.0.1:51806 GET /files/logo.png
127.0.0.1:51808 GET /files/nofile.txt
127.0.0.1:51809 GET /stop
Остановлен, заметок было 2.
```

Ответ `/notes.json`:

```
["Купить хлеб","<b>жирный</b> & \"кавычки\""]
```

На странице вторая заметка видна как текст, а не жирным шрифтом: в HTML она ушла как `&lt;b&gt;жирный&lt;/b&gt; &amp; &quot;кавычки&quot;`. Картинка пришла с типом `image/png`, а несуществующий файл — 404 «Нет такого файла». Запрос `/files/../notes.c` в журнале не виден вовсе: путь с `..` библиотека отклонила ответом 400 ещё до обработчика.

## Заметка из другой программы

Сервер говорит на HTTP, поэтому ему всё равно, кто спрашивает — браузер или своя программа. Вот маленький клиент на функциях главы 18: он отправляет заметку той же формой, что и браузер, и читает список через JSON.

```
// note: записать заметку в записную книжку из другой программы. note "текст"
#include <net.h>
#include <stdio.h>
#include <stdlib.h>
#include <string.h>

int main(int argc, char **argv)
{
    if (argc < 2) {
        printf("note \"текст заметки\"\n");
        return 1;
    }
    char *text = net_url_encode(argv[1]);
    char *form = malloc(strlen(text) + 8);
    sprintf(form, "text=%s", text);
    NetResponse *r = net_post_text("http://localhost:8080/add", "application/x-www-form-urlencoded", form);
    printf("Запись: %s\n", r->error ? r->error : "принята");
    net_free(r);
    free(form);
    free(text);

    r = net_get("http://localhost:8080/notes.json");
    if (!r->error)
        printf("Теперь в книжке: %s\n", r->body);
    net_free(r);
    return 0;
}
```

```
> note "Позвонить маме"
Запись: принята
Теперь в книжке: ["Позвонить маме"]
> note "Купить хлеб и молоко"
Запись: принята
Теперь в книжке: ["Позвонить маме","Купить хлеб и молоко"]
```

В журнале сервера на каждый запуск клиента три строки, а не две:

```
[::1]:51890 POST /add
[::1]:51891 GET /
[::1]:51892 GET /notes.json
```

Средняя — переадресация 303: библиотека клиента, как и браузер, сама пошла на `/` и забрала страницу, хотя программе она не нужна. Если лишний запрос мешает, сервер может отвечать программам иначе, чем браузеру, — например, кодом 201 без переадресации, когда в запросе есть заголовок `Accept: application/json`, а программа ставит его через `net_request`.

## Файлы: net_http_reply_file

`net_http_reply_file(r, путь)` читает файл целиком и отправляет его с кодом 200 и типом по расширению. Если файла нет или он не читается, функция ничего не отправляет и возвращает 0 — тогда программа отвечает сама, как в примере выше. Путь считается от текущей папки программы, а не от папки, где лежит exe: если сервер запускают ярлыком или из другой папки, путь лучше собрать из `GetModuleFileNameA`.

:= Расширение | Тип
: `html`, `htm`, `css`, `js`, `txt` | `text/…; charset=utf-8`
: `json`, `xml`, `pdf`, `zip`, `wasm` | `application/…`
: `png`, `jpg`, `jpeg`, `gif`, `webp`, `svg`, `ico`, `bmp` | `image/…`
: `wav`, `mp3`, `ogg`, `mp4` | `audio/…`, `video/mp4`
: `woff`, `woff2`, `ttf` | `font/…`
: всё прочее | `application/octet-stream`

Файл читается в память целиком, поэтому раздавать так стоит то, что разумно держать в памяти: страницы, картинки, небольшие архивы. Больше гигабайта функция не отдаёт вовсе.

Путь, который лезет вверх по папкам (`/files/../../секрет.txt`), до обработчика не доходит: библиотека находит в нём звено `..` между косыми чертами, прямыми или обратными (в том числе записанное как `%2E%2E`), и сама отвечает 400. Браузер такой адрес и не отправит, но любая программа может.

! Проверка `..` в обработчике записной книжки остаётся второй линией: имя после `/files/` всё равно прислал кто-то чужой. Его всегда приклеивают к своей папке, а `\` и `:` в нём отвергают, чтобы запись вроде `C:/…` не стала путём от корня диска, — иначе сервер раздаст любые файлы компьютера, до которых дотянется.

## Остановка

Сервер останавливает `net_http_stop(сервер)`. Указатель на сервер изнутри обработчика даёт `net_http_server(r)`, поэтому остановка по адресу — две строки, как в примерах выше: сначала ответить, потом остановить. Текущий запрос доработает, ответ уйдёт, новые приниматься не будут, и `net_http_run` вернёт 0 — программа продолжит работу со строки после неё.

Кнопка остановки в адресе удобна, пока сервер виден только своему компьютеру. Если к нему ходят из сети, остановить его по `/stop` сможет кто угодно. Такой путь закрывают паролем в параметре или проверяют, что спрашивает сам компьютер: `peer` начинается с `127.0.0.1:` или `[::1]:`. А если сеть серверу не нужна вовсе, его запускают так, чтобы из сети к нему было не прийти, — об этом в следующем разделе.

## Сервер в своём потоке: net_http_start

`net_http_run` занимает поток целиком. Если программе нужно и обслуживать запросы, и делать своё — считать, рисовать окно, опрашивать устройство, — сервер запускают в отдельном потоке: `net_http_start(порт, обработчик, данные)`. Она открывает порт, запускает поток сервера и сразу возвращает указатель на сервер (или ноль, если порт занят). Обработчик зовётся в потоках сервера, а не в главном, — но, как и у `net_http_run`, по одному запросу за раз.

У неё есть пара — `net_http_start_local` с теми же параметрами. Такой сервер слушает один адрес `127.0.0.1`: прийти к нему можно только с этого же компьютера, соседи по сети его не видят, и брандмауэр Windows о нём не спрашивает. Это нужный выбор для всего, что сервер делает лишь для своей программы или своего хозяина: окно настроек в браузере, связь двух своих программ, кнопка `/stop`, которую никто чужой не нажмёт.

```
// side: сервер отвечает в своём потоке, а главный поток делает своё дело
#include <net.h>
#include <stdio.h>
#include <string.h>

static HANDLE g_quit;                           // «пора закрываться» — событие Windows
static int g_asked;                             // меняет только поток сервера
static volatile int g_seconds;                  // меняет только главный поток

static void site(NetHttpRequest *r, void *user)
{
    (void)user;
    g_asked++;                                  // здесь поток сервера: никакого printf
    if (strcmp(r->path, "/quit") == 0) {
        net_http_reply_text(r, 200, "Закрываюсь.");
        SetEvent(g_quit);                       // знак главному потоку
    } else {
        char text[100];
        snprintf(text, sizeof text, "Работаю %d с, это вопрос номер %d", g_seconds, g_asked);
        net_http_reply_text(r, 200, text);
    }
}

int main(void)
{
    g_quit = CreateEventA(0, TRUE, FALSE, 0);
    NetHttpServer *sv = net_http_start_local(0, site, 0);   // 0 — любой свободный порт
    if (!sv) {
        printf("%s\n", net_error());
        return 1;
    }
    printf("Сервер: http://127.0.0.1:%d/  остановить: /quit\n", net_http_port(sv));
    while (WaitForSingleObject(g_quit, 1000) == WAIT_TIMEOUT)
        g_seconds++;                            // своё дело — раз в секунду
    net_http_stop(sv);                          // снаружи: дождётся конца потока сервера
    printf("Проработал %d с, вопросов было %d\n", g_seconds, g_asked);
    return 0;
}
```

```
Сервер: http://127.0.0.1:51811/  остановить: /quit
Проработал 5 с, вопросов было 3
```

Между первой и последней строкой браузер открыл адрес сервера через 2 и через 5 секунд и получил «Работаю 2 с, это вопрос номер 1» и «Работаю 5 с, это вопрос номер 2», а на `/quit` — «Закрываюсь.».

Порт 0 значит «любой свободный», а какой достался, говорит `net_http_port` — так программа может поднять сервер для себя, не боясь, что порт 8080 занят. А `_local` в имени функции делает его сервером только для этого компьютера: адрес в первой строке — `127.0.0.1`, и с телефона по сети этот адрес не откроется. Пока главный поток считает секунды, сервер отвечает: на это и нужен отдельный поток. По той же причине программа с `net_http_start` может спросить свой сервер сама через `net_get`; из `net_http_run` так нельзя — поток, который должен ответить, сам ждал бы ответа.

Обработчик здесь чужой для главного потока, и это задаёт правила:

- Печатать из обработчика можно: `printf` и `FILE` библиотеки Си под общим замком, строки двух потоков не перемешаются. Но порядок строк тогда решает случай; если он важен, обработчик ведёт счёт или кладёт данные в общую память, а печатает главный поток.
- Каждую общую переменную пусть меняет один поток: `g_asked` меняет только обработчик, а главный читает его после остановки сервера; `g_seconds` меняет только главный. Если менять одни данные должны оба потока, их берут под замок `SRWLOCK` (`AcquireSRWLockExclusive` и `ReleaseSRWLockExclusive`). Сам с собой обработчик не пересекается: хотя соединения читаются в разных потоках, библиотека вызывает его под своим замком, строго по одному, поэтому `g_asked++` в нём безопасен и потокобезопасным обработчик делать не нужно.
- Останавливать сервер лучше из главного потока. Обработчик лишь подаёт знак — здесь событие Windows через `SetEvent`, — а главный поток, проснувшись в `WaitForSingleObject`, зовёт `net_http_stop(sv)`. Она обрывает соединения, чьи запросы ещё не дочитаны, дожидается конца потока сервера и освобождает всё.

! Можно остановить сервер `net_http_start` и изнутри обработчика, через `net_http_server(r)`: сервер допишет этот ответ, сразу оборвёт недочитанные соединения и закончит работу. Указатель от `net_http_start` при этом ещё не освобождён — главный поток позже всё равно зовёт `net_http_stop(sv)`, и она дождётся конца потока сервера и освободит всё. После остановки снаружи указатель свободен, и второй `net_http_stop` с ним звать нельзя. Главный поток об остановке изнутри сам не узнает, поэтому знак через событие удобнее.

## Пределы сервера

Сервер `net.h` рассчитан на свою программу и свою сеть, а не на тысячи посетителей из интернета. Его пределы стоит знать заранее:

:= Что | Как устроено
: Чтение запросов | Каждое соединение — в своём потоке, до 64 сразу; следующие ждут, пока не освободится место
: Обработчик | Строго по одному, под замком: следующий запрос ждёт, пока обработчик не ответит на текущий
: Соединение | Одно на запрос, после ответа закрывается (`Connection: close`)
: Молчание гостя | Каждое чтение ждёт до 10 с; молчащий гость занимает только своё соединение и остальных не задерживает
: Остановка | `net_http_stop` — снаружи или из обработчика — обрывает недочитанные соединения сразу, не дожидаясь их 10 с; ответ, который даётся сейчас, уходит целиком
: Заголовки запроса | До 64 КБ включительно; хоть на байт больше — ответ 431
: Тело запроса | До 64 МБ, длина — по заголовку `Content-Length`; больше — ответ 413
: Тело частями | `Transfer-Encoding: chunked` принимается: куски собираются в одно тело, `size` — его длина
: Путь с `..` | Ответ 400 до обработчика
: Шифрование | Только HTTP, без HTTPS
: Где слышен | `net_http_run` и `net_http_start` — на всех сетях, IPv4 и IPv6; `net_http_start_local` — только `127.0.0.1`

Разделение на чтение и ответ сделано ради медленных гостей. Телефон на плохой связи, браузер, который открыл соединение про запас, или чужая программа, которая прислала ползапроса и замолчала, — каждый из них ждёт в своём потоке, а сервер тем временем читает и обслуживает остальных. Вот как это выглядит со стороны: первый гость присылает начало запроса без пустой строки в конце и молчит, второй спрашивает следом.

```
// slowguest: медленный гость не задерживает остальных
#include <net.h>
#include <stdio.h>

static void site(NetHttpRequest *r, void *user)
{
    (void)user;
    net_http_reply_text(r, 200, "Привет");
}

int main(void)
{
    NetHttpServer *sv = net_http_start_local(0, site, 0);
    if (!sv) {
        printf("%s\n", net_error());
        return 1;
    }
    int port = net_http_port(sv);

    // Первый гость: начало запроса — и тишина, пустой строки в конце нет
    NetSocket *slow = net_connect("127.0.0.1", port);
    if (slow)
        net_send_text(slow, "GET / HTTP/1.1\r\nHost: x\r\n");

    // Второй гость спрашивает следом
    char url[64];
    snprintf(url, sizeof url, "http://127.0.0.1:%d/", port);
    ULONGLONG t0 = GetTickCount64();
    NetResponse *a = net_get(url);
    if (a->error)
        printf("Не вышло: %s\n", a->error);
    else
        printf("Второй гость: %d %s, через %llu мс\n", a->status, a->body, GetTickCount64() - t0);
    net_free(a);

    t0 = GetTickCount64();
    net_http_stop(sv);                          // недочитанный запрос первого обрывается
    printf("Сервер остановлен за %llu мс\n", GetTickCount64() - t0);
    net_close(slow);
    return 0;
}
```

Второй гость получает ответ 200 «Привет» за считанные миллисекунды, хотя первый всё ещё держит своё соединение открытым. Остановка тоже не ждёт молчуна: `net_http_stop` обрывает его недочитанный запрос, и программа заканчивается сразу, а не через 10 секунд.

Сам обработчик при этом по-прежнему один на всех. Отсюда главное правило обработчика — отвечать быстро. Пока он думает над одним запросом, ответы остальным ждут. Долгую работу (большой расчёт, запрос к другому серверу) лучше начать в отдельном потоке и ответить сразу «принято», а результат отдать по следующему запросу.

Сервер `net_http_run` и `net_http_start` слушает на всех сетях, и брандмауэр Windows при первом запуске спросит, разрешить ли программе принимать соединения из сети. Разрешите — к сайту можно будет зайти с телефона по адресу компьютера (`http://192.168.1.7:8080`); откажите — он останется доступен только с этого компьютера по `localhost`. Сервер `net_http_start_local` брандмауэр не тревожит вовсе: из сети его не видно.

## Итог

Веб-сервер в `net.h` — это обработчик: он получает `NetHttpRequest` с методом, путём, параметрами, заголовками и телом и отвечает одной из функций `net_http_reply…`, а не ответив ничего, отдаёт 404. Значения из адреса и формы достаёт `net_http_param`, заголовки — `net_http_header`, свои заголовки ответа добавляет `net_http_add_header`, файлы отдаёт `net_http_reply_file`. `net_http_run` обслуживает запросы на месте, `net_http_start` — в отдельном потоке, `net_http_start_local` — в отдельном потоке и только для этого компьютера; останавливает их `net_http_stop`. Каждое соединение сервер читает в своём потоке, до 64 сразу, поэтому медленный гость не задерживает остальных, а обработчик зовёт по одному, под замком, — заботиться о потоках в нём не нужно. Всё, что пришло от пользователя, экранируется перед вставкой в страницу; путь с `..` библиотека отклоняет сама, а имя файла из адреса программа всё равно приклеивает к своей папке и проверяет. Последняя глава части спускается под библиотеку — к сокетам и WinHTTP напрямую.
