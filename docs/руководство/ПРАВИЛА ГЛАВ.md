# Как писать главы «Руководства WinCC»

Заглавие: «Руководство WinCC». Подзаголовок: «Компилятор Си для Windows и его библиотеки».
Формат A4. Подписи автора в книге нет — ни на обложке, ни на титуле, ни в тексте. Главы лежат в папке `главы`, каждая — отдельный файл
UTF-8 `NN Название.txt`. Сборщик (`python сборка.py`) превращает их в PDF, поэтому
разметка строгая. Рисунки — в папке `рисунки`.

## О чём книга

WinCC — свой компилятор языка Си для Windows: из файлов `.c` он делает обычные программы
Windows — консольные `.exe`, оконные `.exe` и библиотеки `.dll`. Готовая программа не зависит
ни от чего, кроме DLL самой Windows: библиотека Си (printf, malloc, файлы, математика…)
вшивается в каждую программу, и в неё попадает только то, что программа на самом деле зовёт.
К компилятору прилагаются: окно-редактор WinCC.exe, заголовки Windows (`windows.h` и другие),
GDI+ для Си (`gdiplus.h`), библиотека оформления окон WUI (`wui.h`, 61 тема ThemeLibrary)
и библиотека сети (`net.h`, под ней `winsock2.h`, `ws2tcpip.h`, `winhttp.h`).

Книга — руководство для того, кто пишет на WinCC программы: как поставить, как собирать,
что умеет язык и библиотека, как сделать окно, DLL, красивое окно на WUI, сетевую программу.
Читатель знает Си на уровне учебника (переменные, функции, указатели, структуры) или учит
его параллельно. Язык Си с нуля книга не преподаёт; всё, что касается Windows, окон,
библиотек, сборки и особенностей WinCC, объясняет с нуля.

Устройство самого компилятора (как он внутри разбирает текст, тесты разработчика,
сверка с MSVC, выгрузка тем, сборка самого wcc.exe из исходников) — не предмет книги:
о нём одной-двумя фразами там, где это помогает понять поведение (например, почему
программа маленькая).

## План глав

Часть I. Начало
1. Что такое WinCC — зачем, что получается на выходе, из чего состоит, что внутри готового exe
2. Установка и первая программа — установщик, что где лежит, hello.c в окне и в консоли, кириллица
3. Окно WinCC — редактор, вкладки, сборка, вид программы, ошибки, запуск, темы, клавиши
4. Командная строка wcc — все ключи, несколько исходников, `.asm`, `-S`, `--run`, код выхода

Часть II. Язык и библиотека Си
5. Какой Си понимает WinCC — что из C99/C11 есть, размеры типов в Windows, слова MSVC,
   `#pragma pack`, `#pragma comment`, битовые поля, чего нет
6. Стандартная библиотека — stdio, файлы, printf и scanf, stdlib, строки, математика, время,
   setjmp, сигналы, переменные окружения, system
7. Текст, кириллица и UTF-8 — исходник в UTF-8, манифест, A- и W-функции, `wchar_t`, `L""`,
   консоль, пути к файлам, GDI
8. Вставки на ассемблере — `asm("…")` в функции и вне функций, файлы `.asm`, x87

Часть III. Программы для Windows
9. Оконная программа на windows.h — WinMain, класс окна, цикл сообщений, рисование, меню,
   кнопки, диалог открытия файла, когда консоль, когда окно
10. Свои DLL — `--dll`, экспорт, программа, которая её зовёт, `-l`, где ищется DLL, DllMain
11. Функции любых DLL Windows — как wcc находит DLL без .lib, `#pragma comment(lib)`, своё
    объявление функции, которой нет в заголовках, LoadLibrary и GetProcAddress
12. Рисование: GDI и GDI+ — GDI в WM_PAINT, затем `gdiplus.h`: сглаживание, кисти,
    градиенты, текст, картинки, сохранение PNG; калькулятор из примеров как образец

Часть IV. Оформление окон WUI
13. Первое окно WUI — идея, `wui_window`, `wui_content`, `wui_run`, ключ запоминания темы,
    выбор темы, почему окно без консоли
14. Раскладка — столбец, строка, перенос, прокрутка, карточка, размеры, доли, поля, отступы,
    выравнивание
15. Элементы и события — каждый элемент с примером, `wui_on_click`, `wui_on_change`,
    значения, тексты, включение и скрытие
16. Темы, значки и своё рисование — список тем и групп, цвета темы, значки, холст GDI+,
    боковое меню, заголовок до верха окна, сообщения и всплывающая строка, несколько окон
17. Программа целиком на WUI — от замысла до готового exe, по шагам

Часть V. Сеть
18. HTTP и HTTPS — `net_get`, `net_post`, `net_request`, заголовки, скачивание файла с ходом,
    тайм-ауты, ошибки
19. TCP и UDP — соединение, сервер, строки, ожидание, пакеты, рассылка, чат как пример
20. Свой веб-сервер — `net_http_start`, `net_http_run`, обработчик, параметры, формы, файлы,

21. Сокеты и WinHTTP напрямую — `winsock2.h`, `ws2tcpip.h`, `winhttp.h` без библиотеки,

## Разметка

```
# Заголовок главы
Первый абзац — вводный (сборщик делает его курсивным «лидом»).

## Раздел
### Подраздел (редко)

Абзацы разделяются пустой строкой. Имена функций, файлов, ключей внутри абзаца — в обратных
кавычках: `wui_window`, `wcc --gui`.

: ячейка | ячейка | ячейка
:= Заголовок | столбца | таблицы   (строка-шапка, ставится первой)

```
код программы, вывод, командная строка — блок между строками из трёх обратных кавычек
```

! Врезка — важное замечание, подвох, совет. Одна-четыре фразы.

@ имя.png | Подпись к рисунку      (рисунок из папки «рисунки»)

1. Шаг первый
2. Шаг второй   (нумерованный список — только для пошаговых действий)
- пункт        (маркированный список — короткие перечни)
```

- `#` — одна строка, первая в файле.
- Таблицы — 2–4 столбца. Знак `|` внутри ячейки нельзя (он делит ячейки): пишите словами
  («или»), а в коде — вне таблицы.
- Нельзя: ссылки и адреса сайтов (кроме адресов в примерах программ, например
  `https://example.com`), слова «источник», упоминания сверки и сборки книги, эмодзи,
  markdown-жирный `**`, курсив `*…*`, заголовки через `####`.

## Примеры кода — только проверенные

Каждый пример, который выглядит как программа, обязан собираться: проверка —
`python "проверка примеров.py" NN` (NN — номер главы). Она берёт из главы каждый блок,
в котором есть `main`, `wmain`, `WinMain` или `wWinMain`, и собирает его через `..\..\wcc.exe`.

- Программа из одного файла — один блок с `#include` и `main`. Полностью, без «…».
- Программа из нескольких файлов: каждый блок начинается строкой `// файл: имя.c` (или `.h`,
  `.asm`), а в одном из блоков стоят строки `// сборка: wcc a.c b.c -o prog.exe` — их
  проверка выполнит по порядку в папке, где лежат все файлы этой главы. Так же — DLL:
  `// сборка: wcc --dll mathlib.c` и `// сборка: wcc usemath.c -l mathlib`.
- Кусок кода без `main` (одна функция, пара строк) проверка пропускает: он должен быть
  верным, но собирать его не нужно.
- Вывод программы приводить настоящий — запустить программу и скопировать. Консольные
  программы запускать можно; окна — собрать, открыть, закрыть.
- Пишите короткие, но живые примеры: читатель должен понять, зачем это, а не только как.
- Если пример не собирается из-за ошибки в самом WinCC (а не в примере) — не обходить
  молча: записать в отчёт, что именно не работает (файл, строка, сообщение).

## Рисунки

Окна WUI снимаются самой библиотекой, без экрана и мыши:

```
set WUI_SNAPSHOT=рисунки\13-первое-окно.png
set WUI_SIZE=760,480
set WUI_SCALE=2
программа.exe
```

`WUI_SNAPSHOT` — первое окно сохраняется картинкой после первой отрисовки, программа
закрывается; `WUI_SIZE=ширина,высота` — размер окна в точках; `WUI_SCALE=2` — масштаб
экрана (снимок вдвое чётче, для печати так и надо); `WUI_THEME=Id` — тема (Id —
из `wui_theme_id`, например `Emerald`). Окно WinCC.exe снимается так:
`WinCC.exe --window рисунки\03-окно.png 1100x700 тема:Id` (без файлов — добавить `пусто`).
Имена рисунков начинаются с номера главы: `13-…png`. Рисунок нужен там, где он объясняет
лучше слов (окна, темы, раскладка), а не на каждой странице.

## Голос

Взрослый, ровный, без «давайте» и без детского тона. Сначала — зачем это нужно и какая
картина должна сложиться в голове, потом — как сделать, шаг за шагом, потом — как
убедиться, что получилось. Объяснять почему; предугадывать вопрос новичка и отвечать
прямо в тексте. Одно точное сравнение лучше трёх бытовых. В конце главы — короткий
«Итог» (абзац-два), без вопросов и заданий «проверь себя». Термины — общепринятые
(функция, заголовок, DLL, сообщение окна, сокет), с объяснением при первом появлении.
Справочные приложения — сухие и полные: таблицы, без рассказов.

## Мера

Глава — 2000–3500 слов (5–9 страниц A4 с таблицами и кодом). Приложения — сколько нужно,
чтобы перечислить всё. Страница ≈ 420 слов текста или ≈ 50 строк кода.

## Факты (брать отсюда и из исходников, не придумывать)

Папка проекта (для проверки на этой машине): `C:\Users\O.V.K\Documents\O.V.K\Программы\Code\WinCC`.
Описание, что где, — `README.md` проекта. Заголовки — `include\`, исходники библиотек —
`lib\wui\`, `lib\net\`, примеры — `examples\` (hello.c, window.c, dll\, calc\, wui\, net\).

- Установщик `WinCCSetup.exe` ставит без прав администратора в `%LOCALAPPDATA%\Programs\WinCC`;
  переключатели: ярлыки на рабочем столе и в «Пуске», команда `wcc` в любой консоли (папка
  в PATH пользователя), WinCC в «Открыть с помощью» для `.c`/`.h` (программу по умолчанию
  не меняет), запуск после установки. Повторный запуск — обновление поверх. Удаление —
  «Приложения и возможности» или кнопка «Удалить WinCC». Ключи: `/silent [/dir="папка"]`,
  `/uninstall [/silent]`.
- В установленной папке: `wcc.exe`, `WinCC.exe`, `runtime\` (библиотека Си, исходники),
  `include\` (заголовки Windows, WUI, сети), `lib\` (WUI и сеть исходниками), `examples\`
  (только исходники), `README.md`, это руководство.
- Ключи wcc: `wcc файл.c [ещё.c файл.asm ...] [параметры]`; `-o имя`, `--console` (так по
  умолчанию), `--gui` (без консоли; так же, если есть WinMain и нет main), `--dll`, `-l имя`
  (брать функции из этой DLL), `-I папка`, `-D ИМЯ[=знач]`, `-S` (ассемблерный текст в `.s`),
  `--stack МБ` (по умолчанию 8), `--run` (собрать и запустить). Без параметров wcc печатает
  справку. Удачная сборка печатает строку «Готово: имя.exe — консольная программа, N байт, M мс».
- Ошибки — строками `файл:строка: текст`, по-русски; код выхода wcc 1.
- Цель Windows: `long` — 4 байта, `wchar_t` — 2 байта (UTF-16), `L"…"` — UTF-16, указатель — 8,
  `long long` — 8, `long double` — то же, что `double`. Макросы `_WIN32`, `_WIN64`, `__WINCC__`.
- В каждом exe — манифест: кодовая страница программы UTF-8 (A-функции user32 берут текст
  программы, а он UTF-8, как есть — кириллица работает), Common Controls 6 (современный вид
  кнопок). GDI манифест не слушает, поэтому `TextOutA`, `DrawTextA`, `ExtTextOutA`,
  `GetTextExtentPoint32A`, `CreateFontA` идут через переходники библиотеки. С `#define UNICODE`
  до `windows.h` обычные имена — W-функции. Консоль печатает через UTF-16 — кириллица видна.
- Импорт: какая DLL даёт функцию, wcc узнаёт, читая таблицы экспорта самих DLL (System32 и
  папка программы), `.lib` не нужны. Всегда просматриваются: kernel32, user32, gdi32,
  comdlg32, shell32, advapi32, comctl32, ole32, winmm, ws2_32; другие — `-l имя` или
  `#pragma comment(lib, "имя")`.
- `#pragma comment(lib, "имя")`: если рядом с wcc есть папка `lib\имя`, её `.c` собираются вместе
  с программой как библиотека (неиспользуемое выбрасывается) — так подключаются WUI и сеть;
  иначе это имя DLL. `#pragma comment(linker, "/SUBSYSTEM:WINDOWS")` — оконная программа даже
  с `main`.
- Размеры: hello.exe ≈ 35 КБ; программа с net.h ≈ 45–65 КБ; программа на WUI ≈ 0,65–0,75 МБ (данные
  тем ≈ 250 КБ), её сборка ≈ 5 с. Версия wcc, окна и установщика — 1.3.0.
- Ассемблер понимает обычные команды x86-64 и x87 (`fld`, `fstp`, `fsin`, `st(0)`…`st(7)`,
  `tbyte ptr`); в `asm()` внутри функции аргументы лежат в `[rbp+16]`, `[rbp+24]`…, выход —
  `jmp .L.return.имя_функции` (см. `tests\x87.c`); имя Си внутри asm — `@имя`.
- Битовые поля есть и раскладываются как у MSVC.
- Ограничения (1.3.0): `long double` = `double`; языкового `_Complex` нет (`complex.h` как у
  Microsoft); оптимизация простая (регистры, константы, адресация; без разворота циклов и встраивания); `return` в `__finally` нельзя; `mbrtowc`/`mbtowc` не дают символ за U+FFFF (строки целиком — `mbstowcs`,
  `%ls`, `fputws` — пары UTF-16 понимают).
- Окно WinCC.exe — раздел «Окно WinCC.exe» в README проекта (клавиши, вкладки, ошибки, запуск,
  запоминание).
- WUI — раздел «Оформление окон» в README, весь API — `include\wui.h`, показ — `examples\wui`.
- Сеть — раздел «Сеть» в README, весь API — `include\net.h`, примеры — `examples\net`.
